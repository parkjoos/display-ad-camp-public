# 13. 종합 점수판 · 배점표 (R-22, R-23, R-24, R-25, R-49, R-57)

## 1. 목적

- 퀴즈 게임(이모티콘 퀴즈 · 사진 보고 맞추기)은 **팀별로 맞힌 개수만 센다** (R-22). 게임 결과 화면은 정답 수와 그에 따른 순서만 보여주고, 종합 점수(100 / 50 / 0 등)는 계산하지 않는다.
  - 예외 (R-49): 점수판에 **"정답 수" 라운드**(정답 1개당 점수)가 게임 전체에 연결된 게임은 게임 화면 · 진행자 화면에 **점수 = 정답 수 × 1개당 점수**를 보여준다 — 기본값으로 이모티콘 퀴즈(1개당 50). 정답 수에 곱하기만 하므로 순서는 정답 수 순서와 같다.
  - 예외 (R-62): 사진 보고 맞추기 **릴레이**는 라운드 등수 = 대표를 모두 내보낸 순서이고, 게임 결과 순위는 라운드마다 등수의 배점을 더한 **게임 점수** — 이 점수판의 등수 행과 같은 계산을 게임 안에서도 한다 (10장).
- 종합 점수는 **종합 점수판**에서 진행자가 팀별로 입력하고 합산한다 (R-23). 앱으로 진행하지 않는 게임(팀 정하기 · 10초 안에 성공하라 · 제기차기 · 신발 던지기 등)도 같은 표에 넣어 전체 점수를 한곳에서 관리한다.
- 게임(라운드)마다 1 · 2 · 3등이 몇 점인지 참가자에게 보여주는 **배점표** 화면을 두고, 그 화면에서 바로 점수를 입력 · 수정한다 (R-24). 기본값은 시트 기준으로 넣어 둔다.

| 화면 | 하는 일 | 절 |
| --- | --- | --- |
| 배점표 | 게임별 1 · 2 · 3등 점수를 모니터에 크게 보여줌 + 점수 입력 · 수정 | 4장 |
| 게임 홈의 배점 구역 | 그 게임의 배점을 보여줌 + 바로 수정 | 5장 |
| 종합 점수판 | 팀별 등수 · 점수 입력, 합계 · 순위 | 6장 |
| 점수판 발표 화면 | 합계 순위를 하위부터 공개 (시상식) | 7장 |
| 라운드 설정 | 라운드 추가 · 삭제 · 이름 · 방식 · 순서 · 앱 게임 연결 | 8장 |

- 세 화면 모두 **같은 라운드 데이터**(이름 · 방식 · 점수)를 쓴다. 배점표에서 점수를 바꾸면 점수판 계산도 바로 바뀐다.

## 2. 진입

| 경로 | 동작 |
| --- | --- |
| ☰ 메뉴 → "배점표" | 배점표 화면 |
| ☰ 메뉴 → "종합 점수판" | 점수판 입력 화면 |
| 게임 홈 → 배점 구역 [배점표 전체 보기] | 배점표 화면 |
| 퀴즈 게임 결과 화면 → "종합 점수판에 채울까요?" | [확인] 자동 입력 / [점수 고치기] 고쳐서 입력 / [취소] (10장, `D-18`) |
| 퀴즈 게임 라운드 종료 화면 → 진행자 화면 [팀 점수에 반영] | 이번 라운드까지 반영 (10-6, R-57) |
| 관리 페이지(`/admin`) → [점수 입력] | 같은 점수판 입력 표 — 노트북에서 입력하면 게임 창에도 바로 반영 (R-25, R-31) |

- 이 화면들이 열려 있는 동안 게임 단축키(`1`~`4` 득점 등)는 꺼지고 각 화면의 키(9장)만 동작한다.
- 점수판 입력은 팀 설정이 필요하다 (없으면 "팀 설정이 필요합니다" + [팀 설정] 링크). 배점표는 팀 설정 없이도 열린다.

## 3. 라운드 (게임) 목록 — 기본값

출처: 구글 시트 「타임라인」. 기본 목록은 `data/scoreboard.json` 에 두고 (초기 데이터, [02-data-schema.md](02-data-schema.md) 7장), 현장에서 바꾼 값은 현장 상태 파일 `state/scoreboard.json` 에 저장한다 (9-1).

| 순서 | 라운드 | 방식 | 기본 점수 | 연결된 앱 게임 · 카테고리 | 비고 |
| --- | --- | --- | --- | --- | --- |
| 1 | 팀 정하기 | 등수 | 1등 50 / 2등 0 / 3등 0 | — | "가장 빨리 팀을 완성한 팀 +50" |
| 2 | 10초 안에 성공하라 | 등수 | 1등 200 / 2등 100 / 3등 50 | — | 1-1 몸풀기 |
| 3 | 줄줄이 말해요 | 성공 · 실패 | 성공 200 / 실패 0 | `chain-talk` | 1-2 몸풀기 (앱은 주제 룰렛만 — 결과 자동 입력 없음) |
| 4 | 이모티콘 퀴즈 | 정답 수 | 정답 1개당 50 | `emoji-quiz` (게임 전체) | 2-1. 19명 모두 참여, 맞힌 사람의 팀에 정답 1개 → 50점 (R-49). 처음엔 시트대로 영화 · 속담 · 노래 제목 3행 각각 등수(100/50/0)였음 (`D-11`) |
| 5 | 사진 보고 맞추기 | 등수 | 1등 100 / 2등 50 / 3등 0 (라운드마다) | `photo-quiz` | 2-2. **라운드마다** 등수 → 배점을 더한다 (R-57 — 3라운드면 최대 300). 라운드 등수는 릴레이(R-62)로 대표를 모두 내보낸 순서 (팀당 대표를 끄면 그 라운드 정답 수). 이 행의 배점이 게임 결과 순위(게임 점수)에도 쓰인다. 처음엔 게임 전체 순위 하나였음 |
| 6 | 제기차기 | 등수 | 1등 300 / 2등 200 / 3등 100 | — | 3-1 |
| 7 | 신발 던지기 | 등수 | 1등 600 / 2등 400 / 3등 200 | — | 3-2 |

- 팀이 4개면 등수 방식 라운드에 "4등" 점수 칸이 생긴다 (기본값 0).
- 개인전(청개구리 가위바위보)은 개인 상품이라 목록에 없다.

### 라운드 방식

| 방식 | 값 | 배점 표시 | 점수판 팀별 입력 | 점수 계산 |
| --- | --- | --- | --- | --- |
| 등수 | `rank` | 1등 · 2등 · 3등 (· 4등) 점수. 앱 게임(득점형)에 연결된 행은 "(라운드마다)" | 등수 선택. 같은 등수를 여러 팀에 줄 수 있음 (공동). 앱 게임에 연결된 행은 퀴즈가 **라운드별 등수 목록**을 넣는다 (R-57) | 그 라운드의 등수별 점수. 라운드별 등수 목록이면 라운드마다 배점의 합 |
| 성공 · 실패 | `pass` | 성공 · 실패 점수 | 성공 / 실패 선택 | 성공 점수 / 실패 점수 |
| 정답 수 (R-49) | `count` | "정답 1개당 50" | 정답 수 숫자 입력 (0 이상) — 퀴즈 결과로 자동 입력 (10장) | 정답 수 × 1개당 점수 |
| 직접 입력 | `manual` | "직접 입력" (보너스 · 감점 등) | 숫자 직접 입력 (음수 가능) | 입력한 숫자 그대로 |

- 점수판은 **등수 · 성공 여부 · 정답 수를 저장**하고 점수는 매번 배점으로 계산한다 → 배점을 나중에 바꿔도 이미 입력한 등수 · 정답 수의 점수가 새 배점으로 바로 다시 계산된다.
- **점수 직접 수정 (D-18 "점수 고치기")**: 등수 · 성공 칸도 그 칸의 점수만 숫자로 덮어쓸 수 있다 (정답 수 칸은 정답 수를 고친다 — 덮어쓰기 없음). 덮어쓴 칸은 배점이 바뀌어도 그 숫자를 유지하고, 칸에 ✎ 표시 + "직접 수정" 툴팁. [배점대로] 를 누르면 덮어쓰기를 지우고 다시 배점으로 계산.

## 4. 배점표 화면 (R-24)

모니터에 띄워 참가자에게 "게임별로 1 · 2 · 3등이 몇 점인지" 보여주는 화면. 같은 화면에서 진행자가 점수를 입력 · 수정한다.

```
┌──────────────────────────────────────────────────────────────────┐
│ ☰  🏅 게임별 배점                                    [수정] [점수판] │
├──────────────────────────────────────────────────────────────────┤
│                              🥇 1등      🥈 2등      🥉 3등        │
│  팀 정하기                      50          0          0          │
│  10초 안에 성공하라             200        100         50          │
│  줄줄이 말해요              성공 200 · 실패 0                       │
│  이모티콘 퀴즈                  정답 1개당 50                       │
│ ▶ 사진 보고 맞추기              100         50          0          │
│  제기차기                      300        200        100          │
│  신발 던지기                   600        400        200          │
└──────────────────────────────────────────────────────────────────┘
```

| 요소 | 내용 |
| --- | --- |
| 표 | 라운드 순서대로. 등수 방식은 1 · 2 · 3등 (· 4등) 열, 성공 · 실패 방식은 한 칸에 "성공 200 · 실패 0", 정답 수 방식은 "정답 1개당 50", 직접 입력 방식은 "직접 입력" |
| 글자 | 모니터 3m 거리에서 읽히는 크기 (행 높이 7vh 이상, 점수 48px 이상). 행이 많으면 화면에 맞게 자동 축소 |
| 강조 행 | 행을 클릭하거나 `↑` `↓` 로 고르면 그 행 강조 (▶) — "지금 할 게임" 을 짚어 줄 때 |
| 한 게임만 크게 | 강조 행에서 `Enter` → 그 게임 배점만 화면 가득 (🥇 100 · 🥈 50 · 🥉 0 대형 카드, 정답 수 방식은 "⭕ +50 정답 1개당" 카드 하나). `Esc` 로 표로 돌아감 |
| [수정] (`E`) | 수정 모드 켜기 / 끄기. 수정 모드에서는 점수 칸이 숫자 입력 칸으로 바뀜 (참가자에게 보여줄 때는 수정 모드를 끈다) |
| 입력 규칙 | 정수, 음수 허용, 0 ~ 9999 권장. 입력하면 즉시 저장 (9-1). 잘못된 값(빈칸 · 글자)은 저장하지 않고 원래 값으로 |
| [기본값으로] | 수정 모드에서만 보임. 확인 후 모든 라운드 점수를 `data/scoreboard.json` 기본값으로 |
| [점수판] | 종합 점수판으로 이동 |

- 라운드 추가 · 삭제 · 이름 · 방식 변경은 배점표가 아니라 라운드 설정(8장)에서 한다. 배점표는 **점수만** 고친다.
- 사진 보고 맞추기 행(게임 전체에 연결된 등수 행)의 배점은 릴레이 게임 결과 순위(게임 점수)에도 쓰인다 — 바꾸면 진행 중인 게임도 따라간다. 이 행이 없으면 게임 점수는 100 / 50 / 0 (R-62, `D-33`).

## 5. 게임 홈의 배점 구역

앱 게임(줄줄이 말해요 · 이모티콘 퀴즈 · 사진 보고 맞추기)의 게임 홈에 그 게임의 배점을 보여준다 ([01-app-flow.md](01-app-flow.md) 4-1).

| 요소 | 내용 |
| --- | --- |
| 배점 | 이 게임과 연결된 라운드(`gameId`)의 배점. 예) 사진 보고 맞추기 "🥇 100 · 🥈 50 · 🥉 0", 이모티콘 퀴즈 "정답 1개당 50" (R-49), 줄줄이 말해요 "성공 200 · 실패 0". 카테고리별 등수 행이 여럿이면 "영화 100/50/0 · 속담 100/50/0" 처럼 |
| [배점 수정] | 그 자리에서 숫자 입력 칸으로 바뀜 (배점표 수정과 같은 데이터) |
| [배점표 전체 보기] | 배점표 화면 |
| 연결된 라운드 없음 | "배점표에 연결된 라운드가 없습니다 — 라운드 설정에서 연결하세요" |
| 안내 문구 | "이 게임은 정답 수로 순위를 정합니다. 종합 점수는 점수판에서 입력합니다." (퀴즈 게임만). 정답 수 라운드가 게임 전체에 연결된 게임은 "맞힌 팀에 정답 1개마다 점수를 줍니다 (게임 화면에 점수 표시). 끝나면 점수판에 정답 수로 채웁니다." (R-49). 릴레이 게임(R-62)은 "라운드마다 대표를 모두 내보낸 순서로 등수를 매겨 배점을 더합니다. 게임 결과 순위도 그 합입니다." |

## 6. 종합 점수판 (R-23)

```
┌──────────────────────────────────────────────────────────────────────────┐
│ ☰  🏆 종합 점수판                  [배점표] [라운드 설정] [발표 화면] [초기화] │
├──────────────────────────┬─────────────┬─────────────┬─────────────┬─────┤
│ 라운드                    │ ● 팀A        │ ● 팀B        │ ● 팀C        │     │
├──────────────────────────┼─────────────┼─────────────┼─────────────┼─────┤
│ 팀 정하기 (50/0/0)        │ 1등  50      │ 2등   0      │ 3등   0      │ ✔   │
│ 10초 안에 성공하라         │ 2등 100      │ 1등 200      │ 3등  50      │ ✔   │
│ 줄줄이 말해요 (성공 200)   │ 성공 200     │ 실패   0     │ 성공 200     │ ✔   │
│ 이모티콘 퀴즈 (1개당 50)   │ 3개 150      │ 2개 100      │ [  선택  ]   │     │
│ …                        │             │             │             │     │
├──────────────────────────┼─────────────┼─────────────┼─────────────┼─────┤
│ 합계                      │ 350 (1위)    │ 300 (2위)    │ 250 (3위)    │     │
└──────────────────────────┴─────────────┴─────────────┴─────────────┴─────┘
```

| 요소 | 내용 |
| --- | --- |
| 행 | 라운드 (설정 순서). 라운드 이름 옆에 방식 · 배점 요약 |
| 열 | 팀 (팀 설정의 이름 · 색, 순서 = 팀 키 순서) |
| 셀 (등수) | 클릭하면 [1등] [2등] [3등] ([4등]) [지우기]. 선택하면 "2등 100" 처럼 등수와 점수 표시. 퀴즈가 라운드마다 넣은 칸은 "1·2·-등 150" (라운드별 등수 — `-` 는 정답 없는 라운드, R-57). 손으로 등수를 고르면 등수 하나로 바뀐다 |
| 셀 (성공 · 실패) | [성공] [실패] [지우기] |
| 셀 (정답 수, R-49) | 정답 수 입력 칸 (0 이상 정수). "3개 150" 처럼 정답 수와 점수 표시 |
| 셀 (직접 입력) | 숫자 입력 칸 |
| 셀 점수 직접 수정 | 등수 · 성공 칸에서 [점수 수정] (또는 `E`) → 그 칸 점수만 숫자로 덮어쓰기. ✎ 표시, [배점대로] 로 되돌리기 (3장) |
| 자동 입력 표시 | 퀴즈 결과에서 자동으로 채운 칸은 행 이름 옆에 "자동 · 사진 보고 맞추기" 작은 표시 (10장) |
| 오른쪽 끝 | 그 라운드 모든 팀 입력 완료면 ✔ |
| 확인 표시 | 등수 방식에서 1등 없이 2등이 있는 등 순서가 이상하면 노란 표시 (저장은 됨) |
| 합계 행 | 팀별 합계 + 현재 순위 (점수가 같으면 같은 순위, 다음 순위는 건너뜀). 1위 팀 강조 |
| 저장 | 입력할 때마다 즉시 저장 (9-1) |

## 7. 점수판 발표 화면

- [발표 화면] 또는 `P` → 모니터용 전체화면 순위 발표 (시상식 · 중간 발표용).
- 처음엔 모든 팀이 가려진 상태 → `Enter` 마다 (R-85 — 예전 `→`) **하위 순위부터** 공개 (공동 순위는 함께) → 1위 공개 시 강조 + 꽃가루 (퀴즈 결과 화면과 같은 연출, [05-screens.md](05-screens.md) 4-8).
- 팀 카드: 순위 · 팀 이름 · 합계. 모두 공개 후 아래에 라운드별 점수 작은 표.
- `Esc` → 점수판 입력 화면.

## 8. 라운드 설정

[라운드 설정] → 라운드 목록 편집 화면.

| 항목 | 입력 | 규칙 |
| --- | --- | --- |
| 이름 | 텍스트 | 필수, 20자 이내 |
| 방식 | 등수 / 성공 · 실패 / 정답 수 / 직접 입력 | 이미 입력값이 있는 라운드의 방식을 바꾸면 그 라운드 입력값을 지울지 확인 |
| 점수 | 등수: 1등 · 2등 · 3등 (· 4등) / 성공 · 실패: 성공 · 실패 / 정답 수: 정답 1개당 | 정수, 음수 허용. 배점표에서 고친 값과 같은 데이터 |
| 연결된 앱 게임 | 없음 / 줄줄이 말해요 / 이모티콘 퀴즈 / 사진 보고 맞추기 | 게임 홈 배점 구역에 표시할 라운드 + 퀴즈 결과 자동 입력 대상 (10장). 한 게임에 여러 라운드 연결 가능. 정답 수 라운드를 게임 전체로 연결하면 그 게임 화면 · 진행자 화면이 점수를 보여준다 (R-49) |
| 연결된 카테고리 (선택) | 그 게임의 카테고리 중 하나 | 지정하면 자동 입력 때 **그 카테고리 라운드의 정답 수**로 순위를 매기거나(등수) 정답 수를 넣는다(정답 수) (예: "이모티콘 퀴즈 - 영화" ↔ `movie`). 비우면 게임 전체 정답 수 |
| 순서 | ▲▼ | 배점표 · 점수판 행 순서 |
| 추가 · 삭제 | [+ 라운드 추가] / [삭제] | 입력값이 있는 라운드 삭제는 확인창 |
| 기본값으로 | [기본값으로 되돌리기] | 라운드 목록 · 점수 · 연결을 `data/scoreboard.json` 기본값으로 (점수판 입력값은 같은 라운드 id 끼리 유지) |

- 예: 이모티콘 퀴즈를 다시 카테고리마다 등수로 채점하려면 (`D-11` 처음 기본값) "이모티콘 퀴즈" 행을 지우고 등수 방식 라운드 3개를 추가해 영화 · 속담 · 노래 제목 카테고리에 연결한다 — 이때 게임 화면은 점수 대신 정답 수를 보여준다.
- 서버에서 배점 · 라운드 설정을 한 번이라도 바꿨으면(`state/scoreboard.json` 의 `rounds` 가 있음) R-49 의 새 기본값(이모티콘 1행 · 정답 수)이 저절로 들어가지 않는다 → [기본값으로 되돌리기], 또는 이모티콘 행의 방식을 "정답 수" 로 바꾸고 1개당 50 · 카테고리 "게임 전체".
- 서버 모드의 기본값 `data/scoreboard.json` 은 서버 저장소의 사본이다 — 새 버전을 배포해도 바뀌지 않으므로 기본값을 바꾼 버전은 배포 뒤 사본을 바꾼다 (관리 페이지에 고치는 화면은 없다). R-49 는 10/13 배포 때 바꿈.
- 예: 보너스 · 감점이 필요하면 "직접 입력" 방식 라운드를 추가한다.

## 9. 저장 · 조작

### 9-1. 저장
- 로컬 서버가 **`state/scoreboard.json` 파일**에 라운드 설정(배점 포함)과 점수판 입력값을 저장한다 (R-28 — 원본은 서버 저장 폴더, R-37). 저장할 때마다 직전 내용을 `state/.backup/` 에 남긴다(최근 30개). 브라우저 저장소(`camp-game:scoreboard:v1`)는 서버가 꺼졌을 때를 위한 임시 사본 ([08-tech.md](08-tech.md) 6장).
- 라운드 설정 · 배점을 한 번도 바꾸지 않았으면 `data/scoreboard.json` 기본값을 그대로 쓴다.

```json
{
  "version": 1,
  "rounds": null,
  "entries": {
    "team-forming": [{ "rank": 1 }, { "rank": 2 }, { "rank": 3 }],
    "chain-talk": [{ "pass": true }, { "pass": false }, { "pass": true }],
    "emoji-quiz": [{ "count": 3 }, { "count": 2 }, { "count": 0 }],
    "photo-quiz": [{ "ranks": [1, 2, 1] }, { "ranks": [2, 1, null], "value": 90 }, { "ranks": [3, 2, 2] }],
    "bonus": [{ "value": -10 }, null, null]
  },
  "filled": {
    "photo-quiz": { "from": "photo-quiz", "at": "2026-10-29T17:30:00+09:00", "session": "2026-10-29T16:40:00+09:00" }
  },
  "updatedAt": "2026-10-29T17:05:00+09:00"
}
```

| 필드 | 설명 |
| --- | --- |
| `rounds` | 배점표 · 라운드 설정에서 바꾼 라운드 목록 (형식은 02 문서 7장). `null` 이면 기본값 사용 |
| `entries` | 라운드 id → 팀 순서대로 입력값, 미입력은 `null`. 등수 라운드 `rank` (퀴즈가 라운드마다 넣으면 라운드별 등수 목록 `ranks` — `null` 은 등수 없음 · 0점, R-57), 성공 · 실패 라운드 `pass`, 정답 수 라운드 `count` (R-49), 직접 입력 라운드 `value`. 등수 · 성공 라운드에 `value` 가 함께 있으면 **점수 직접 수정**(배점 대신 그 숫자) |
| `log` | 종합 점수 추이 기록 (R-58) — 합계가 바뀔 때마다 `{ at, what, totals }` (시각 · 바뀐 행 이름이나 "사진 보고 맞추기 R2" · 그때 팀별 합계). 같은 `what` 을 3분 안에 이어 쓰면 마지막 것을 바꾼다. 최대 200개. 점수판 [초기화] · 상태 초기화하면 비운다. 기록 · 통계 화면의 꺾은선 ([05-screens.md](05-screens.md) 4-12) |
| `filled` | 퀴즈로 자동 입력한 라운드 기록 (어느 게임에서, 언제, 그 게임 진행의 시작 시각 `session`) — 자동 입력 표시 · 덮어쓰기 경고에 사용. 같은 진행에서 라운드마다 반영한 행은 다시 써도 덮어쓰기 경고를 내지 않는다 |

## 10. 퀴즈 결과 → 점수판 채우기 (`D-18` 확정, R-25)

게임은 정답 수만 세고(R-22), 점수 계산은 점수판이 한다. 그 사이를 **"점수판에 채울까요?"** 확인 창(게임 결과)과 **[팀 점수에 반영]**(라운드 종료, 10-6 — R-57)으로 잇는다. 등수 라운드에는 **라운드별 등수**를, 정답 수 라운드(R-49)에는 정답 수를 채운다 — 두 길은 같은 계산이다. 사진 보고 맞추기 릴레이(R-62)는 라운드 등수를 매기는 법만 다르다 — **대표를 모두 내보낸 순서** (못 끝낸 팀은 그 뒤에 맞힌 대표 수로, 정답 없는 라운드는 등수 없음). 칸 형식(`ranks`) · 배점 합 계산은 그대로.

### 10-1. 흐름

```
[퀴즈 결과: 모든 순위 공개]
      │
      ▼
┌──────────────────────────────────────────────────────┐
│  종합 점수판에 채울까요?                                 │
│  사진 보고 맞추기 → 1등 팀A (100) · 2등 팀B (50) · 3등 팀C (0) │
│                                                      │
│   [확인]        [점수 고치기]        [취소]            │
└──────────────────────────────────────────────────────┘
   │                 │                    │
   ▼                 ▼                    ▼
 자동 입력       고치기 창 (10-3)        아무것도 안 함 →
 (10-2)          → [입력] 으로 저장      나중에 ☰ 또는 관리 메뉴에서
                                         종합 점수판에 직접 입력
```

| 항목 | 규칙 |
| --- | --- |
| 어디에 뜨나 | **진행자 화면**에 뜬다 (참가자가 보는 모니터에는 띄우지 않음, R-26). 진행자 화면이 연결돼 있지 않을 때만 게임 화면에 비상용으로 표시 ([12-host-view.md](12-host-view.md) 4-5) |
| 언제 뜨나 | 퀴즈 게임(득점형) 결과 화면에서 **모든 순위를 공개한 직후**. 단 라운드 종료 화면에서 모든 라운드를 반영했고(10-6) 점수판 값이 지금 계산과 같으면 띄우지 않는다 — 진행자 화면 결과 카드에 "✔ 종합 점수판에 반영돼 있습니다" (R-57). 등수 행에 정답 수가 같은 팀이 있는 라운드가 있으면 창에 "같은 라운드에서 정답 수가 같은 팀은 같은 등수로 채워집니다" 안내 |
| 대상 행 | 이 게임과 연결된(`gameId`) 등수 · 정답 수 라운드 전부. 연결된 라운드가 없으면 창 대신 토스트 "점수판에 연결된 라운드가 없습니다" |
| 순위 · 정답 수 기준 | 라운드에 카테고리가 연결돼 있으면(`categoryId`) **그 카테고리 라운드들**, 아니면 **모든 라운드**. 등수 행은 **라운드마다** 그 라운드 정답 수로 매긴 등수(1224, 그 라운드 정답이 하나도 없으면 등수 없음 · 0점)의 목록 → 점수 = 배점의 합 (R-57 — 추가 문제 결과와 무관). 릴레이(R-62)는 라운드 등수 = 대표를 모두 내보낸 순서 (못 끝낸 팀은 맞힌 대표 수 1224) — 그래서 채운 값의 합이 게임 결과의 게임 점수와 같다 (같은 배점일 때). 정답 수 행은 정답 수 합 (추가 문제 정답은 넣지 않음) |
| 미리보기 | 창에 행마다 팀별로 등수 행은 "1·2등 (150)", 정답 수 행은 "3개 (150)" 를 보여줌. 이번 게임에서 나오지 않은 카테고리 행은 "이번 게임에서 나오지 않음 — 채우지 않음" |
| 이미 값이 있는 행 | 창에 "이미 입력된 값을 덮어씁니다" 경고 (행마다 표시). 같은 진행에서 라운드마다 반영한 행은 경고 없음 |
| 다시 열기 | 진행자 화면 결과 패널의 [점수판에 채우기] 버튼으로 언제든 다시 열기 (게임 화면 `B` 는 R-85 에서 없앰) |
| 줄줄이 말해요 | 룰렛형이라 결과가 없어 창이 뜨지 않는다. 성공 · 실패는 점수판에서 직접 입력 |

### 10-2. [확인] — 자동 입력
- 대상 행마다 팀별 **등수**(정답 수 행은 **정답 수**)를 입력한다 (점수는 배점으로 계산). 공동 순위는 같은 등수.
- 저장 후 토스트 "종합 점수판에 채웠습니다 (사진 보고 맞추기)" + 점수판 해당 행에 "자동 · 사진 보고 맞추기" 표시.

### 10-3. [점수 고치기] — 고쳐서 입력
- 자동 입력값이 미리 채워진 **고치기 창**이 열린다: 행 × 팀 표, 칸마다 등수 선택 + 점수 칸.
  - 등수를 바꾸면 점수는 배점으로 다시 계산된다.
  - 라운드별 등수 행(R-57)은 등수 목록을 그대로 보이고 점수 칸만 고친다 (직접 수정). 등수를 바꾸려면 종합 점수판에서 칸을 다시 고른다.
  - 점수 칸에 숫자를 직접 넣으면 그 칸은 **점수 직접 수정**(3장)으로 저장된다.
  - 정답 수 행은 칸마다 정답 수 입력 ("[3] 개 × 50") — 점수는 1개당 점수로 계산 (R-49).
- [입력] → 저장 (10-2 와 같은 표시). [취소] → 아무것도 저장하지 않고 확인 창으로 돌아감.

### 10-4. [취소]
- 아무것도 저장하지 않는다. 진행자는 나중에 ☰ → 종합 점수판, 또는 관리 페이지의 [점수 입력] 에서 직접 입력한다.

### 10-5. 관리 페이지의 점수 입력 (R-25, R-31)
- 관리 페이지(`/admin`) → **[점수 입력]** → 종합 점수판 입력 표 (게임 창 ☰ → 종합 점수판과 같은 데이터 — `state/scoreboard.json`).
- 노트북에서 입력하는 동안 모니터의 게임 화면은 그대로다. 저장하면 서버가 게임 창에 알려(`reload`) 게임 창의 점수판 · 발표 화면도 바로 바뀐다 ([08-tech.md](08-tech.md) 4-4).
- 관리 페이지에서는 [배점표] · [라운드 설정] 도 함께 연다 (게임 창과 같은 화면 모듈 — [🏆 종합 점수판] · [🏅 배점표] 탭).
- 관리 페이지는 입력을 한 번에 하나씩 이어서 저장하고(빠르게 여러 칸을 입력해도 리비전이 꼬이지 않음), 게임 창에서 바꾼 값은 **서버가 상태 파일이 바뀌었다고 알릴 때만** 다시 읽어 따라간다 — 점수판 · 팀 설정이 바뀌었을 때만, 내가 저장한 것은 건너뜀, 끊겼다 다시 붙으면 한 번 (R-55, [08-tech.md](08-tech.md) 4-4 `GET /api/live/changes`. 3초마다 다시 읽으면 켜 둔 동안 Upstash 시간당 약 9,600 명령). 409 가 나면 파일 내용으로 바꾸고 "다시 입력하세요" 안내.

### 10-6. 라운드 종료 → [팀 점수에 반영] (R-57)

라운드마다 그 라운드 점수를 종합 점수판에 넣는다. 사진 보고 맞추기는 라운드마다 대표가 바뀌는 별개의 게임처럼 진행하므로(`D-4`) 라운드마다 등수를 매겨 배점을 준다 — 릴레이(R-62)는 그 등수가 대표를 모두 내보낸 순서다 (미리보기 "1등 +100" 도 그 등수).

| 항목 | 규칙 |
| --- | --- |
| 어디서 | 득점형 게임의 라운드 종료 화면(R-56). 진행자 화면 라운드 종료 카드 아래 "종합 점수판에 반영" 카드 ([12-host-view.md](12-host-view.md) 4-9). 진행자 화면이 없으면 게임 화면 비상용 `B` |
| 미리보기 | 이 게임에 연결된 등수 · 정답 수 행마다 팀별 **이번 라운드가 더하는 점수** — 등수 행 "1등 +100" (정답 없는 라운드 "등수 없음 +0"), 정답 수 행 "3개 +150". 카테고리가 연결된 행은 이번 라운드가 그 카테고리일 때만. 아래에 반영 뒤 종합 합계(팀별 · 순위) |
| [팀 점수에 반영] | 이 진행에서 반영한 라운드들(이번 라운드 포함)로 **다시 계산해서** 행을 쓴다 — 등수 행은 라운드별 등수 목록 `ranks`, 정답 수 행은 정답 수 합 `count`. 같은 라운드를 두 번 반영해도 두 번 더해지지 않는다. 처음 반영할 때 그 행에 이 진행이 아닌 값(리허설 · 손 입력)이 있으면 "이미 입력된 값을 덮어씁니다" 경고. 모니터에는 토스트 없이 라운드 종료 화면 안내로 알린다 |
| 반영 뒤 | 카드 "✔ 반영했습니다" + 종합 합계. 게임 화면 라운드 종료 카드마다 "종합 450 (+100)" + 아래 "종합 점수판에 반영했습니다". [📝 정답 기록](R-60) · [◀ 라운드로 돌아가기] 로 맞힌 팀이 바뀌어 계산이 달라지면 "점수가 바뀌었습니다 — [다시 반영]" |
| 반영하지 않고 넘어가면 | 그대로 진행. 게임 결과의 "점수판에 채울까요?" 가 모든 라운드로 채운다 (10-1) |
| 연결된 행이 없으면 | 카드에 "점수판에 연결된 라운드가 없습니다 — 종합 점수판에서 직접 입력" (버튼 없음) |
| 진행 기록 | 세션에 반영한 라운드 번호 목록(`reflectedRounds`)을 남긴다 ([07-state-model.md](07-state-model.md) 3-2) |

## 11. 범위 밖

- 점수판 · 배점표를 진행자 화면(`/host`)에 띄우기 — 필요하면 별도 결정.
- 여러 노트북에서 동시에 점수 입력 · 실시간 동기화 — 진행 노트북 한 대에서만 입력한다. 점수판 기록은 서버의 `state/scoreboard.json` 하나이고, 관리 페이지 점수 입력 · 게임 창이 같은 파일을 쓴다 (늦게 쓴 쪽은 409 후 다시 읽음 — 동시 편집은 아니다).
