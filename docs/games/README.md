- `photo` · `emoji` 를 묶어 **득점형**, `roulette` 을 **룰렛형** 이라 부른다.

- 앱은 게임 종류를 데이터로 등록하는 구조라, 나중에 게임을 추가해도 앱 흐름(메뉴 · 게임 홈 · 룰렛)은 그대로 쓴다.
- 새 게임 종류를 추가하려면: 이 표에 행 추가 → `games/<게임>.md` 작성 → [../02-data-schema.md](../02-data-schema.md) 에 스키마 추가 → 앱에 해당 type 화면 구현. 새 게임 추가는 어드민 기능이 아니다 — 필요해지면 이 저장소에서 Claude Code 로 직접 작업한다 (`D-10`, 지금은 범위 밖).
- 아래 3~5장(정답 수 · 판정 · 진행자 원칙)은 **득점형(`photo`, `emoji`)** 에만 적용된다. "득점형" 은 정답을 기록하는 게임이라는 뜻이고, 종합 점수는 어느 게임도 계산하지 않는다 (R-22 — 이모티콘 퀴즈의 점수 표시는 정답 수 × 1개당 점수일 뿐, R-49). 예외: 사진 보고 맞추기 릴레이(R-62)는 결과 순위를 라운드 등수의 배점 합으로 정한다 — 종합 점수판과 같은 계산.

## 2. 팀

- 팀 수: 2 ~ 4 (행사 기준 3팀 × 6명 — 참석자 21명 중 준비위원회 3명 제외. 2026-10-13 기준 게임 참가 19명 → 7 · 6 · 6명, R-49)
- 팀 이름 · 색: **앱 설정에서 입력** (R-9). 코드 · 데이터에 기본 팀 이름 없음. 상세는 [../03-settings.md](../03-settings.md).
- 팀 순서: 설정 화면의 순서 = 진행자 화면 맞힌 팀 버튼 순서 = 스코어보드 왼쪽부터.
- 팀 설정은 모든 게임이 공유한다.

### 대표자 — 라운드마다 새 대표, 모두 한 번씩 (`D-4` 확정 → R-49 로 사진 보고 맞추기만 → R-62 로 팀당 n명 릴레이)

- **이모티콘 퀴즈는 대표 없이 19명 모두 참여** (R-49) — 문제를 전체에 내고 먼저 외친 사람이 답한다. 아래 대표자 규칙은 사진 보고 맞추기에만 적용한다.
- 사진 보고 맞추기는 **라운드마다 각 팀에서 새 대표 n명 (게임 옵션 "팀당 대표", 기본 2명)** 이 나와 **릴레이**로 한다 (R-62, [photo-quiz.md](photo-quiz.md) 4-1). 맞힌 사람은 그 라운드에서 빠지고, 대표가 모두 맞혀 나온 순서가 라운드 1 · 2 · 3등. 한 팀만 남으면 라운드 종료. 목표는 **모든 사람이 한 번씩** 게임을 하는 것. 팀당 대표를 0(끔)으로 하면 예전처럼 대표 1명 · 정답 수.
- 진행 예 (사진 보고 맞추기, 3팀 × 2명):
  1. (진행자) "팀마다 두 분씩 나와 주세요" · 카테고리 고르기(룰렛) — 둘 중 무엇을 먼저 해도 됨 → "첫 번째 게임은 음식 확대 사진 게임입니다" → 1라운드 (한 팀만 남을 때까지)
  2. (진행자) "다음 두 분씩 나와 주세요" · 카테고리 고르기 → "두 번째 게임은 포스터 보고 영화 맞추기입니다" → 2라운드
  3. …
- 인원 계산 (`D-28` → R-62 로 결정): 사진 라운드마다 팀당 2명 → 계획 3라운드면 **팀당 6명이 한 번씩**. 19명 → 7 · 6 · 6명이면 7명 팀은 한 명이 남는다 — 팀이 정하거나 [한 라운드 더 ▶]. (처음 계획은 이모티콘 퀴즈 3라운드 + 사진 3라운드 × 대표 1명이었으나 R-49 로 이모티콘 퀴즈가 전원 참여가 됨.)
- 앱은 사람 이름을 받지 않고 대표 호출 문구도 띄우지 않는다 (호출과 카테고리 고르기 순서가 현장에서 바뀔 수 있으므로 진행자가 말로 부른다). 누가 나왔는지는 팀이 챙긴다. 앱은 라운드 소개에서 "n 번째 게임은 ○○ 입니다" 만 보여준다 ([../05-screens.md](../05-screens.md) 4-5).

## 3. 정답 수 · 순서 (득점형 공통, R-22)

> **예외 — 사진 보고 맞추기 릴레이 (R-62)**: 정답 수 대신 라운드마다 팀별 맞힌 대표 수를 세고, 대표를 모두 내보낸 순서가 **라운드 등수**다 (못 끝낸 팀은 맞힌 대표 수로 1224, 정답 없는 라운드는 등수 없음). 게임 결과 순위는 라운드마다 등수의 배점(배점표 사진 행, 기본 100 / 50 / 0)을 더한 **게임 점수** 순서 — 종합 점수판과 같은 계산. 게임 점수가 같으면 아래 동점 처리(추가 문제)를 그대로 쓴다. 자세히는 [photo-quiz.md](photo-quiz.md) 4-1. 팀당 대표를 끈(0) 게임과 이모티콘 퀴즈는 이 장 그대로.

### 게임은 맞힌 개수만 센다
- 문제당 맞힌 팀에 정답 1개. 팀별 **정답 수**만 쌓는다.
- 이모티콘 퀴즈(R-49)는 점수판의 "정답 수" 라운드(정답 1개당 50)와 연결돼 있어, 게임 화면 · 진행자 화면이 정답 수 대신 **점수(정답 수 × 50)** 를 보여준다. 세는 것은 똑같이 정답 수이고 순서도 같다 — 점수가 같으면 동점이어도 가릴 필요가 없어 추가 문제를 권하지 않는다.
- 게임 결과는 정답 수와 그에 따른 **순서(1위 · 2위 · 3위)**만 보여준다. **종합 점수(100 / 50 / 0 등)는 게임 안에서 계산하지 않는다.**
- 종합 점수는 별도 메뉴 **종합 점수판**에서 진행자가 입력 · 합산하고, 게임별 1 · 2 · 3등 점수는 **배점표**에서 보여주고 입력한다 ([../13-scoreboard.md](../13-scoreboard.md)).
- 결과 화면에는 라운드(카테고리)별 정답 수도 함께 보여준다 — 이모티콘 퀴즈처럼 카테고리마다 따로 채점할 때 점수판에 옮겨 적기 위함.

### 순서 계산
- **표준 경쟁 순위("1224 방식")** — 순위 = (나보다 정답 수가 많은 팀 수) + 1.

### 동점 처리 — 추가 문제 오픈 (`D-3` 확정)

정답 수가 같은 팀이 있으면 **추가 문제를 열어** 순서를 가린다.

| 정답 수 (팀1 · 팀2 · 팀3) | 처음 순위 (공동) | 추가 문제로 가릴 그룹 |
| --- | --- | --- |
| 5 · 4 · 3 | 1 · 2 · 3 | 없음 |
| 5 · 5 · 3 | 1 · 1 · 3 | 팀1 · 팀2 (1위 다툼) |
| 5 · 3 · 3 | 1 · 2 · 2 | 팀2 · 팀3 (2위 다툼) |
| 4 · 4 · 4 | 1 · 1 · 1 | 세 팀 모두 |
| 0 · 0 · 0 | 1 · 1 · 1 | 세 팀 모두 |

| 항목 | 규칙 |
| --- | --- |
| 언제 | 결과 화면에서 모든 순위를 공개한 뒤 동점 그룹이 있으면 "동점! 추가 문제로 순위를 정합니다" 안내 → 진행자가 진행자 화면에서 고른다 (게임 창 `S` 는 R-85 에서 없앰) |
| 어떤 문제 | 이 게임에서 **아직 출제하지 않은 문제 중 진행자가 고른 1문제** — 진행자 화면에서 카테고리 → 문제 순서로, 이 게임에 포함된 카테고리의 남은 문제가 정답과 함께 후보로 나온다 (R-54). 게임 창 `S`(비상용)는 그 후보 중 무작위 1문제. 예비 문제를 따로 준비하지 않는다 |
| 순서 | 위 순위의 동점 그룹부터 차례로 (1위 다툼 → 2위 다툼 …) |
| 참가 | 그 동점 그룹 팀만 답할 수 있다 (다른 팀 키는 무시). 사진 릴레이(R-62)도 추가 문제에는 대표 규칙이 없다 — 동점 팀 선착순 |
| 판정 | 선착순 (`D-2`) — 먼저 맞힌 팀이 그룹 안에서 위 순위. 세 팀 동점이면 맞힌 팀이 위로 가고, 남은 두 팀은 다음 추가 문제로 다시 가린다 |
| 아무도 못 맞힘 | 정답 공개 후 다음 추가 문제 |
| 정답 수 | 추가 문제 정답은 **정답 수에 더하지 않는다** (순서만 정함). 결과 카드에 "추가 문제로 결정" 배지 |
| 남은 문제가 없을 때 | 더 열 문제가 없으면 공동 순위로 확정 (안내 "추가 문제가 없어 공동 순위로 정합니다") |

- 공동 순위로 확정된 경우 점수판에 어떻게 옮길지(예: 공동 1등 두 팀 모두 "1등")는 진행자가 점수판에서 정한다 (점수판은 같은 등수를 여러 팀에 줄 수 있음).
- 동점 처리 방식은 고정이라 게임 데이터 · 설정에 동점 관련 필드가 없다.

## 4. 판정 방식 — 선착순 (`D-2` 확정)

- **먼저 외친 팀부터 답할 기회**를 준다. 오답이면 다음 팀에 기회가 넘어간다. 정답 · 오답 판정은 진행자가 **말로** 한다 (앱에 판정 버튼 없음).
- 이모티콘 퀴즈(R-49)는 사람 단위 — 19명 중 **먼저 외친 사람**이 답하고, 맞히면 그 사람이 속한 팀을 고른다. 틀리면 다음에 외친 사람.
- 앱 기록은 **[정답 공개] 이후** 진행자 화면에서 **맞힌 팀을 골라** 1개를 센다 (R-29, [../12-host-view.md](../12-host-view.md) 4-3). 아무도 못 맞혔으면 [없음].
- **문제당 맞힌 팀은 최대 1팀** (정답 1개).
- 사진 보고 맞추기 릴레이(R-62)는 **대표를 모두 내보낸 팀은 그 라운드의 다음 문제에서 맞힌 팀이 될 수 없다** — 진행자 화면 버튼이 꺼지고, 게임 창 숫자키는 토스트 "팀A — 대표가 모두 맞혀 이번 라운드에서 빠졌습니다". 답할 기회도 남은 대표에게만.
- 다른 팀을 고르면 맞힌 팀이 **교체**된다 (진행자 실수 정정용).
- 순서: 문제 → (말로 판정) → [정답 공개] → 맞힌 팀 선택 → [다음 문제] (R-26, R-29).
- 오답 페널티 없음.
- 화이트보드 동시 공개(여러 팀 동시 정답) 방식은 만들지 않는다.

## 5. 진행자 공통 원칙

- 판정은 진행자가 한다. 앱은 기록 · 표시만 한다.
- 앱은 시간을 재지 않고 저절로 넘어가지 않는다 (타이머 없음 — R-33). 정답을 언제 공개할지는 진행자가 정한다.
- 아무도 못 맞혀도 정답은 공개하고 넘어간다.
- 정답 기록 실수는 진행자 화면 정답 화면의 맞힌 팀 버튼 · [없음], 지난 문제는 [📝 정답 기록] 으로 언제든 정정 (게임 화면 `Backspace` 되돌리기는 R-83 에서 없앰).
