# 04. 관리(어드민) 기능 (R-7, R-13, R-15, R-31, R-32, R-37)

게임 창과 분리된 **관리 페이지(`/admin`, 별도 창)** 에서 **카테고리와 문제를 추가 · 수정 · 숨기기 · 삭제**하고, 점수 입력 · 현장 상태 초기화 · 백업 내려받기 · 올리기도 하는 기능. 문제를 추가하는 유일한 경로이며 별도 스킬은 없다. 저장은 **서버 API** 로만 하고 (R-18), 결과는 서버 저장 폴더의 데이터 파일(`data/games/*.json`)과 이미지 폴더(`assets/`)에 기록된다. 운영에서는 서버(서버 모드)의 저장소가 원본이다 (R-37, [08-tech.md](08-tech.md) 5장).

## 1. 저장 방식

| 항목 | 내용 |
| --- | --- |
| 경로 | 관리 페이지 → 로컬 서버의 관리 API (`/api/admin/*` — 요청마다 PIN 헤더, 2-1) → 서버가 검증 · 백업 · 파일 쓰기 ([08-tech.md](08-tech.md) 4장) |
| 브라우저 | Chrome · Safari 모두 가능 (브라우저 전용 파일 API 를 쓰지 않음) |
| 접속 범위 | 서버 모드: 서버 주소 `/admin` (공개 주소 — PIN). 노트북 모드: 노트북 안(`127.0.0.1`)에서만 |
| 누가 | 누구나 (데이터 담당을 나누지 않음 — `D-14`). 서버 모드는 운영자가 정한 PIN, 노트북 모드는 그 터미널의 PIN 으로 들어온다 |
| 서버가 꺼져 있으면 | 관리 페이지가 열리지 않는다 (페이지도 서버가 내주고, PIN 도 확인할 수 없음). 게임 창 ☰ → 관리는 서버 연결을 먼저 확인하고, 꺼져 있으면 토스트 "서버에 연결할 수 없습니다 — start.command 로 서버를 켜세요". 관리 페이지를 연 뒤에 서버가 꺼지면 읽기 전용 + 같은 안내 (저장 버튼 비활성) |
| 저장 단위 | 저장 버튼 1번 = 게임 데이터 파일 1번 쓰기 (+ 필요한 이미지 업로드) |

## 2. 진입 — 별도 페이지 `/admin` (R-31)

| 방법 | 동작 |
| --- | --- |
| 게임 창 ☰ → "관리" (메뉴 맨 아래, 구분선 아래 작은 글씨) | **새 창**으로 `/admin` 을 연다 → 노트북 화면으로 옮겨서 쓴다 |
| 주소 직접 입력 | `http://127.0.0.1:1029/admin` |

- 관리는 게임 창(`/`) · 진행자 화면(`/host`)과 **다른 페이지 · 다른 창**이다. 세 페이지 모두 같은 로컬 서버가 내준다.
- 모니터의 게임 화면은 그대로 둔 채 노트북에서 고칠 수 있다 — 게임 진행 중에 정답 오타를 고쳐도 게임이 멈추지 않는다.
- 게임 창 단축키(`→`, `Enter` 등)는 관리 창에 영향이 없다 (창이 다르므로).
- 관리 페이지에서 저장하면 서버가 게임 창에 알려(`reload`) 게임 창이 바뀐 파일을 다시 읽는다 — 게임 창 새로고침 불필요 (5-1, [08-tech.md](08-tech.md) 4-4).

### 2-1. 잠금 — 탭에 둔 PIN 을 요청마다 헤더로 (`D-9` 확정, R-31)

관리 페이지는 모든 문제 · 정답을 보여주고 데이터 파일을 고칠 수 있으므로 **PIN 으로 잠근다**. 수준은 진행자 화면([12-host-view.md](12-host-view.md) 5장)과 같다 — 참가자가 정답을 미리 보거나 장난으로 데이터를 고치는 것을 막는다.

| 항목 | 규칙 |
| --- | --- |
| PIN | **진행자 화면과 같은 PIN** — 서버를 켤 때마다 새로 만드는 6자리, 서버 터미널에만 표시 (`--pin` 으로 고정 가능) |
| 첫 화면 | `/admin` 을 열면 PIN 입력 화면부터 (6자리 숫자 칸, 입력은 ● 로 가림). 데이터를 불러오기 전이라 게임 목록 · 문제 · 정답이 없다 |
| 확인 | 입력한 PIN 을 헤더에 실어 `POST /api/admin/verify` → 맞으면 관리 홈, 틀리면 "PIN 이 맞지 않습니다" |
| **탭 단위 보관** | 맞은 PIN 은 **그 탭의 세션 저장소(`sessionStorage`)에만** 둔다. 같은 탭에서 새로고침하면 그대로, 탭을 닫으면 사라진다. 새 탭 · 새 창으로 열면 다시 묻는다 |
| **요청마다 헤더 검사** | 관리 페이지는 `/api/admin/*` 요청마다 헤더 `X-Admin-Pin: <PIN>` 을 붙인다. **서버는 `/api/admin/*` 요청마다 이 헤더를 지금 PIN 과 비교**하고, 없거나 틀리면 401 |
| 쿠키를 안 쓰는 이유 | 쿠키는 같은 브라우저의 모든 창이 함께 쓴다. 관리 PIN 은 관리 탭 안에만 두고 헤더로 보내므로 게임 창 · 진행자 화면과 섞이지 않는다 (진행자 화면에 로그인해 있어도 관리 페이지는 PIN 을 따로 묻는다) |
| [잠그기] | 관리 페이지 오른쪽 위. 탭에 둔 PIN 을 지우고 PIN 입력 화면으로 (자리를 비울 때) |
| PIN 이 바뀌면 (서버 재시작) | 다음 요청이 401 → 편집 내용은 그대로 둔 채 PIN 입력 창 → 새 PIN 을 넣으면 하던 요청(저장 등)을 다시 보낸다 |
| 실패 제한 | 틀린 PIN 5회 → 60초 잠금 (진행자 화면 PIN 실패와 합쳐서 센다). 서버가 바뀐 뒤 옛 PIN 으로 온 요청이 여러 개여도 같은 틀린 PIN 은 1회로 센다 |
| 잠그지 않는 것 | 노트북 모드: 게임 창이 쓰는 데이터 읽기(`/data/**` · `/assets/**`)와 현장 상태 API(`/api/state*`) — 행사 중 게임 진행 · 팀 설정 · 배점표 · 종합 점수판은 PIN 없이 동작해야 하므로. 서버 모드는 이것들도 로그인 필요 ([08-tech.md](08-tech.md) 11-2) — 관리 PIN 확인 때 입장 쿠키도 받는다 |
| 서버 쪽 | `/api/admin/*` 는 PIN 헤더 + (쓰기 요청은) `X-Camp-App` + 같은 출처일 때만 받는다 ([08-tech.md](08-tech.md) 4-3 · 4-5) |

## 3. 화면 구성

```
/admin (관리 페이지, 별도 창)
PIN 입력 ─▶ 관리 홈 ─▶ 게임 편집 ─▶ 카테고리 편집
                  │              └─▶ 문제 목록 ─▶ 문제 편집 / 여러 장 추가 / 표 붙여넣기
                  ├─▶ 점수 입력 (종합 점수판 입력 — R-25)
                  ├─▶ 상태 초기화 (R-32, 3-10)
                  ├─▶ 백업 내려받기 · 올리기 (R-37, 3-11)
                  ├─▶ 백업 목록 (게임별 저장 전 사본, 5-3)
                  ├─▶ 전체 검증
                  ├─▶ 안 쓰는 이미지 정리 (R-68, 3-14)
                  └─ (관리 홈 안) 공개 모드 켜기 · 끄기 (R-96, 3-16)
```

### 3-1. 관리 홈

| 요소 | 내용 |
| --- | --- |
| 서버 상태 | "● 저장 가능 (127.0.0.1:1029)" / "○ 서버 연결 안 됨 (읽기 전용)". 5초마다 서버 확인(2초 안에 답이 없으면 연결 안 됨) · 관리 요청이 네트워크 오류면 연결 안 됨. 뜨는 순간 그때 응답 시간을 재어 서버 로그에 비콘 한 줄 (R-66 — [08-tech.md](08-tech.md) 11-4) |
| 게임 목록 | 게임별 카드: 아이콘 · 이름 · type · 카테고리 수 · 문제 수 · 검증 상태(✔ / ⚠ 경고 n / ✕ 오류 n) |
| 🌐 공개 모드 (R-96) | 게임 목록 바로 아래 — 지금 상태(켜짐 · 꺼짐)와 [공개 모드 켜기] / [공개 모드 끄기] · (켜짐) [↗ /play 열기] (3-16) |
| 데이터 보관 (R-37) | "저장한 내용은 이 서버에 바로 남습니다 — 모두가 같은 내용을 봅니다. 노트북으로 옮기거나 보관하려면 백업을 내려받으세요." + [⬇ 백업 내려받기 · ⬆ 올리기] (3-11) |
| 백업 | [백업 목록] — 게임별 저장 직전 사본 목록, 선택 시 그 시점으로 복원 (5-3) |
| 검증 | [전체 검증] — 모든 게임 데이터 · 이미지 존재 · 쓰지 않는 이미지 검사 결과 표 (`GET /api/admin/check`). 쓰지 않는 이미지가 있으면 그 줄에 [🗑 하나씩 보며 정리] |
| 안 쓰는 이미지 정리 (R-68) | [🗑 안 쓰는 이미지 정리] → 문제가 쓰지 않는 이미지를 한 장씩 크게 보며 지운다 (3-14) |
| 점수 입력 (R-25) | [점수 입력] → 종합 점수판 입력 표 (게임 창 ☰ → 종합 점수판과 같은 데이터). 노트북에서 입력하면 게임 창에도 바로 반영된다. [🏅 배점표] 탭 · [라운드 설정] 도 함께 — [13-scoreboard.md](13-scoreboard.md) 10-5 |
| 상태 초기화 (R-32) | [상태 초기화] → 진행 기록 · 점수판 · 팀 설정 등 현장 상태를 골라 초기화 (3-10) |
| [잠그기] | 이 탭의 PIN 을 지우고 PIN 입력 화면으로 (2-1) |
| [📖 설명서] (맨 위, 모든 화면) | 진행자 요약 설명서 화면 (3-12, R-38) |

- **새 게임 추가는 어드민 기능이 아니다** — 새 게임 종류(type)도, 기존 type 의 새 게임도 범위 밖 (`D-10` 확정, 스펙 아웃). 필요해지면 앱 기능이 아니라 이 프로젝트 하네스(저장소에서 Claude Code 로 데이터 파일 · 문서를 직접 고침)로 처리한다. 지금은 스킬로도 만들지 않는다.

### 3-2. 게임 편집

| 구역 | 편집 항목 |
| --- | --- |
| 기본 정보 | 게임 이름, 아이콘, 설명, 규칙 문구(줄 추가 · 삭제 · 순서) |
| 진행 기본값 | 득점형: 라운드 수, 라운드당 문제 수, 문제 순서(랜덤 / 작성 순서), **팀당 대표 (0 = 끔)** — 사진 게임에만 보인다. 라운드당 문제 수는 팀당 대표 방식에서도 처음 뽑는 수다 (R-95 — 순위가 정해지면 다 내지 않아도 라운드 끝) (`defaults.relay` 0 ~ 6, 데이터에 값이 없으면 사진 2명 — R-62, [02-data-schema.md](02-data-schema.md) 3-3), **인당 문제** — 한 사람이 몇 문제를 맞히면 빠지는지 (`defaults.perRep` 1 ~ 5, 없으면 1 — R-64). 팀은 대표 × 인당 문제만큼 맞히면 끝. 맞힌 사람은 진행자 화면 · 게임 화면 점수 띠에서 팀 · 대표를 눌러 기록한다 (R-94). 안내 문구에 "릴레이" · "다음 대표" 를 쓰지 않는다 — 팀당 대표 안내 "팀마다 이만큼 함께 나와 맞힌 사람은 빠지고, 대표가 모두 빠진 순서로 등수. 0 = 끔 (정답 수 방식, 라운드당 문제 사용)" / 룰렛형: 문제 순서(랜덤 / 작성 순서)만 — 주제 안 [다음 문제] (R-45, 라운드 · 추첨 옵션은 없음 `D-7`). 줄줄이 말해요의 문제 순서는 **여기서만** 정한다 — 게임 홈에는 옵션이 없다 (R-65). 타이머 없음 (R-33) |
| 판정 (득점형) | 편집 항목 없음 — 판정은 선착순(`D-2`), 동점은 추가 문제 오픈(`D-3`)으로 고정. 배점은 배점표에서 ([13-scoreboard.md](13-scoreboard.md)) |
| 카테고리 목록 | 카드 목록 — 아이콘 · 이름 · 문제 수 · 숨김 여부. ▲▼ 로 순서 변경. [+ 카테고리 추가] |

- 카테고리 카드 버튼: [편집] [문제 관리] [숨기기 / 보이기] [삭제]. 줄줄이 말해요 주제도 [문제 관리] 가 있다 (선택 — 문제 없이 써도 됨, R-44 · 3-13). 줄줄이 말해요 목록의 개수 열은 "예시 n · 문제 m".

### 3-3. 카테고리 추가 · 편집

| 필드 | 입력 | 규칙 |
| --- | --- | --- |
| 이름 | 텍스트 | 필수, 16자 이내, 게임 안에서 중복 금지 |
| id | 텍스트 (영문) | 필수, 슬러그 형식 ([02-data-schema.md](02-data-schema.md) 3-6), 게임 안에서 유일. **추가할 때만 입력 가능, 이후 변경 불가** (이미지 폴더 · 문제 id 가 이 값에 묶임). 이름을 입력하면 `category-k7q2` 처럼 무작위 id 를 제안 (다른 사람이 동시에 만든 카테고리와 겹치지 않게 — `D-14`). 알아보기 쉬운 영문으로 바꿔도 된다 |
| 아이콘 | 이모지 선택기 (자주 쓰는 32개 + 직접 입력) | 1개 |
| 설명 | 텍스트 | 40자 이내 |
| 질문 문구 (득점형) | 텍스트 | 30자 이내. 문제 화면에 표시 (예: "이 장면의 명대사는?") — R-17 |
| 기본 연출 (`photo`) | 원본 / 확대 / 가림 | 이 카테고리에 문제를 추가할 때 처음 선택될 연출 |
| 규칙 문구 (룰렛형) | 텍스트 | 60자 이내, 주제 카드에 표시 |
| 예시 (룰렛형) | 태그 입력 (Enter 로 추가) | 최대 20개, 각 20자 |
| 숨김 | 토글 | 숨기면 게임 홈 · 룰렛에 안 나옴 (데이터는 유지) |

- 저장 → 데이터 파일 갱신 (5장). 새 카테고리는 득점형이면 문제 0개 상태로 생성 → [문제 관리] 로 바로 이동 제안.

### 3-4. 카테고리 삭제

| 상황 | 동작 |
| --- | --- |
| 문제 0개 | 확인창 후 데이터에서 제거 |
| 문제 있음 | 확인창 "문제 7개가 함께 삭제됩니다. 숨기기를 권장합니다." [숨기기] [삭제] [취소] |
| 진행 중 게임이 이 카테고리를 쓰는 중 | 삭제 불가, 숨기기만 가능 ("진행 중인 게임에서 사용 중") |

- 삭제해도 **이미지 파일은 저절로 지우지 않는다** (영구 삭제 방지). 쓰지 않는 이미지는 [전체 검증] 에서 "사용 안 하는 이미지 n개" 로 안내하고, [🗑 안 쓰는 이미지 정리] 에서 사람이 한 장씩 보고 지운다 (3-14, R-68).
- 설정의 제외 목록에 있던 id 는 자동 정리 ([03-settings.md](03-settings.md) 4장).

- 같은 카테고리에 같은 정답이 이미 있으면 경고 "같은 정답의 문제가 있습니다 (food-zoom-3fhx)" — 저장은 가능 (W07).
- 확대 연출에서는 처음(가장 확대) 화면에 보이는 범위를 점선 상자로 보이고 그 밖을 어둡게 한다. 가림 상자는 선택 후 `Delete` 로도 지운다.
- 버튼: [취소] (저장하지 않고 목록으로) · [저장하고 새 문제] (추가할 때만 — 같은 카테고리 문제 추가 화면이 다시 열림) · [저장] (`⌘S`).
- `addedAt` 은 새 문제에만 기록하고, 편집 저장은 원래 값을 그대로 둔다.
- 클립보드 붙여넣기 `⌘V` (R-34) — 이모티콘 문제 편집(3-8)도 같은 규칙:
  - 받는 것: 클립보드에 이미지가 들어 있을 때 — 화면 캡처(`⌘⌃⇧4`), 웹페이지 이미지 오른쪽 클릭 → "이미지 복사", Finder 에서 이미지 파일 복사(`⌘C`).
  - 들어가는 곳: 문제 이미지가 기본. 정답 이미지 칸을 누른 뒤 붙여넣으면 정답 이미지 (문제 이미지 칸을 누르면 다시 문제 이미지). 지금 붙여넣을 칸은 테두리로 보인다.
  - 처리는 끌어다 놓은 파일과 같다 — 형식 · 축소 규칙(4장), 저장할 때 업로드. 들어가면 토스트 "클립보드 이미지를 넣었습니다".
  - 글자 칸에 커서가 있고 클립보드에 글자가 있으면 글자 붙여넣기를 그대로 둔다 (정답 · 메모 등).
  - 클립보드에 이미지가 없으면 토스트 "클립보드에 이미지가 없습니다 — 웹페이지 이미지는 오른쪽 클릭 → '이미지 복사' 로 복사하세요" (글자 칸 밖에서 눌렀을 때). 웹페이지를 드래그로 골라 복사하면 이미지 대신 주소만 들어가는 경우가 많다.
  - 확인 창이 떠 있을 때는 붙여넣지 않는다.

### 3-7. 여러 장 한 번에 추가 (`photo`)

- 이미지 여러 장 선택 → 표 형태로 한 번에 입력: 썸네일 · 정답(기본값 = 파일명에서 확장자 · 숫자 · 밑줄 제거) · 연출(기본값 = 카테고리 기본 연출).
- [모두 저장] → 이미지 업로드 → id 발급 → 데이터 파일 한 번 저장.
- 확대 지점 · 가림 상자는 일괄 추가 후 각 문제 편집에서 지정 (연출이 확대 · 가림인데 설정이 비어 있으면 목록에 "⚠ 설정 필요" 표시, 그 문제는 숨김 상태로 저장).
  - 데이터에는 "설정 필요" 필드가 없으므로 이렇게 표시한다: 확대 = `zoom: 5` · `focus` 기본값(가운데) · 숨김, 가림 = 이미지 전체를 덮는 상자 하나 `[0, 0, 100, 100]` · 숨김. 목록은 "숨김 + 이 모양" 이면 "⚠ 설정 필요" 로 본다.
  - 그 문제를 편집으로 열면 가림은 상자 없이 시작하고, 숨김은 풀린 채로 열린다 → 상자 · 지점을 정하고 저장하면 바로 출제 대상이 된다.
- 업로드가 끝난 행은 저장이 실패(409 등)해도 다시 [모두 저장] 할 때 같은 id · 파일을 그대로 쓴다.
- 클립보드 붙여넣기는 두지 않는다 — 클립보드에는 이미지가 한 장씩만 들어가므로 여러 장은 파일로 (R-34). 한 장씩은 3-6 문제 편집에서 `⌘V`.

### 3-9. 표 붙여넣기 (`emoji` · `roulette`, R-15)

- 문제 목록(또는 룰렛형의 게임 편집) 상단 [표 붙여넣기] → 큰 입력 칸 → 구글 시트 · 엑셀에서 복사한 표 붙여넣기.
- 열 형식: [02-data-schema.md](02-data-schema.md) 6장 (첫 줄이 머리글이면 자동으로 건너뜀).
- 미리보기 표: 행마다 ✔ 등록 / ⚠ 경고(체크박스로 포함 여부) / ✕ 제외(사유).
  - ⚠ 중 **이미 있는 정답 · 표 안에서 겹치는 정답**(줄줄이: 같은 주제 이름)은 처음에 체크를 빼 둔다 — 같은 시트를 다시 붙여넣어도 중복으로 들어가지 않게. 그 밖의 ⚠(이모지 아닌 글자 · 글자 수 초과 등)는 체크된 채로 시작.
  - 없는 카테고리 이름 → "새 카테고리 '○○' 를 만들까요?" 행 묶음 표시, id 입력 칸 제공 (무작위 id 제안 — 3-3). 체크를 빼면 그 카테고리 행은 등록하지 않는다.
- [n개 등록] → 카테고리별 끝에 붙여넣은 행 순서대로 추가, id 발급, **한 번의 저장**.
- 템플릿: 관리 화면 [템플릿 복사] → 머리글 행이 클립보드에 복사됨 (구글 시트 첫 행에 붙여넣기용). 파일 템플릿은 `docs/templates/emoji-quiz-template.tsv`.

### 3-10. 현장 상태 초기화 (R-32)

현장 상태 파일(`state/` — 팀 설정 · 진행 기록 · 점수판)을 깨끗한 상태로 되돌린다. 리허설 · 테스트 뒤 서버에서 초기화하면 모두가(게임 화면 · 진행자 화면) 바로 깨끗한 상태를 본다 (상태 파일은 git 에 올리지 않는다 — R-37).

| 대상 | 파일 | 초기화하면 |
| --- | --- | --- |
| 진행 기록 (게임별로 고를 수 있음) | `state/sessions/<게임 id>.json` | 진행 · 완료 기록 없음 — 게임 홈은 [게임 시작], 이어하기 카드 · 지난 결과 없음 |
| 종합 점수판 입력값 | `state/scoreboard.json` 의 입력값 | 모든 칸 빈칸. 배점 · 라운드 설정은 그대로 |
| 배점 · 라운드 설정 | `state/scoreboard.json` 의 변경분 | `data/scoreboard.json` 기본값으로 |
| 팀 설정 | `state/settings.json` 의 팀 | 팀 미설정 (이름 · 색 · 수) |
| 게임 옵션 · 카테고리 제외 | `state/settings.json` 의 게임별 설정 | 데이터 기본값(`defaults`), 제외 없음 |
| 표시 설정 | `state/settings.json` 의 제목 · 부제 | `data/app.json` 값 |
| 마지막 화면 위치 | `state/route.json` | 비움 |

| 버튼 | 고르는 대상 | 쓰는 때 |
| --- | --- | --- |
| [리허설 기록 지우기] | 진행 기록 전체 + 종합 점수판 입력값 (팀 · 배점 · 옵션은 유지) | 10/27 리허설 뒤 |
| [전부 초기화] | 위 표 전부 | 처음부터 다시 세팅할 때 |
| 직접 고르기 | 표의 체크박스 (진행 기록은 게임별) | 그 밖 |

- 팀 설정을 고르면 진행 기록 · 종합 점수판 입력값도 자동으로 함께 고른다 — 팀 수가 사라지면 둘 다 쓸 수 없다 ([03-settings.md](03-settings.md) 6장과 같은 규칙).
- [초기화] → 확인 창: 지워지는 항목 목록 + 진행 중인 게임이 있으면 "진행 중: 사진 보고 맞추기 R2 · 3번 문제 — 함께 지워집니다". 확인 버튼은 `--danger`.
- 서버가 각 파일의 직전 내용을 `state/.backup/` 에 복사한 뒤 초기 상태로 **덮어쓴다** (파일을 지우지 않음 — [08-tech.md](08-tech.md) 4-5). 이때는 진행 기록도 백업한다.
- 초기화 후 서버가 게임 창에 `reload` 를 보낸다 → 게임 창은 상태를 다시 읽고, 지워진 게임을 보고 있었으면 제목 화면으로 + 토스트 "관리 페이지에서 현장 상태를 초기화했습니다".
- 결과 안내: "초기화했습니다". 되돌리려면 초기화 전에 받아 둔 백업 파일을 [백업 올리기] (3-11) 하거나, 서버 저장 폴더의 `state/.backup/` 사본을 쓴다. 큰 초기화 전에는 [백업 내려받기] 를 먼저 권한다 (확인 창에 안내).
- 서버 API: `POST /api/admin/state/reset` ([08-tech.md](08-tech.md) 4-3).
- 게임별 [새로 시작] · 종합 점수판 [초기화] · 팀 설정 "모든 설정 초기화" 는 그대로 있다. 이 화면은 그것들을 한곳에서 한 번에 하는 곳이다.

### 3-11. 백업 내려받기 · 올리기 (R-37)

서버 저장 폴더의 내용을 **파일 하나로 받거나, 받은 파일로 되돌린다**. 쓰는 때: 서버 ↔ 노트북 옮기기, 행사 전날 · 끝난 뒤 보관, 큰 수정 · 초기화 전. 노트북 모드에서도 똑같이 동작한다.

| 버튼 | 동작 |
| --- | --- |
| [⬇ 백업 내려받기] | `data/` · `assets/` · `state/` 를 묶은 **`camp-game-<YYYYMMDD-HHmmss>.tar`** 를 내려받는다 (Blob 에 있는 이미지도 서버가 받아 와 넣는다 — R-67, Blob 전송량에 셈). 자동 백업 폴더(`.backup/`) · 숨김 파일 · 서버 서명 키는 넣지 않는다. Mac 에서 더블클릭(또는 `tar xf`)하면 `data` · `assets` · `state` 폴더로 풀린다 |
| [⬆ 백업 올리기] | `.tar` 파일 고르기 → **미리보기** → [올리기] → 나눠 보낸다: 서버가 목록 · 문제 · 상태를 검사하고 지금 문제 · 현장 상태를 자동 백업한 뒤 → 이미지(4MB 조각) → 문제 · 상태 순으로 같은 이름 파일을 덮어쓴다. 보내는 동안 "올리는 중… 이미지 n / N (MB)" |

미리보기 (브라우저에서 파일을 읽어 보여준다 — 올리기 전에 서버에 보내지 않음):

| 항목 | 내용 |
| --- | --- |
| 담긴 것 | 폴더별 파일 수 · 크기, 게임별 카테고리 · 문제 수, 현장 상태 파일(팀 설정 · 진행 기록 · 점수판) 유무 |
| 고르기 | ☑ 문제 · 이미지 (`data/` · `assets/`) ☑ 현장 상태 (`state/`) — 둘 다 기본 켬. 예) 노트북에서 넣은 문제만 서버로 옮기고 서버의 팀 설정 · 진행 기록은 두려면 현장 상태를 끈다 |
| 건너뛰는 것 | 정해진 위치 밖 파일, `..` · 숨김 파일 · 링크, 이미지 확장자가 아닌 `assets/` 파일 — "건너뜀 n개" 와 목록 |
| 오류 | 게임 데이터가 검증 오류(02 문서 5장)면 올리지 않는다 — 오류 목록 표시. 상태 파일 형식이 틀리면 그 파일만 건너뛴다 |
| 확인 창 | "서버의 같은 이름 파일을 덮어씁니다. 서버에만 있는 파일은 남습니다. 올리기 전 지금 문제 · 현장 상태는 자동 백업으로 남깁니다 (이미지는 지우지 않으므로 빼고)." + 진행 중인 게임이 있으면 "게임 진행 중에는 올리지 마세요" (`--danger`) |

- **나눠 올리기** (R-51 · DEP-18 — Vercel 은 요청 하나가 4.5MB 까지): ① 시작 — 목록과 문제 · 현장 상태 JSON 을 보내면 서버가 다시 검사하고(걸리면 아무것도 쓰지 않음) 자동 백업을 남긴다 ② 이미지 — 하나씩, 4MB 가 넘으면 조각으로 (서버가 마지막 조각에서 이어 붙여 쓴다) ③ 끝 — 문제 · 현장 상태를 쓴다. 이미지를 먼저 쓰므로 중간에 끊겨도 문제가 아직 없는 이미지를 가리키지 않는다 (먼저 올라간 이미지는 [전체 검증] 의 쓰지 않는 이미지로 보인다 — 다시 올리면 된다). 서버에 임시 사본을 쌓지 않는다.
- 올리기 전 서버 내용은 저장 폴더의 `.restore-backup/` 에 tar 로 남긴다 (최근 3개) — **문제 · 현장 상태만**. 올리기는 이미지를 지우지 않고 같은 이름만 덮어쓰므로 이미지는 넣지 않는다 (무료 Redis 용량 — R-51). 이 화면의 "올리기 전 자동 백업" 목록에서 내려받아 다시 올리면 되돌릴 수 있다.
- 다 쓰면 서버가 게임 화면 · 관리 페이지에 다시 읽으라고 알린다 (`reload`) — 열린 화면이 새 내용으로 바뀐다.
- 크기 제한 300MB (이미지 수백 장). 파일 하나는 이미지 15MB · JSON 2MB 까지 (이미지는 4MB 조각으로 나눠 보낸다).
- 서버 API: `GET /api/admin/archive` (내려받기), `POST /api/admin/archive/begin` → `PUT /api/admin/archive/upload/<id>?path=&offset=` → `POST /api/admin/archive/upload/<id>/finish` (나눠 올리기 — 화면이 쓰는 것), `POST /api/admin/archive?parts=data,state` (한 번에 올리기, 본문 tar — 요청 크기 상한이 없는 Node 서버용), `GET /api/admin/archive/auto` · `GET /api/admin/archive/auto/<파일>` (올리기 전 자동 백업 목록 · 내려받기) — 모두 PIN 헤더 ([08-tech.md](08-tech.md) 4-3).

### 3-12. 진행자 설명서 (R-38)

- 맨 위 줄 [📖 설명서] → "⚙ 관리 › 진행자 설명서" 화면. 진행자 화면의 설명서([12-host-view.md](12-host-view.md) 4-7)와 같은 내용에 **관리 페이지 구역**을 더한다. 넓은 화면에서는 카드 여러 열로 한 화면에 보이게.
- 관리 페이지 구역: 문제 고치기(게임 → 카테고리 → 문제, 저장하면 바로 반영 — 진행 중이면 진행자 화면 정답만 바뀜), 잘못 저장했을 때 [↺ 백업 목록], 점수 [🏆 점수 입력], 백업 받을 때(리허설 뒤 10/27 · 행사 전날 10/28 · 끝난 뒤 10/29 → [💾 백업 내려받기 · 올리기]), 리허설 뒤 [🧹 상태 초기화] → [리허설 기록 지우기].
- 서버 API 를 쓰지 않는 화면이라 서버가 꺼져 있어도 열린다.

### 3-13. 문제 추가 · 편집 (줄줄이 말해요, R-44)

줄줄이 말해요 → 주제 [문제 관리] → [+ 문제 추가] / [편집].

```
┌──────────────────────────────────────┬──────────────────────────────────┐
│ 📜 앞 두 글자로 네 글자 — 문제 추가    │ 미리보기 (게임 화면)               │
│ 문제   [ 코스○○          ] [○ 넣기]   │  ┌────────────────────────────┐ │
│ 정답 후보 [ 쓰고 Enter · 쉼표로 여러 개 ] │  │   📜 앞 두 글자로 네 글자     │ │
│   (코스모스 ✕) (코스요리 ✕) (코스피아 ✕) │  │          코스○○             │ │
│   후보 3개                            │  └────────────────────────────┘ │
│ 메모   [ '코스닥' 은 세 글자라 불인정 ] │                                  │
│ 숨김   ☐ 출제에서 빼기                 │                                  │
│ id     category-m3xk-9tdw (자동 발급)  │                                  │
├──────────────────────────────────────┴──────────────────────────────────┤
│                         [취소] [저장하고 새 문제] [저장 (⌘S)]              │
└──────────────────────────────────────────────────────────────────────────┘
```

| 필드 | 입력 | 규칙 |
| --- | --- | --- |
| 문제 | 텍스트 + [○ 넣기] (커서 자리에 `○` — 맥에서 ○ 를 치기 번거로워서) | 필수. 20자 권장 (넘으면 경고, 화면에서 축소). 게임 화면에 이 글자 그대로 크게 |
| 정답 후보 | 태그 입력 — 쓰고 `Enter` 로 하나씩. **쉼표 · 줄바꿈이 섞인 글을 붙여넣으면 여러 개로 나눠 한 번에** (구글 시트 한 열을 복사해 붙여넣어도 됨). 칩 ✕ 로 빼기. 개수 표시 | 필수 1개 이상. 앞뒤 공백 정리, **같은 후보는 하나만** (띄어쓰기 · 대소문자 무시하고 비교 — 겹치면 "이미 있음" 토스트). 각 30자 · 50개 권장 (넘으면 경고) |
| 메모 | 여러 줄 | 100자. 진행자 화면 전용 (인정 기준 등) |
| 숨김 · id | 사진 · 이모티콘 문제와 같음 | id 는 자동 발급 (3-5 와 같은 규칙) |

- 같은 주제에 같은 문제 글자가 있으면 "⚠ 같은 문제가 있습니다 (id) — 저장은 됩니다" (W07).
- 미리보기: 게임 화면의 문제 화면을 같은 비율로 작게 (주제 · 규칙 · 문제 글자). 정답 후보는 미리보기에 나오지 않는다 (모니터에는 진행자가 켤 때만).
- 저장 = 데이터 파일 한 번 쓰기 (5장). 주제 `questions` 끝에 추가. [저장하고 새 문제] 는 같은 주제의 빈 편집 화면으로.
- 표 붙여넣기(3-9)로 문제를 한꺼번에 넣는 것은 하지 않는다 — 주제 붙여넣기만 (필요해지면 추가).

### 3-14. 안 쓰는 이미지 정리 (R-68)

문제를 지우거나 이미지를 빼고 · 바꾸면(확장자가 바뀔 때) 옛 이미지 파일이 저장소에 남는다 (3-4 · 4장 — 저절로 지우지 않음). 10/27 운영 저장소(Upstash 무료 250MB)에서 131MB 중 이미지가 124MB, 그중 81개 · 30MB 가 문제에서 쓰지 않는 이미지였다. 이 화면에서 **사람이 한 장씩 보고** 지운다.

| 요소 | 내용 |
| --- | --- |
| 들어가기 | 관리 홈 [🗑 안 쓰는 이미지 정리] · [전체 검증] 의 "사용 안 하는 이미지" 줄 [🗑 하나씩 보며 정리] |
| 위 안내 | "문제에서 쓰지 않는 이미지 n개 · 합계 — 문제를 지우거나 이미지를 바꾸면 옛 파일이 남습니다. 큰 것부터 보여 줍니다." + 경고 "지운 이미지는 되돌릴 수 없습니다. 보관하려면 먼저 백업을 내려받으세요 (이미지가 함께 들어갑니다). 예전 문제 백업으로 되돌리면 지운 이미지는 없는 이미지(W02)로 보입니다." + [💾 백업 내려받기 · 올리기] (3-11). 없으면 "문제에서 쓰지 않는 이미지가 없습니다 ✔" |
| 한 장 보기 | "3 / 81" · 게임 › 카테고리(지운 카테고리면 id + "없는 카테고리") · 파일 이름, 이미지 크게(화면 높이의 56%), 크기 · 저장 시각. [◀ 이전] [다음 ▶] (← → 키도, 끝에서 처음으로 돈다) · **[🗑 이 이미지 지우기]** — 누르면 바로 지우고(확인창 없음 — 보고 누르는 버튼) 다음 장으로, 토스트 "지웠습니다 — <파일> (<크기>)" |
| 목록 | 아래 표 — 번호 · 게임 › 카테고리 · 파일 · 크기, 큰 것부터. 줄을 누르면 그 장으로. 지운 줄은 빠진다 |
| 무엇이 "안 쓰는" 이미지인가 | 게임별 `assets/<게임 id>/` 아래 이미지 중 그 게임 문제의 `image` · `answerImage` 가 가리키지 않는 것 ([전체 검증] W08 과 같은 기준). 데이터 파일이 없거나 깨진 게임은 무엇을 쓰는지 알 수 없어 빼고 "데이터 파일을 읽을 수 없는 게임은 빼고 찾았습니다: <id>" |
| 서버 확인 | 지우기 요청마다 서버가 **그 게임 데이터를 다시 읽어** 문제가 쓰는 이미지면 409 "문제에서 쓰는 이미지라 지우지 않았습니다" — 다른 창에서 그 이미지를 다시 쓰게 저장했어도 지워지지 않는다 (게임 저장과 같은 줄에서 확인 → 지우기). 이미 지웠으면 404 |
| 로그 | `🗑 이미지 지움 <경로> (<크기>KB — 쓰지 않는 이미지, 관리 페이지)` |

- API: `GET /api/admin/images/unused` → `{ images: [{ game, path, size, mtimeMs }], skipped }`, `DELETE /api/admin/assets/<게임>/<카테고리>/<파일>` → `{ path, size }` ([08-tech.md](08-tech.md) 4-3).
- Redis 저장소에서는 파일 키 · 조각 키 · 폴더 목록 항목을 함께 지운다 (Upstash 콘솔에서 키를 직접 지우면 조각이 남을 수 있다 — 이 화면으로 지운다).
- Blob 저장소(R-67)에 있는 이미지도 이 화면에서 지운다 — Blob 에서 먼저 지우고 머리말을 지운다. 미리보기는 서버가 302 로 Blob 주소를 알려 준다.

### 3-15. 이미지 Blob 으로 옮기기 (R-67) — 걷어냄 (DEP-27)

10/27 운영 Redis 에 있던 쓰는 이미지 146개를 이 화면([☁ 이미지 Blob 으로 옮기기] — 한 장씩 · 멈추기 · 다시 하기, 서버 모드만)으로 Vercel Blob 에 옮긴 뒤 **화면 · API 를 걷어냈다** (Upstash 131MB → 988KB — [15-qa-results.md](15-qa-results.md) 39장). 새로 올리는 이미지는 처음부터 Blob 으로 간다 ([08-tech.md](08-tech.md) 11-7).

### 3-16. 공개 모드 켜기 · 끄기 (R-96, `D-37`)

관리 홈 "🌐 공개 모드" 구역에서 **누구나 PIN 없이 게임을 해 보는 `/play`** 를 켜고 끈다 ([01-app-flow.md](01-app-flow.md) 8장). 다시 배포하지 않고 바로 바뀐다.

| 요소 | 내용 |
| --- | --- |
| 상태 (꺼짐) | "꺼짐 — `<주소>/play` 는 "지금은 공개하지 않습니다" 만 보여 줍니다" + [공개 모드 켜기] |
| 켜기 | 확인창 "공개 모드 켜기 — 켜면 `<주소>/play` 에서 누구나 PIN 없이 숨기지 않은 모든 문제의 정답과 사진을 볼 수 있습니다. 사람 사진처럼 밖에 공개하면 안 되는 문제는 먼저 숨기세요." [취소] [켜기] → 토스트 "공개 모드를 켰습니다" |
| 상태 (켜짐) | "켜짐 — 누구나 `<주소>/play` 에서 PIN 없이 게임을 해 볼 수 있습니다 (정답 · 사진 포함, 점수는 남지 않음)" + [공개 모드 끄기] (확인창 없음) · [↗ /play 열기] (새 탭) |
| 안내 | "숨긴 카테고리 · 문제와 진행자 메모는 나오지 않습니다. 게임 화면(/) · 진행자 화면 · 관리 페이지는 켜도 PIN 그대로입니다." |
| 로그 | `🌐 공개 모드 켬 (관리 페이지)` · `🌐 공개 모드 끔 (관리 페이지)` |

- 공개하는 게임은 이모티콘 퀴즈 · 사진 보고 맞추기 — 줄줄이 말해요는 혼자 할 수 없어 켜도 나오지 않는다 (R-97).
- 무엇을 공개할지는 **숨김**으로 정한다 — 카테고리 편집 · 문제 편집의 숨김(3-3 · 3-5). 숨긴 것은 `/play` 에 나오지 않고 그 이미지도 로그인 없이 받을 수 없다. 숨김은 행사용 게임 화면에도 똑같이 적용된다.
- 켜 둔 값은 저장소의 `state/public.json` 에 남는다 — 서버를 다시 켜도 그대로. **백업에는 넣지 않는다**: 백업을 다른 서버 · 노트북에 올려도 공개 모드는 꺼진 채 (거기서 따로 켠다). [상태 초기화] 도 건드리지 않는다.
- API: `GET /api/admin/public` → `{ on }`, `PUT /api/admin/public` `{ on: true | false }` → `{ on }` (PIN 헤더 — 2-1). 그 밖은 400.

## 4. 이미지 저장 규칙

| 항목 | 규칙 |
| --- | --- |
| 저장 경로 | 문제 이미지 `assets/<게임 id>/<카테고리 id>/<문제 id>.<확장자>`, 정답 이미지 `.../<문제 id>-answer.<확장자>` (서버가 폴더 생성) |
| 축소 | 긴 변 2400px 초과 또는 4MB 초과면 **브라우저에서** 긴 변 2400px 로 축소 후 JPEG(품질 0.9 — 그래도 4MB 가 넘으면 0.8 · 0.7 · 0.6) 로 업로드. **500KB 넘는 PNG · JPEG 는 크기 그대로 JPEG 0.85 로 다시 저장** (`D-35` — 화면 캡처 PNG 가 1 ~ 3MB 로 올라가던 것. 투명한 곳이 있는 PNG 는 PNG 그대로, 다시 저장해도 작아지지 않으면 원본). 편집 화면 안내 "1600×900 · 2.1MB → 저장 시 1600×900 JPEG 310KB". gif 는 축소하지 않음 (4MB 이하만). 서버도 이미지 하나는 4MB 까지 받는다 (Vercel 요청 상한 4.5MB — R-51) |
| 저장 위치 | 노트북 · 저장 폴더 서버는 파일. **Redis 저장소(운영 Vercel)는 Blob** (R-67 · DEP-27, [08-tech.md](08-tech.md) 11-7) — Blob 을 쓸 수 없으면 저장이 실패한다 ("이미지 저장소(Blob)를 쓸 수 없어 저장하지 않았습니다", Redis 에 넣지 않음) |
| 방향 | 휴대폰 사진의 회전 정보(EXIF)를 반영해 바로 세워 저장 |
| 업로드 | `PUT /api/admin/assets/<게임>/<카테고리>/<파일명>` — 서버가 PIN 헤더 · 파일명 · 형식 · 크기를 검사 ([08-tech.md](08-tech.md) 4-5). 응답 `{ path, url }` — 운영은 `url`(Blob 주소)을 이미지 주소 표에 바로 넣어 미리보기 · 문제 목록이 Blob 에서 바로 (R-70) |
| 이미지 교체 | 같은 이름으로 덮어씀. 확장자가 바뀌면(png → jpg 등) 옛 파일은 남겨 둠 (저절로 지우지 않음 — [전체 검증] 에 "사용 안 하는 이미지" 로 안내, [🗑 안 쓰는 이미지 정리] 에서 지움, 3-14) |
| HEIC | 지원 안 함 → "HEIC(아이폰 사진)는 지원하지 않습니다. jpg 로 변환해 올려 주세요 (Mac 미리보기 → 내보내기 → JPEG)" |

## 5. 데이터 저장

### 5-1. 저장 절차
1. 관리 페이지에서 게임을 열 때 게임 데이터와 리비전을 받는다 (`GET /api/admin/games/:id`).
2. 저장 시 브라우저에서 먼저 검증 ([02-data-schema.md](02-data-schema.md) 5장). 오류면 저장하지 않고 해당 입력 칸 표시.
3. 이미지가 있으면 먼저 업로드 (4장).
4. `PUT /api/admin/games/:id` (처음 받은 리비전을 `If-Match` 로 보냄) → 서버가 PIN 헤더 확인 · 다시 검증 · 리비전 비교 · 백업 · 원자적 쓰기 ([08-tech.md](08-tech.md) 4-6).
5. 409(다른 곳에서 바뀜) → "파일이 다른 곳에서 바뀌었습니다. [다시 불러오기] 후 편집하세요". 422 → 오류 목록 표시. 401(PIN 이 바뀜 — 서버 재시작 등) → 편집 내용을 둔 채 PIN 입력 창 → 맞으면 저장 다시 시도 (2-1).
6. 성공 → 관리 페이지의 데이터 교체 + 토스트 "저장했습니다 (문제 8개)". 서버가 게임 창에 `reload` 를 보내 게임 창도 새로고침 없이 바뀐 데이터를 쓴다 (메뉴 · 게임 홈 숫자 즉시 갱신). 진행자 화면은 서버가 데이터 파일에서 바로 찾으므로 즉시 반영.

### 5-2. 진행 중 게임과의 관계

| 변경 | 진행 중 게임 영향 |
| --- | --- |
| 문제 정답 · 힌트 · 연출 수정 | 즉시 반영 (진행 기록은 문제 id 로 참조) |
| 문제 추가 | 다음 라운드 추첨부터 후보 문제에 포함 (이미 뽑힌 라운드 문제는 그대로) |
| 문제 숨김 · 삭제 | 이미 이 게임에 뽑힌 문제는 삭제 불가 ("진행 중인 게임에서 사용 중"). 숨김은 가능하되 이미 뽑힌 문제는 계속 출제 |
| 카테고리 숨김 · 삭제 | 3-4 |

- 게임 창은 서버의 `reload` 알림으로 바뀐 데이터를 다시 읽는다 (새로고침 불필요). 진행 기록은 문제 id 로 참조하므로 진행 위치 · 점수는 그대로다.

### 5-3. 백업 복원
- 관리 홈 → [백업 목록] → 게임 · 시각 선택 → 미리보기(카테고리 · 문제 수) → [이 시점으로 복원].
- 복원도 저장과 같은 절차 (서버가 현재 파일을 먼저 백업한 뒤 덮어씀) → 복원을 다시 되돌릴 수 있음.

## 6. 데이터 원본 · git 과의 관계 (R-14, R-37)

- 운영에서 문제 · 이미지 · 현장 상태의 원본은 **서버 저장소**다. 관리 페이지에서 저장하면 바로 모두에게 반영된다 — 커밋 · 푸시가 필요 없다.
- git 저장소의 `data/` · `assets/` 는 **초기 데이터**(서버 첫 시작 · 노트북 모드 시작 값)일 뿐이다. 서버에서 고친 내용을 초기 데이터에도 남기고 싶으면 [백업 내려받기] → 풀어서 `data/` · `assets/` 를 커밋 (선택, [08-tech.md](08-tech.md) 5-4). `state/` 는 git 에 올리지 않는다.
- 서버 ↔ 노트북 옮기기는 3-11, 자세한 경우는 [08-tech.md](08-tech.md) 5-5.
