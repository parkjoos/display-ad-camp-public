# 16. 배포 — Vercel + 외부 Redis (R-51, `D-30`) — 작성 중

같은 앱을 Vercel 에 올려 진행자 여러 명이 휴대폰(LTE · 5G)으로 진행자 화면을 쓰게 한다. 저장은 외부 Redis(Upstash)에 둔다. 서버 모드의 동작 · 잠금 규칙은 [08-tech.md](08-tech.md) 11장, 진행자 화면 쪽은 [12-host-view.md](12-host-view.md) 2-2 · 5-4.

**코드 쪽은 끝났다** — 사내 설정 제거 · 함수 진입점 · 공개 파일 막기 · 실시간 알림 구독 · 실행 시간 상한 대응 · 백업 나눠 올리기 · 이미지 ETag ([14-tasks.md](14-tasks.md) DEP-14 ~ DEP-18 · DEP-20). Vercel · Upstash 첫 배포 · 데이터 옮기기(DEP-19 — 2-1 · 4장)도 10/14 끝냈다 — 결과는 [15-qa-results.md](15-qa-results.md) 20장.

## 1. 구성 한눈에

```
 git push ─▶ Vercel (함수 — 리전 서울 icn1) ─▶ Upstash Redis (도쿄, rediss://) — 원본
                │                        └─▶ Vercel Blob (공개, 서울) — 이미지 바이트 (R-67 · 2-3, Redis 에는 주소만)
                ▲
                │ 인터넷 (https://display-ad-camp.fun + PIN — 2-2)
 노트북(게임 화면 → 모니터) · 진행자 휴대폰(진행자 화면) · 관리 페이지
```

- 문제 · 이미지 · 현장 상태의 원본은 **Redis** 다 (R-37 · R-50). Blob 저장소를 켜면 이미지 바이트만 Blob 에 있고, 어느 이미지가 어디 있는지(주소)는 Redis 에 있다 (R-67 · 2-3). git 은 코드 · 초기 데이터만. 새 버전을 올려도 Redis 내용은 바뀌지 않는다.
- 공개 주소라 주소를 아는 사람은 누구나 닿는다 — **게임 화면까지 PIN** 으로 잠그고, 정답이 든 데이터 · 이미지는 로그인한 사람에게만 준다 (08-tech 11-2).
- 함수 인스턴스가 여러 개 떠도 같게 동작한다 — 같이 볼 상태(실시간 중계 · 잠금 · 연결된 창)도 Redis 에 둔다 (08-tech 11-6).

## 2. 값

| 값 | 어디에 | 내용 |
| --- | --- | --- |
| 공개 주소 (허용 도메인) | Vercel 이 넣음 (시스템 환경 변수) | **넣지 않는다** — 운영 배포는 `VERCEL_PROJECT_PRODUCTION_URL`(가장 짧은 커스텀 도메인 — 대표) · `VERCEL_URL`(배포별 주소) · `VERCEL_BRANCH_URL`(브랜치 주소)로 안다 (R-63, 08-tech 11-1). 도메인을 붙이거나 바꾸면 **다시 배포만** 한다. 프로젝트 Settings → Environment Variables 의 "Enable access to System Environment Variables" 가 켜져 있어야 한다 |
| `CAMP_PUBLIC_ORIGIN` | Vercel 환경 변수 (선택) | 위 주소 말고 더 받을 주소 — `https://<도메인>`, 여러 개면 쉼표로. 지금 값 `https://display-ad-camp.vercel.app` (예비 주소 — 커스텀 도메인이 있으면 시스템 환경 변수에 vercel.app 주소가 없다). 빼면 vercel.app 주소는 403. Production 에만 |
| `CAMP_PIN` | Vercel 환경 변수 (비밀) | 6자리 숫자. **저장소 파일 · 채팅 · 문서에 적지 않는다** |
| `REDIS_URL` · `KV_URL` | Vercel 이 넣음 (Upstash 연결) | Vercel 프로젝트에서 Upstash 를 연결하면 저절로 들어간다(비밀번호가 든 `rediss://`). 앱이 이것을 읽으므로 `CAMP_REDIS_URL` · `CAMP_REDIS_PASSWORD` 는 넣지 않는다 — 다른 Redis 를 쓸 때만 |
| `CAMP_REDIS_PREFIX` | Vercel 환경 변수 (선택) | 기본 `camp-game:` — 리허설용 등 따로 쓰려면 다른 접두어 |
| `CAMP_SEED` | 처음 한 번만 | `1` 이면 빈 Redis 에 초기 데이터를 넣는다 (5장) |
| `BLOB_READ_WRITE_TOKEN` | Vercel 이 넣음 (Blob 저장소 연결) | 있으면 운영 배포에서 이미지를 Blob 에 (R-67 · 2-3). 비밀 값 — 직접 적지 않는다. Production 에 있어야 한다 |

- Vercel · Upstash 계정을 만들고 비밀 값을 넣는 일은 운영자가 직접 한다.
- 리전: Vercel 함수는 서울(`icn1` — `vercel.json`), Upstash 는 서울이 없어 도쿄. 요청 하나가 Redis 를 여러 번 차례로 부르므로 미국 기본값(`iad1`)으로 두면 느리다.
- Upstash **읽기 리전은 두지 않는다** — 도쿄(주 리전)만. Vercel 에서 만들면 Global 타입에 싱가포르 읽기 리전이 붙어 있었는데, 쓰기마다 복제본에서 명령이 한 번 더 세어져(10/14 전체의 약 25%) 10/15 뺐다 (Upstash 콘솔 → Settings → Manage Regions, 바꾼 뒤 30분 동안 다시 못 바꿈). 서울 함수는 도쿄로 붙으므로 읽기 리전은 이득이 없다 (R-55).
- `CAMP_STREAM_MAX_S` 는 넣지 않는다 — Vercel 함수는 270초 (08-tech 11-4).

### 2-1. 만들기 (처음 한 번)

1. ☐ Vercel — 이 저장소로 새 프로젝트 (또는 CLI `vercel`). 프레임워크는 "Other" — 빌드(`npm test`) · 공개 폴더(`public`) · 리전 · 함수 설정은 `vercel.json` 이 정한다. (10/14 만듦)
2. ☐ Upstash — Vercel 프로젝트에서 Upstash for Redis 를 연결(무료, 리전 도쿄 `ap-northeast-1`) → `REDIS_URL` · `KV_URL` 등이 저절로 들어간다. (10/14 연결)
3. ☐ 환경 변수(2장 표 — `CAMP_PIN`)를 **Production 에만** 넣는다 — 비밀 값은 보이지 않게. 미리보기 배포는 앱이 켜지지 않는다(503 "미리보기 배포(preview)는 쓰지 않습니다" — 운영 Redis 를 지킴). Preview 에 `CAMP_PUBLIC_ORIGIN` 을 넣으면 미리보기가 켜져 운영 Redis 에 쓰므로 넣지 않는다. `CAMP_SEED` 는 넣지 않는다 — 쓰던 데이터를 옮긴다 (4장).
4. ☐ 배포 — 공개 주소는 Vercel 시스템 환경 변수로 저절로 (R-63). 도메인을 붙였으면 다시 배포.
5. ☐ 확인 — `/api/health` 200, `/` 은 PIN 화면, 로그인 없이 `/data/app.json` 401 · `/docs/08-tech.md` 404, 로그 "✔ 캠프 게임 함수 시작 — 대표 주소 … · 다른 주소 … · 저장소 Redis …" (PIN 은 로그에 없다).

### 2-2. 도메인 — `display-ad-camp.fun` (R-63, 10/21)

`*.vercel.app` 주소는 가끔 접속이 안 된다 — **사람들에게는 `https://display-ad-camp.fun` 만 알려 준다.** 가장 짧은 커스텀 도메인이라 `VERCEL_PROJECT_PRODUCTION_URL` 로 대표 주소가 된다. `display-ad-camp.vercel.app` 은 `CAMP_PUBLIC_ORIGIN` 으로 예비로 남긴다 (2장).

| | `display-ad-camp.vercel.app` (처음 주소) | `display-ad-camp.fun` (10/21 ~) |
| --- | --- | --- |
| 네임서버 | `vercel-dns-3.com` (Vercel) | `ns1` · `ns2.vercel-dns.com` (Vercel DNS — 도메인을 Vercel 에서 관리) |
| 받는 IP | 지역 · 시각마다 다른 쌍 — 끝자리 .3 · .67 · .130 · .131 · .195 (64.29.17.x · 216.198.79.x) | **64.29.17.65 · 216.198.79.65 두 개로 고정** (10/21 루트 A 레코드 — 아래). 그 전에는 Vercel 이 관리하는 ALIAS 로 4개(.1 · .65) 중 둘 |
| TTL (다시 조회하는 주기) | 5분 | 5분 (고정한 A 레코드 300초. 그 전 ALIAS 는 30분) |

| --- | --- | --- | --- | --- |

- 왜: 루트는 Vercel 이 관리하는 ALIAS 라 IP 가 예고 없이 바뀔 수 있다 (`.67` 같은 IP 가 섞일 수 있음). 고정하면 어느 IP 로 가는지가 정해져, 리허설에서 행사장 망으로 한 번 확인한 결과가 행사 날에도 같다. 두 IP 는 서로 다른 대역 — TCP 에서 막히면 브라우저가 다른 IP 로 넘어간다 (TLS 에서 멈추는 경우는 넘어가지 않음).
- **위험**: ① Vercel 문서에 없는 사용법이다 — "새 레코드가 기본 레코드를 덮어쓸 수 있다" 고만 적혀 있고, Vercel 커뮤니티에서는 IP 를 고를 수 없다는 답이 있다. ② Vercel 이 IP 를 바꾸거나 거둬도 따라가지 않는다. ③ 고정한 IP 가 어떤 망에서 막히면 그 망에서는 계속 실패한다 (해외 일부 망에서 `.1` · `.65` 가 멈춘다는 사용자 보고가 있음 — 한국 보고는 못 찾음). ④ 도메인 상태가 "Invalid Configuration" 이 되면 인증서 갱신(2027-01)에 문제가 될 수 있다 — 10/21 추가 직후 "Valid Configuration" 유지 확인.
- **되돌리기**: 위 A 레코드 두 개를 지운다 → ALIAS 로 돌아간다 (캐시 때문에 최대 5분). 행사(10/29) 뒤 지울지 정한다.
- 인증서는 Vercel 이 Let's Encrypt 로 (`display-ad-camp.fun` · `www`, 2027-01-19 까지 자동 갱신). `www.display-ad-camp.fun` 은 Vercel 이 앱에 오기 전에 apex 로 307 — 허용 목록에 넣지 않아도 된다.
- 로그인 쿠키는 도메인마다 — 새 주소로 바꾸면 게임 화면 · 진행자 화면 · 관리 페이지에서 PIN 을 한 번 더 넣는다. 진행자 휴대폰 홈 화면 아이콘도 새 주소로 다시 만든다.

- 다른 망(LTE · 5G · 행사장 Wi-Fi)에서는 리허설(10/27) 때 새 주소로 접속을 확인한다.

### 2-3. 이미지 Blob 저장소 (R-67 · DEP-26)

Upstash 무료 저장 250MB 중 이미지가 대부분이라(10/27 131MB 중 124MB) 이미지 바이트를 **Vercel Blob 공개 저장소**로 옮긴다. 앱 동작 · 한도는 [08-tech.md](08-tech.md) 11-7. Blob 저장소를 만들고 프로젝트에 연결하는 일은 운영자가 대시보드에서 한다.

**R-67 버전부터 운영은 Blob 필수** — Blob 을 쓸 수 없으면 이미지를 Redis 에 넣지 않고 이미지 저장이 503 으로 실패한다(진행 · 점수 · 이미 있는 이미지 보기는 그대로). 그래서 **1 · 2번(저장소 만들기 · 연결)을 먼저 하고 배포**한다.

1. ☑ Vercel 프로젝트 → **Storage → Create → Blob** — 이름은 자유, **Access: Public**(만들 때 정하면 바꿀 수 없다), **Region: Seoul (icn1)**, 연결할 프로젝트 `display-ad-camp`.
2. ☑ 프로젝트 Settings → Environment Variables 에 **`BLOB_READ_WRITE_TOKEN` 이 Production 에 있는지** 확인 (Production 만 — 미리보기는 앱이 켜지지 않는다).
3. ☑ 배포 → 함수 시작 로그 "… · 이미지 **Vercel Blob (공개)** · …" ("✕ 이미지 저장소(Blob)를 쓸 수 없습니다 — <까닭>" 이면 2번 · 까닭대로).
4. ☑ 관리 페이지 [🗑 안 쓰는 이미지 정리] 로 안 쓰는 이미지를 먼저 지운다 (R-68 — 옮길 양이 준다).
5. ☑ [💾 백업 내려받기] → 보관 (옮기기 전 상태).
6. ☑ 관리 홈 [☁ 이미지 Blob 으로 옮기기] → [☁ n개 옮기기] → "쓰는 이미지가 모두 Blob 에 있습니다 ✔" (실패가 있으면 다시 누르면 남은 것만 — [04-admin.md](04-admin.md) 3-15).
7. ☑ 확인 (10/27 — 15-qa 39장: Upstash 131MB → 988KB, 이미지 146개 모두 Blob, 조각 0) — 게임 화면에서 사진 게임 홈 · 문제 사진이 뜨는지, 관리 페이지 문제 목록 썸네일, Upstash 콘솔 Usage 의 Storage 가 줄었는지 (옮기기 전 131MB → 문제 · 상태 · 백업만), Vercel Usage → Blob 저장 · 작업 수.

- Blob 연결이 끊기면(토큰 없음) 이미 옮긴 이미지는 공개 주소로 그대로 보이지만, 이미지 저장 · 지우기 · 옮기기는 503 — Redis 로 돌아가지 않는다. 연결을 되살리고 다시 배포한다.
- 옮기기를 마친 뒤 옮기기 화면 · API 와 Redis 에서 이미지를 읽는 부분을 걷어냈다 (DEP-27) — 이 절은 기록으로 남긴다. 다시 Redis 에 이미지가 생길 일은 없다 (Redis 저장소는 이미지를 Blob 에만).
- 한도(Hobby): 저장 1GB · 간단 작업 1만 · 고급 작업 2천 · 전송 10GB / 월. **넘으면 30일 동안 Blob 을 쓸 수 없어 사진이 안 뜬다** — 행사 전에 Vercel Usage → Blob 을 본다. 그때는 노트북 모드(6장)로.

### 2-4. Blob 저장소 방화벽 — Referer 로 막기 (R-69 · DEP-28)

Blob 공개 주소는 주소만 알면 누구나 열린다. Blob 자체에는 Origin · Referer 허용 목록이 없어 **저장소 방화벽(WAF) 규칙**으로 우리 화면에서 온 요청만 통과시킨다. 앱(R-69)은 서버가 Blob 에서 받을 때도 Referer `https://display-ad-camp.fun/` 를 붙인다 — 이 버전을 배포한 뒤 규칙을 건다.

1. ☑ Blob 저장소(`display-ad-camp-blob-public`) → Settings → **Firewall → Protect your store → Enable firewall** — 팀 공용 프로젝트 `vercel-blob-default-project` 에 연결된다 (다른 Blob 저장소도 방화벽을 켜면 같은 규칙을 함께 쓴다). (10/27 켬)
2. ☑ 그 프로젝트의 Firewall → **Add New → Rule** (Hobby 는 사용자 규칙 3개까지) → 저장 → Review Changes → **Publish** (10/27 게시):
   - Name: `Referer 없는 Blob 요청 막기`
   - If: **Request Header** `referer` · `Does not start with` · `https://display-ad-camp.fun/` — 헤더가 아예 없는 요청도 걸린다 (10/27 확인)
   - Then: **Deny** — **Challenge 는 쓰지 않는다** (SDK 요청이 429 로 실패).
   - Method 조건은 두지 않는다 — Blob 공개 주소로 들어오는 요청은 GET · HEAD · OPTIONS 뿐이고(규칙 편집기의 Method 값도 이 셋만), SDK 의 올리기 · 지우기는 다른 API 로 가서 이 규칙과 상관없다. GET 만 막으면 HEAD 로 파일이 있는지 · 크기를 Referer 없이 알 수 있다.
3. ☐ 확인 — 10/27 curl: Referer 없음 403 · 다른 사이트 Referer 403 · HEAD(Referer 없음) 403 · `https://display-ad-camp.fun/` Referer 404(없는 시험 경로 — 통과). 이미지를 옮긴 뒤: 게임 화면 · 관리 페이지에서 사진이 뜨는지, 관리 페이지에서 이미지를 하나 올려 보기, [백업 내려받기] 가 되는지, Blob 주소(`https://voyyic4bgrfla0aj.public.blob.vercel-storage.com/…`)를 새 탭에 붙이면 막히는지(403). 방화벽 Traffic 화면에서 Denied 가 그 요청만인지.

- 주소는 `https://display-ad-camp.fun` 으로만 연다 — vercel.app 주소로 연 화면은 Referer 가 달라 사진이 막힌다 (필요하면 조건을 `Does not match expression` `^https://(display-ad-camp\.fun|display-ad-camp\.vercel\.app)/` 로).
- Referer 는 도구로 꾸밀 수 있다 — 주소가 퍼져도 브라우저로는 그냥 안 열리게 하는 정도 (08-tech 11-7). 더 막는 길(비공개 저장소 + 서명 URL)은 하지 않기로 했다 (`D-36`).
- **Vercel 콘솔에서 Blob 이미지 미리보기가 안 뜬다** — 콘솔은 Referer `https://vercel.com/` 를 보내 이 규칙에 막힌다. vercel.com 을 허용 목록에 더하지 않는다 (`D-36`): 콘솔에서 볼 때만 `vercel-blob-default-project` Firewall → Rules 에서 규칙을 끄고(토글) Review Changes → Publish, 다 보면 다시 켜고 Publish.

## 5. 처음 데이터 넣기 · 데이터가 사라졌을 때

- 빈 Redis 를 저절로 초기 데이터로 채우지 않는다 (08-tech 11-6). **처음 한 번만** `CAMP_SEED=1` 을 더해 켜면 코드 폴더의 초기 데이터를 넣는다 (`처음 시작 — 저장소에 초기 데이터 n개 파일을 넣었습니다`). 그 뒤 `CAMP_SEED` 는 뺀다 — 켜 둔 채 Redis 가 비워지면 옛 초기 데이터로 조용히 돌아간다.
- 쓰던 데이터를 옮길 때는 `CAMP_SEED` 없이 켜고 관리 페이지 [백업 올리기] 로 백업 파일을 넣는다 (4장).
- 사라지는 경우: 저장소를 지움 · 접두어를 바꿈 · 누가 같은 접두어 키를 지움 · 무료 저장소가 오래 쓰이지 않아 정리됨.
- 증상: 로그 "저장소가 비어 있습니다", 게임 화면 "data/app.json 을 불러오지 못했습니다".
- 복구: 가장 최근 백업을 넣는다 (4장). 현장 상태는 열려 있던 게임 화면의 임시 사본이 다시 올라가기도 한다 (08-tech 6-1).

## 6. 서버를 쓸 수 없을 때 — 노트북 모드로

- 노트북에서 `start.command` → 노트북 관리 페이지 [백업 올리기] 로 가장 최근 백업(4장)을 올린다 — 문제 · 이미지 · 팀 · 진행 기록이 이어진다. 백업이 없으면 저장소의 초기 데이터로 시작하고 팀 설정을 다시 한다.
- 노트북 모드는 휴대폰 접속이 없다 — 진행자 화면은 노트북 화면에 (12-host-view 2-3).
- 서버가 돌아오면 노트북 [백업 내려받기] → 서버 [백업 올리기] 로 되돌린다.

## 7. 문제 해결

| 증상 | 확인 |
| --- | --- |
| 모든 요청이 503 "서버를 시작하지 못했습니다 — <빠진 설정>" | 응답 · Vercel 로그의 원인대로 — `CAMP_PIN` (Production), "서비스 주소를 알 수 없습니다" 면 시스템 환경 변수 접근(2장), Upstash 연결(`REDIS_URL` · `KV_URL`). "운영자에게 알려 주세요" 면 저장소 접속 실패 — 로그 (08-tech 11-5) |
| 브라우저에 "허용되지 않은 주소입니다" (403) | 함수 시작 로그의 대표 · 다른 주소에 브라우저 주소가 있는지 — 없으면 아래 도메인 행, `CAMP_PUBLIC_ORIGIN` 으로 더했으면 브라우저 주소와 정확히 같은지 (`https://` 포함, 끝 `/` 없이) |
| 저장할 때 "다른 출처의 요청은 받지 않습니다" (403) | 위와 같음 |
| 모두 다시 로그인해야 함 | PIN 을 바꿨거나 저장소의 `.camp-secret`(서명 키 — 08-tech 11-2)이 사라졌다 |
| 로그에 "저장소를 쓸 수 없습니다 — 접속 실패" | `CAMP_REDIS_URL` 의 호스트 · 포트, TLS 면 `rediss://` 인지 |
| 로그에 "… 인증 실패" | `CAMP_REDIS_PASSWORD` 가 Upstash 비밀번호와 같은지 |
| 로그에 "저장소가 비어 있습니다", 게임 화면에 데이터 오류 | 처음이면 5장, 쓰던 서버면 데이터가 사라진 것 — 가장 최근 백업 (5장) |
| 저장할 때 503 "다른 곳에서 저장하는 중" | 다른 인스턴스가 같은 파일을 저장 중 — 다시 저장 |
| 저장 · 연결이 갑자기 모두 실패 | Upstash 무료 한도(명령 · 용량 · 전송)를 넘었는지 — Upstash 콘솔 사용량 |
| Upstash 명령 수가 빨리 는다 | 켜 둔 게임 화면 · 진행자 화면이 있는지 (3-1) — Vercel 로그의 "게임 화면 연결 (다시)" · "진행자 화면 연결" 이 270초마다 찍히면 열린 화면이 있다 |
| 진행자 화면이 "재연결 중" 을 반복 | 휴대폰 인터넷 연결. 서버가 270초마다 먼저 끊고 다시 붙는 것은 화면에 보이지 않는다 (08-tech 11-4) |
| 브라우저가 가끔 "사이트에 연결할 수 없음" · 시간 초과, 몇 분 뒤 되기도 함 | `*.vercel.app` 주소로 들어왔는지 — `https://display-ad-camp.fun` 으로 (2-2). 새 주소에서도 그러면 다른 망(Wi-Fi ↔ LTE)으로 바꿔 보고, 크롬 `chrome://net-internals/#dns` 에서 주소를 조회해 받은 IP 를 기록한다 |
| 게임 화면 "서버 연결 끊김" · 진행자 화면 "○ 재연결 중" · 관리 페이지 "서버 연결 안 됨" 이 가끔 뜸 | Vercel 로그(Runtime Logs)에서 **"연결 끊김"** 을 찾는다 — 뜰 때마다 그 화면이 비콘을 보낸다 (R-66, 08-tech 11-4). "응답 2,904ms (… 요청→첫 응답 2,902)" 처럼 응답이 길면 그 기기의 네트워크가 멈춘 것이고, "도착 n초 뒤" 가 끊겨 있던 시간이다. 10/27 회사 Mac 에서는 모든 TCP 연결이 1 ~ 7초씩 멈췄다 — 보안 프로그램(투명 프록시) · 회사망 문제로, 서버 · DNS 쪽이 아니다 (15-qa 35장). 행사 노트북 · 행사장 망에서 다시 본다. 무료 플랜은 로그를 1시간만 보관하니 뜬 직후에 본다 |
| 도메인을 붙였는데 "허용되지 않은 주소입니다" (403) | 붙인 뒤 다시 배포했는지 (시스템 환경 변수는 배포 때 정해진다). 함수 시작 로그의 대표 · 다른 주소에 그 도메인이 있는지 — 없으면 "Enable access to System Environment Variables" 가 켜져 있는지, 그 도메인이 가장 짧은 커스텀 도메인이 아니면 `CAMP_PUBLIC_ORIGIN` 에 더한다 |
| 사진이 안 뜸 (Blob 을 켠 뒤) | 브라우저 개발자 도구에서 `/assets/…` 가 302 로 `….public.blob.vercel-storage.com` 에 가는지 — 그 주소가 4xx 면 Vercel Usage → Blob 한도를 넘었는지 (넘으면 30일 동안 사용 불가 — 6장 노트북 모드). 302 가 아니라 404 면 그 이미지가 없는 것 (관리 페이지 [전체 검증]) |
| 이미지 저장이 503 "이미지 저장소(Blob)를 쓸 수 없…" | 함수 시작 로그 "✕ 이미지 저장소(Blob)를 쓸 수 없습니다 — <까닭>" 대로: "BLOB_READ_WRITE_TOKEN 이 없습니다" 면 2-3 의 1 · 2번 뒤 다시 배포, "SDK 를 불러오지 못했습니다" 면 빌드 로그(설치) · 함수 묶기 확인. 고칠 때까지 이미지는 저장되지 않는다 (Redis 에 넣지 않음) |
| 방화벽 규칙을 건 뒤 사진이 안 뜸 · 백업 내려받기 실패 | 2-4 의 규칙 — 화면 주소가 `https://display-ad-camp.fun` 인지 (vercel.app 은 Referer 가 다름), 동작이 Challenge 가 아니라 Deny 인지, 서버 요청은 R-69 버전(서버도 Referer 를 붙임)으로 배포됐는지. `vercel-blob-default-project` 방화벽 Traffic 의 Denied 요청에서 Referer 를 본다. 급하면 규칙을 끄고(토글) 게시 |
| 안 쓰는 이미지 지우기가 503 "Blob 에 연결되어 있지 않아" | Blob 에 있는 이미지인데 토큰이 없는 배포 — 2-3 의 2번 |
| `display-ad-camp.vercel.app` 이 403 | `CAMP_PUBLIC_ORIGIN` 에 그 주소가 있는지 (커스텀 도메인이 있으면 시스템 환경 변수에는 vercel.app 주소가 없다) |
| 미리보기 배포 주소가 503 "미리보기 배포(preview)는 쓰지 않습니다" | 정상 — 운영 Redis 를 지키려고 미리보기는 켜지 않는다 (08-tech 11-5) |

## 8. 공개 모드 `/play` (R-96 — 행사 뒤)

관리 페이지 관리 홈 "🌐 공개 모드" [공개 모드 켜기] 로 `https://display-ad-camp.fun/play` 를 연다 — **다시 배포하지 않는다** (스위치는 Redis 의 `state/public.json`, [08-tech.md](08-tech.md) 11-8). 환경 변수도 바꾸지 않는다.

1. ☐ R-96 버전 배포 (`/play` 는 언제나 열리지만 꺼져 있으면 "지금은 공개하지 않습니다").
2. ☐ 관리 페이지에서 **밖에 공개하면 안 되는 문제를 숨긴다** — 특히 사진 보고 맞추기 "인물 퀴즈"(회사 사람 어릴 적 사진 — 행사용으로 동의를 받은 것). 숨긴 카테고리 · 문제와 그 사진은 `/play` 에 나오지 않는다.
3. ☐ [공개 모드 켜기] → 확인창 [켜기]. 함수 로그 "🌐 공개 모드 켬 (관리 페이지)".
4. ☐ 로그인하지 않은 브라우저(시크릿 창)로 `/play` — 게임 목록 · 사진이 뜨는지, `/` 는 PIN 화면 그대로인지.

- **Blob 방화벽(2-4)**: `/play` 화면의 사진 요청도 Referer `https://display-ad-camp.fun/` 라 그대로 통과한다. vercel.app 주소로 연 `/play` 는 사진이 막히니 `https://display-ad-camp.fun/play` 로만 알린다.
- **한도**: 사진은 Blob 에서 바로 받는다 — 전송 10GB / 월 (11-7). 사진 퀴즈 카테고리를 모두 풀면 쓰는 이미지 대부분(약 94MB 이하 — 줄여 올린 뒤면 더 적음)을 받으므로 대략 **월 100명 남짓 모두 풀면 한도**에 닿는다 (카테고리 몇 개만 풀면 그만큼 적다 — R-98). 넘으면 30일 동안 사진이 모두 안 뜬다 — 많이 알릴 때는 Vercel Usage → Blob 전송을 본다. Upstash 는 방문 한 번에 명령 약 6개뿐이다.
- 끄려면 [공개 모드 끄기] — 바로 "지금은 공개하지 않습니다". 이미 받아 둔 브라우저 캐시 사진은 남는다.

## 9. 공개용 저장소 동기화 (R-106)

개발은 이 저장소(`parkjoos/display-ad-camp`)에서 하고, 공개용 사본은 `parkjoos/display-ad-camp-public` 에 둔다. 공개 저장소는 이 저장소의 이력을 갖지 않고 자기 커밋만 쌓는다 (11/02 첫 공개 — 커밋 하나).

| 동작 | `.github/workflows/sync-public.yml` — 이 저장소 `main` 에 푸시하면(또는 Actions 에서 수동 실행) 공개 저장소를 받아 파일을 통째로 바꿔 넣고(`.github` 제외, 이 저장소에서 지운 파일은 지움) 바뀐 게 있으면 새 커밋 하나로 푸시. 푸시가 겹치면 차례로 |

### 9-1. 처음 한 번 — 배포 키 등록 (운영자)

열쇠는 운영자가 직접 만들어 넣는다 (개인 키를 다른 곳에 남기지 않게 마지막에 지운다).

1. ☐ 키 만들기 — `ssh-keygen -t ed25519 -N "" -C "display-ad-camp public sync" -f ~/camp-public-deploy`
2. ☐ 공개 저장소에 배포 키(쓰기 허용)로 — `gh repo deploy-key add ~/camp-public-deploy.pub --repo parkjoos/display-ad-camp-public --title "sync from display-ad-camp" --allow-write` (또는 공개 저장소 Settings → Deploy keys → Add, "Allow write access")
3. ☐ 이 저장소 비밀 값으로 — `gh secret set PUBLIC_REPO_DEPLOY_KEY --repo parkjoos/display-ad-camp < ~/camp-public-deploy` (또는 Settings → Secrets and variables → Actions)
4. ☐ 키 파일 지우기 — `rm ~/camp-public-deploy ~/camp-public-deploy.pub`
5. ☐ 확인 — `gh workflow run sync-public.yml --repo parkjoos/display-ad-camp` (또는 Actions → 공개 저장소 동기화 → Run workflow) → 성공. 공개할 변화가 있었으면 공개 저장소에 `github-actions[bot]` 커밋
