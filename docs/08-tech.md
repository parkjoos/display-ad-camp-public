# 08. 기술

## 1. 실행 방식 (R-2, R-18)

| 항목 | 내용 |
| --- | --- |
| 실행 | Finder 에서 `start.command` 더블클릭 → 터미널이 열리며 로컬 서버 시작 → 브라우저가 `http://127.0.0.1:1029/` 로 자동으로 열림 |
| 터미널에서 실행 | `node server.mjs` (옵션: `--pin <6자리>`) |
| 필요한 것 | Node.js 22 이상 (운영자 노트북 v22.17 확인). **npm 패키지 설치 없음** — Node 내장 모듈만 사용 |
| 주소 | 항상 `http://127.0.0.1:1029` (포트 1029 = 행사일 10/29). 포트가 바뀌면 브라우저 임시 사본(6장)이 달라지므로 고정 |
| 종료 | 터미널에서 `Ctrl+C` 또는 터미널 창 닫기. **게임 진행 중에는 터미널 창을 닫지 않는다** |
| 네트워크 | 필요 없음. 노트북 안에서만 접속 (`127.0.0.1`). 노트북 모드에는 다른 기기 접속 기능이 없다 ([12-host-view.md](12-host-view.md) 2-3) — 휴대폰 접속은 서버 모드로 (11장). 예외 — **정답 영상(R-61)** 은 유튜브에서 틀므로 인터넷이 있어야 한다 (게임 화면이 `https://www.youtube.com/iframe_api` 를 불러 `youtube.com/embed` 플레이어를 띄움). 인터넷이 없으면 영상 없이 정답 글자 — 나머지 진행은 그대로 |
| 배포 | 서버 모드 — Vercel + 외부 Redis 로 옮기는 중 (11장, R-36 · R-51). 문제 · 이미지 · 현장 상태의 원본은 서버 저장소(Redis — 11-6), git 은 코드 · 초기 데이터 (5장, R-37). 노트북 모드는 비상용 |

### `start.command` 동작
1. 스크립트가 있는 폴더로 이동.
2. `node` 가 없거나 22 미만이면 안내 후 종료: "Node.js 22 이상이 필요합니다 — https://nodejs.org 에서 설치하세요".
3. `node server.mjs --open` 실행 → 서버가 준비되면 `open http://127.0.0.1:1029/`.
4. 1029 포트가 이미 쓰이고 있으면 `server.mjs` 가 `GET /api/health` 로 확인해서: 이미 켜진 서버가 이 앱이면 브라우저만 열고 종료, 다른 프로그램이면 안내 후 종료. 오류로 끝나면 터미널 창이 닫히지 않게 Enter 를 기다린다.
- 처음 한 번은 macOS 가 "확인되지 않은 개발자" 경고를 띄울 수 있다 → 우클릭 → 열기. 실행 권한(`chmod +x`)은 저장소에 포함.

## 2. 기술 선택

| 항목 | 선택 | 이유 |
| --- | --- | --- |
| 화면 | HTML / CSS / JavaScript (ES2020, ES 모듈) | 빌드 없음. 서버로 열기 때문에 `type="module"` 사용 가능 |
| 프레임워크 | 없음 | 화면 10여 개 수준 |
| 의존성 (R-67, `D-34`) | `@vercel/blob` 하나 (2.8.1 고정) — 이미지 Blob 저장소(11-7)를 켤 때만 불러온다(동적 import). 전이 의존성 `zod` 는 고친 판(4.6.6)으로 고정(`overrides`) | 노트북 모드 · 저장 폴더 서버 모드는 그 코드를 타지 않아 설치(`npm install`) 없이 그대로 켜진다. Vercel 은 빌드 때 설치한다 |
| 정답 영상 (R-61) | 유튜브 IFrame Player API — 실행 중에 유튜브에서 불러온다 (설치 · 저장 없음). 플레이어 `iframe` 은 앱이 직접 만든다 (`allow="autoplay"` · `referrerpolicy` 를 확실히 — 유튜브는 리퍼러 없는 퍼가기를 거절). 끝 시간은 앱이 0.1초마다 확인해 직접 멈춘다 (`end=` 로 멈추면 추천 영상 화면) — `app/ui/clip.js`, 주소 · 시간 읽기는 `app/core/youtube.js` (서버 · 검증 공용) | 영상 파일을 저장소 · Redis 에 두지 않는다 (용량 · 저작권). 문제 데이터에는 주소와 시간만 |
| 서버 | Node 22 내장 모듈 (`node:http`, `node:fs/promises`, `node:path`, `node:crypto`, `node:os`, `node:net` · `node:tls`) | 설치 없음, 코드 수백 줄 수준 |
| 서버 여러 개 저장소 (R-50) | Redis (운영은 Upstash) — Redis 프로토콜(RESP2)을 직접 구현 (`server/redis.mjs`) | 패키지 없이. 기본 명령만 쓰므로 어느 Redis 에도 주소만 바꿔 붙는다 (11-6, `D-29` · `D-30`) |
| 화면 ↔ 서버 공유 코드 | `app/core/validate.js`, `app/core/serialize.js` 를 브라우저와 서버가 같이 import | 검증 · 저장 형식이 어긋나지 않게 |
| 데이터 | `data/*.json` (순수 JSON) | git diff, 서버 · 화면 모두 그대로 읽음 |
| 설정 · 세션 · 점수판 | `state/*.json` 파일 (로컬 서버가 저장) + 브라우저 `localStorage` 임시 사본 | 브라우저를 바꾸거나 서버를 다시 켜도 유지 (R-28, 6장) |
| 진행자 실시간 | Server-Sent Events | 단방향 push 로 충분, 라이브러리 불필요 |
| 이미지 축소 | 브라우저 Canvas (`createImageBitmap` + `canvas.toBlob`) → 서버로 업로드 | 서버에 이미지 라이브러리 불필요 |
| 룰렛 · 애니메이션 | Canvas 2D 또는 SVG + CSS | 라이브러리 불필요 |

## 4. 로컬 서버 (R-18)

### 4-1. 원칙
- 서버는 **파일을 쓰는 유일한 통로**다. 화면(브라우저)은 파일 시스템에 직접 접근하지 않는다.
- `127.0.0.1` 에만 열어 같은 노트북에서만 접속된다 (R-30).
- 현장 상태(팀 설정 · 진행 기록 · 점수판)는 서버가 **`state/` 폴더의 파일로 저장**한다 (R-28, 6장). 메모리에는 PIN, 진행자 토큰, 진행자용 현재 상태 1개만 둔다. Redis 저장소(서버 여러 개 — 11-6)면 `state/` 도, 진행자용 현재 상태 · 연결된 창 · 실패 잠금도 Redis 에 둔다.
- 페이지는 셋이다: 게임 화면 `/`, 진행자 화면 `/host`, 관리 페이지 `/admin` (R-31). 모두 별도 창으로 연다. 행사 뒤 공개 모드 `/play` 가 더해졌다 (R-96 — 관리 페이지에서 켰을 때만 데이터를 준다, 11-8).

### 4-2. 정적 파일

| 경로 | 내용 | 캐시 |
| --- | --- | --- |
| `/` , `/index.html` | 게임 화면 | `no-cache` |
| `/host` | 진행자 페이지 (`host.html`) | `no-store` |
| `/admin` | 관리 페이지 (`admin.html`) — 페이지 자체는 PIN 없이 열리고 첫 화면이 PIN 입력. 데이터는 PIN 헤더가 맞을 때만 관리 API 로 받는다 | `no-store` |
| `/play` | 공개 모드 (`play.html`, R-96) — 페이지는 언제나 열리고, 데이터는 `GET /api/public` 이 켜져 있을 때만 준다 (11-8) | `no-cache` |
| `/app/**` | 화면 코드 · 스타일 | `no-cache` |
| `/data/app.json`, `/data/scoreboard.json`, `/data/games/*.json` | 데이터 | `no-store` (관리 페이지 저장 · 백업 올리기 후 새로고침하면 바로 반영) |
| `/assets/**` | 이미지 | `private, no-cache` + `ETag`(크기 · 저장 시각) — 바뀌지 않았으면 304 로 다시 받지 않는다 (R-51 — 무료 전송량). `HEAD`(게임 홈의 없는 이미지 확인 — 7-1)는 있는지 · 크기 · ETag 만 — 이미지 본문을 저장소에서 읽지 않는다 (R-55). **Redis 저장소(운영)는 이미지가 모두 Blob 이라(R-67 · DEP-27, 11-7) 로그인 확인 뒤 `GET` 을 302 로 Blob 주소에** (`private, no-cache` — 바이트는 Blob CDN 에서). 위의 ETag · 304 는 파일 저장소(노트북 · 저장 폴더) 이미지 |
| `/docs/manual.md`, `/docs/templates/emoji-quiz-template.tsv` | 진행자 설명서 (앱 안 설명서의 링크 — R-51) · 이모티콘 템플릿 | `no-cache` |
| 그 밖 (`/server`, `/docs` 의 나머지, `/.git`, `/data/.backup`, `/state`, 점으로 시작하는 경로, `..` 포함 경로) | 제공 안 함 — 상태 파일은 4-3 의 상태 API 로만 읽는다 | 404 |

### 4-3. 관리 · 상태 API (노트북 모드는 노트북 안에서만, 서버 모드는 로그인 — 11-2)

### 4-5. 서버 보안 규칙

| 항목 | 규칙 |
| --- | --- |
| 접속 범위 | `127.0.0.1` 에만 연다 — 노트북 밖에서는 접속할 수 없다 |
| Host 헤더 | `127.0.0.1:1029` · `localhost:1029` 만 허용. `localhost` 로 들어오면 `127.0.0.1` 로 이동 (브라우저 저장소를 하나로 유지) |
| 쓰기 요청 | `PUT` · `POST` · `DELETE`(이미지 지우기 — R-68) 는 `X-Camp-App: 1` 헤더 필수, `Origin` 이 요청한 주소 자신일 것 → 다른 웹사이트가 몰래 저장 · 삭제 요청을 보내는 것 차단 |
| 경로 조립 | id · 파일명은 슬러그 · 확장자 허용 목록으로 검사한 뒤 **서버가 경로를 조립**. 최종 경로가 프로젝트 폴더 안인지 한 번 더 확인 |
| 크기 제한 | JSON 본문 2MB, 이미지 15MB, 진행 상태 보고 16KB, 상태 파일 256KB, 백업 올리기 300MB (파일 하나는 이미지 15MB · JSON 2MB · 상태 256KB) |
| 삭제 | 파일 삭제 API 는 쓰지 않는 이미지 지우기 하나뿐 (R-68 — 사람이 관리 페이지에서 한 장씩, 문제가 쓰는 이미지는 서버가 거부 · [04-admin.md](04-admin.md) 3-14). 그 밖에 서버가 지우는 것은 자기가 만든 오래된 백업 파일뿐. 상태 "초기화" 는 파일을 지우지 않고 **빈 상태로 덮어쓴다** (직전 내용은 `state/.backup/`) |
| 상태 API | 진행자 화면은 상태 파일에 직접 쓰지 않고 명령으로만 바꾼다 (게임 화면이 적용 후 저장) |
| 진행자 인증 · 조작 | [12-host-view.md](12-host-view.md) 5장 — 조작 명령은 유효한 토큰 + `X-Camp-App` + 같은 출처일 때만, 정해진 명령 목록만 |
| 관리 인증 (`D-9`, R-31) | 관리 페이지(`/admin`)는 진행자 화면과 같은 PIN 을 그 탭의 `sessionStorage` 에만 두고, `/api/admin/*` 요청마다 `X-Admin-Pin` 헤더로 보낸다. 서버는 요청마다 지금 PIN 과 비교 (서버를 다시 켜면 PIN 이 바뀌어 다시 입력). 쿠키를 쓰지 않으므로 진행자 화면 로그인 · 게임 창과 섞이지 않는다. 틀린 PIN 은 진행자 화면과 합쳐 5회 → 60초 잠금 (같은 틀린 PIN 이 여러 요청에 반복되면 1회로 셈) |
| 진행자 인증이 쿠키인 이유 | 진행자 화면은 실시간 갱신에 SSE(`EventSource`)를 쓰는데, 브라우저 `EventSource` 는 요청 헤더를 붙일 수 없다. 그래서 진행자 화면만 PIN 입장 후 `HttpOnly` 쿠키 토큰을 쓴다 ([12-host-view.md](12-host-view.md) 5장) |
| 오류 응답 | 내부 경로 · 스택 정보를 응답에 넣지 않음 (터미널에만 출력) |

### 4-6. 저장 절차 (데이터 파일)
1. 요청 본문을 검증 ([02-data-schema.md](02-data-schema.md) 5장). 오류면 422, 파일 그대로.
2. `If-Match` 리비전과 현재 파일 리비전 비교. 다르면 409 (그 사이 다른 창에서 저장 · 백업 올리기로 바뀜).
3. 직렬화 (키 순서 · 기본값 생략 — 02 문서 2-2). 결과가 현재 파일과 같으면 쓰지 않고 200.
4. 현재 파일을 `data/.backup/<게임 id>-<YYYYMMDD-HHmmss>.json` 으로 복사. 게임별 최근 20개만 유지.
5. 임시 파일(`<파일>.tmp`)에 쓰고 디스크에 확정한 뒤 이름 바꾸기 → 중간에 꺼져도 깨진 파일이 남지 않는다.
6. 게임별로 한 번에 하나의 저장만 처리 (동시 요청은 줄 세움). 서버가 여럿이면(Redis 저장소) 잠금 키로 서버끼리도 줄 세운다 (11-6).
- 이미지 저장도 임시 파일 → 이름 바꾸기. 같은 이름이 있으면 덮어씀 (문제 이미지 교체).

### 4-6-1. 저장 절차 (상태 파일, R-28)
1. 게임 화면이 상태를 바꾸면 300ms 묶어서 `PUT /api/state/...` (마지막으로 받은 리비전을 `If-Match` 로).
2. 서버가 형식 검사(버전 · 필수 필드 · 크기) → 리비전 비교. 다르면 409 → 게임 화면은 파일의 최신 상태를 다시 읽고 토스트 "다른 창에서 바뀐 내용을 불러왔습니다" (게임 창을 두 개 띄웠을 때만 생김).
3. `settings.json` · `scoreboard.json` 은 쓰기 전에 직전 내용을 `state/.backup/<이름>-<YYYYMMDD-HHmmss>.json` 으로 복사 (파일별 최근 30개). 진행 기록(`sessions/*`)은 자주 바뀌고 안에 이력이 있어 백업하지 않는다.
4. 임시 파일 → 디스크 확정 → 이름 바꾸기 (데이터 파일과 같은 원자적 쓰기). 파일별로 한 번에 하나씩.
5. 쓰고 나면 서버가 게임 창에 `reload` `{ kind: "state", name, revision }` 을 보낸다 (4-4). 쓴 창은 자기 리비전이라 무시하고, 다른 창(관리 페이지의 점수 입력 등)이 쓴 것이면 게임 창이 다시 읽는다.
- 직렬화는 데이터 파일과 같은 규칙(02 문서 2-2 — 들여쓰기 2칸 · LF · 키 순서 고정 · `\u` 이스케이프 없음)을 쓴다. git 에는 올리지 않지만(R-37) 백업 파일을 풀어 비교할 때 읽기 쉽다.
- 상태 파일 형식은 [03-settings.md](03-settings.md) 5장 (설정), [07-state-model.md](07-state-model.md) 3장 (진행 기록), [13-scoreboard.md](13-scoreboard.md) 9-1 (점수판) 과 같다 — 브라우저 저장소에 쓰던 내용을 그대로 파일로.

### 4-7. 서버가 멈췄을 때 (비상 대안)

| 상황 | 영향 · 대응 |
| --- | --- |
| 게임 도중 서버가 꺼짐 | 열린 게임 화면은 계속 진행 가능 — 게임 시작 때 **이번 게임 후보 카테고리 이미지를 모두 미리 불러오기** 때문. 화면 구석에 "서버 연결 끊김 · 저장 대기 n건" 작게 표시, 진행자 화면은 갱신 멈춤. 그동안 바뀐 상태는 **브라우저 임시 사본**에 쌓아 두었다가, `start.command` 로 다시 켜면 자동 재연결 후 파일로 올린다 (6장) |
| 서버를 아예 켤 수 없음 | 터미널에서 `python3 -m http.server 1029 --bind 127.0.0.1` 로 **읽기 전용 진행**. 상태는 브라우저 임시 사본으로만 이어지고 파일에는 저장되지 않는다 (서버를 다시 켜면 그때 올림). 관리 페이지 · 진행자 화면은 안 됨 (PIN 을 확인할 서버가 없음) |

## 5. 데이터 원본 · git (R-14, R-37)

### 5-1. 원본은 서버 저장 폴더 (R-37, `D-22`)

- 운영은 서버 모드(11장)다. 문제 · 이미지 · 현장 상태의 **원본은 서버 저장소** — Redis(11-6, Node 서버 하나로 켤 때는 저장 폴더 — 11-3). 모두 서버 주소의 관리 페이지 · 게임 화면에서 고친다.
- git 저장소에는 **코드 · 문서 · 초기 데이터**만 둔다. `data/` · `assets/` 는 서버가 빈 저장소로 처음 켤 때 넣는 값(`CAMP_SEED` — 11-6)이자 노트북 모드(비상용)의 시작 값이다. **현장 상태(`state/`)는 git 에 올리지 않는다** (예전 `D-19` 를 바꿈).
- 서버 ↔ 노트북으로 옮기거나 행사 결과를 보관할 때는 관리 페이지 **[백업 내려받기] · [백업 올리기]** ([04-admin.md](04-admin.md) 3-11).

| 어디에 | 무엇 | 역할 |
| --- | --- | --- |
| 서버 저장소 (Redis) | `data/` · `assets/` · `state/` + 자동 백업(`.backup/`) | **원본**. 잘못 저장 · 초기화에 대비해 백업 파일을 받아 둔다 |
| 백업 파일 (`camp-game-<시각>.tar`) | 내려받은 그 시점의 `data/` · `assets/` · `state/` | 노트북 모드로 옮기기, 행사 결과 보관 (팀 드라이브 등) |
| git 저장소 | 코드 · 문서 · 초기 데이터(`data/` · `assets/`) | 배포 · 서버 첫 시작 · 노트북 모드 시작 값 |
| 브라우저 | 현장 상태 임시 사본 | 서버가 잠깐 끊겼을 때 (6장) |

### 5-2. 저장소
- 비공개 GitHub 저장소 (`D-13`). Vercel 로 옮기며 외부 비공개 저장소로 — 이전 운영 환경 설정을 뺀 `vercel` 브랜치를 새 이력으로 (`D-30`).
- 사진은 내부 행사용이므로 **비공개 유지**.

### 5-3. `.gitignore` (이 앱과 관련된 줄)

```
.DS_Store
data/.backup/
state/
*.tmp
node_modules/
.claude/
.camp-secret
```

- `state/` 는 통째로 올리지 않는다 (R-37). 노트북 모드로 켜면 저장소 폴더 안에 생기지만 git 에는 보이지 않는다.
- `data/.backup/` (관리 페이지 저장 전 백업), `.camp-secret` (서버 모드 서명 키 — 11-2) 도 올리지 않는다.

### 5-4. 초기 데이터를 고치고 싶을 때 (선택)

초기 데이터는 서버 저장소가 비어 있을 때만 쓰이므로 꼭 맞출 필요는 없다. 서버에서 고친 문제를 저장소에도 남기고 싶으면:

1. 서버 관리 페이지 → [백업 내려받기]
2. 받은 파일을 풀어(`tar xf camp-game-<시각>.tar`) `data/` · `assets/` 를 저장소 폴더에 덮어쓴다 (`state/` 는 `.gitignore` 라 섞이지 않는다)
3. `git add data assets` → 커밋 · 푸시

### 5-5. 노트북 모드로 바꿔 진행할 때 · 되돌릴 때

| 상황 | 방법 |
| --- | --- |
| 서버를 쓸 수 없어 노트북으로 진행 | 미리 받아 둔 백업 파일(행사 전날 · 리허설 뒤 — 10-schedule)이 있으면 노트북 관리 페이지 [백업 올리기], 없으면 저장소 초기 데이터 그대로. 팀 설정은 게임 화면에서 다시 |
| 노트북에서 고친 내용을 서버로 | 노트북 관리 페이지 [백업 내려받기] → 서버 관리 페이지 [백업 올리기] |
| 문제를 두 곳(서버 · 노트북)에서 따로 고침 | 합치지 않는다 — 한쪽을 원본으로 정하고 다른 쪽 수정은 관리 페이지로 다시 넣는다 |

- 여러 사람이 한 서버의 관리 페이지에서 고치므로 git 충돌은 생기지 않는다. 같은 게임 데이터를 두 창에서 거의 동시에 저장하면 늦은 쪽이 "파일이 다른 곳에서 바뀌었습니다"(409) — 새로고침 후 다시 저장 ([04-admin.md](04-admin.md) 5장).
- 문제 id 가 무작위 4자리라(02 문서 3-5) 서버 · 노트북에서 각각 추가한 문제 · 이미지 파일 이름은 겹치지 않는다.

## 6. 현장 상태 저장 — 파일이 원본, 브라우저는 임시 사본 (R-28)

| 상태 | 파일 (원본) | 브라우저 임시 사본 (localStorage 키) | 형식 문서 |
| --- | --- | --- | --- |
| 설정 (팀 · 표시 · 게임별 옵션) | `state/settings.json` | `camp-game:settings:v1` | [03-settings.md](03-settings.md) 5장 |
| 게임별 진행 기록 | `state/sessions/<게임 id>.json` | `camp-game:session:v1:<게임 id>` | [07-state-model.md](07-state-model.md) 3장 |
| 마지막 화면 위치 (이어하기 문구) | `state/route.json` | `camp-game:route:v1` | [07-state-model.md](07-state-model.md) 2장 |
| 배점 · 라운드 설정 변경분 + 종합 점수판 입력값 | `state/scoreboard.json` | `camp-game:scoreboard:v1` | [13-scoreboard.md](13-scoreboard.md) 9-1 |

### 6-1. 읽기 (앱 시작 시)
1. `GET /api/state` 로 파일을 읽는다 → 이것이 원본.
2. 파일이 없고 브라우저 사본만 있으면 (예: 이 기능 이전에 쓰던 기록, 서버가 꺼진 동안 생긴 기록) 사본을 파일로 올린다 → 토스트 "브라우저에 있던 기록을 파일로 옮겼습니다".
3. 파일과 사본이 둘 다 있고 사본이 더 최신(`updatedAt`)이며 아직 못 올린 변경이면 → 사본을 올린다 (서버가 꺼진 동안 진행한 내용). 그 밖에는 파일이 이긴다.

### 6-2. 쓰기
- 상태가 바뀌면 **브라우저 사본에 즉시** 쓰고, **파일에는 300ms 묶어서** 쓴다 (4-6-1).
- 서버에 못 쓰면(꺼짐 · 오류) "저장 대기" 로 쌓아 두고 5초마다 다시 시도. 재연결되면 순서대로 올린다.
- 제목 화면 · 구석 표시: 정상 "● 파일 저장" / 대기 중 "○ 저장 대기 n건 (서버 연결 끊김)".

### 6-3. 그 밖
- 브라우저 저장소는 **주소별**로 나뉜다. 항상 `http://127.0.0.1:1029` 로 접속한다 (`start.command` 가 이 주소로 열고, 서버는 `localhost` 접속을 이 주소로 돌린다). 원본이 파일이라 다른 브라우저(Chrome ↔ Safari)로 열어도 같은 상태가 보인다.
- 브라우저 저장소 접근이 막혀도(사생활 보호 창 등) 파일 저장으로 정상 동작한다.
- 상태 파일에는 PIN · 진행자 토큰을 넣지 않는다 (백업 파일로 내려받아 팀 드라이브 등에 보관한다 — 5-1).

## 7. 이미지 처리

### 7-1. 미리 불러오기 (게임 진행)
- **게임 시작 시: 이번 게임 후보 카테고리의 이미지(`image` · `answerImage`)를 모두 백그라운드로 불러온다** (`new Image()` + `decode()`). 서버가 중간에 멈춰도 진행할 수 있게 하기 위함 (4-7).
- 게임 홈 진입 시: 후보 카테고리 이미지가 있는지 확인 → 없는 이미지가 있으면 "⚠ 이미지 2개를 찾을 수 없습니다" (W02). 운영(Redis 저장소)은 **이미지 주소 표(R-70)에 있는지로 — 요청 없이**, 노트북 모드는 `HEAD`.
- **이미지 주소 (R-70)**: 운영은 화면이 `GET /api/assets` 로 받은 표의 **Blob 주소를 `<img>` 에 바로** 쓴다 (`app/core/assets.js` `assetUrl`) — 이미지마다 서버 함수 · Redis 를 거치지 않고, 캐시는 Blob CDN · 브라우저(1달)가 한다. 표에 없거나 표를 못 받았으면 `/assets/…` (서버가 302 로 안내 — 4-2).
- **한 번에 4장씩** (R-55): 미리 받기 · 없는 이미지 확인은 같은 줄에 서서 동시에 4개까지만 요청한다. 141장을 한꺼번에 보내면 Vercel 이 함수 인스턴스를 약 90개 새로 띄우고 인스턴스마다 저장소 점검을 했다 (10/15 실제 환경 — 로그 "함수 시작" 92줄, Upstash 연결 102개, 한 번에 약 2,000 명령). 실패한 이미지도 자리를 비운다.

### 7-2. 사진 표시 · 연출 구현 (`photo`)
- 메인 영역 = 고정 크기 컨테이너 (`overflow: hidden`). 이미지는 `object-fit: contain` 과 같은 규칙으로 **표시 상자(이미지가 실제로 그려지는 사각형)** 를 계산해 그 크기의 래퍼 안에 그린다.
- 확대: 래퍼에 `transform: scale(s)` + `transform-origin`. 가장자리 보정 — 배율 `s` 에서 보이는 영역이 이미지 밖으로 나가지 않도록 `focus` 를 `[50/s, 100 − 50/s]` % 범위로 제한. 전환 `transform 0.6s ease-out`.
- 가림: 같은 래퍼 위에 `position: absolute` 상자를 `[x, y, w, h]` % 로 배치 → 화면 크기 · 이미지 비율이 달라도 같은 자리를 가린다. 제거 시 0.4초 페이드.
- 정답 이미지: 정답 공개 때 두 번째 `<img>` 로 교차 페이드 (미리 불러온 상태).

### 7-3. 어드민 이미지 저장
- 브라우저에서 축소 후 `PUT /api/admin/assets/...` 로 업로드 — 긴 변 2400px 또는 4MB 를 넘으면 줄여서 JPEG 0.9, **500KB 넘는 PNG · JPEG 는 JPEG 0.85 로 다시 저장** (`D-35` — 투명한 PNG · gif 는 그대로, 다시 저장해도 작아지지 않으면 원본), EXIF 방향 반영. 정하는 규칙은 `shrinkPlan`(`app/admin/image.js`, 화면 없이 테스트). 상세는 [04-admin.md](04-admin.md) 4장.

| 상태 파일 저장 실패 (서버 꺼짐 · 디스크 · 권한) | 브라우저 사본으로 계속 진행 + "저장 대기 n건" 표시, 5초마다 재시도 (6-2) |
| `localStorage` 실패 | 파일 저장만으로 정상 동작 (6-3). 서버까지 꺼지면 메모리로만 진행 + 경고 |
| 서버 연결 끊김 (게임 화면) | 진행 계속 (4-7), 구석에 작은 경고. 진행자 상태 보고는 재연결 후 다시 보냄 |
| 서버 연결 끊김 (관리 페이지) | "서버에 연결할 수 없습니다 — start.command 로 서버를 켜세요". 저장 버튼 비활성 |
| 서버가 꺼진 채 ☰ → 관리 · 진행자 화면 | 창을 열지 않고 토스트 "서버에 연결할 수 없습니다 — start.command 로 서버를 켜세요" (`GET /api/health` 로 먼저 확인) |
| 저장 409 | "파일이 다른 곳에서 바뀌었습니다. [다시 불러오기] 후 편집하세요" |

| 관리 API 401 (PIN 이 바뀜 — 서버 재시작 등) | 편집 내용 유지 + PIN 입력 창 → 맞으면 하던 요청 다시 보냄 ([04-admin.md](04-admin.md) 2-1) |
| 전체화면 실패 | 토스트 "브라우저 메뉴에서 전체화면으로 전환하세요" |
| 예기치 못한 스크립트 오류 | `window.onerror` → 토스트 "오류가 발생했습니다 — 새로고침하면 이어서 진행할 수 있습니다" |

### 11-1. 설정값 (환경 변수)

| 이름 | 기본 | 설명 |
| --- | --- | --- |
| `CAMP_PUBLIC_ORIGIN` | 없음 | 서버 모드의 공개 주소 (`https://…`, 끝 `/` 없이). 있으면 서버 모드. 도메인이 여럿이면 쉼표로 — Host · Origin 검사는 모두 통과, 로그에는 첫 번째를 대표로 (나머지는 "다른 주소"). 로그인 쿠키는 도메인마다 따로. Vercel 운영 배포에서는 넣지 않아도 된다 — 아래 시스템 환경 변수 뒤에 더할 주소 |
| `VERCEL_PROJECT_PRODUCTION_URL` · `VERCEL_URL` · `VERCEL_BRANCH_URL` | Vercel 이 넣음 | **Vercel 운영 배포(`VERCEL=1` · `VERCEL_ENV=production`)에서만** 이 순서로 공개 주소에 넣는다 (`https://` 를 붙여서, R-63) — 운영 도메인(가장 짧은 커스텀 도메인, 없으면 vercel.app — 대표) · 배포별 주소 · 브랜치 주소. 그 뒤에 `CAMP_PUBLIC_ORIGIN`(겹치면 하나). 미리보기 · 개발 배포와 Vercel 밖에서는 읽지 않는다 — 운영 도메인 변수가 미리보기에도 들어와, 읽으면 미리보기가 운영 Redis 에 쓴다 (11-5). 프로젝트 설정 "Enable access to System Environment Variables" 가 켜져 있어야 한다 |
| `CAMP_PIN` | 없음 | 6자리 숫자. 서버 모드에서 없거나 형식이 틀리면 시작하지 않는다 |
| `CAMP_DATA_DIR` | 저장소 폴더 | `data/` · `assets/` · `state/` 를 둘 곳 (Redis 없이 켤 때 — 볼륨 경로). 코드 폴더와 다르면 시작할 때 저장 폴더 점검 (11-3) |
| `CAMP_HOST` | 노트북 `127.0.0.1` · 서버 `0.0.0.0` | 받을 주소 (Node 서버로 켤 때) |
| `CAMP_PORT` | `1029` | 받을 포트 (Node 서버로 켤 때) |
| `CAMP_REDIS_URL` | 없음 (Vercel 은 `REDIS_URL` → `KV_URL`) | 있으면 저장 폴더 대신 **Redis 저장소** (11-6) — `redis://호스트:포트` (TLS 는 `rediss://`). 서버 모드에서만. Vercel 에서 없으면 Upstash 연결이 넣어 주는 `REDIS_URL` → `KV_URL`(비밀번호가 든 `rediss://`)을 읽는다 — Vercel 밖에서는 다른 용도의 `REDIS_URL` 을 집지 않게 읽지 않는다 (R-51) |
| `CAMP_REDIS_PASSWORD` | 없음 | Redis 비밀번호 — 주소에 비밀번호가 들어 있으면(Upstash 연결) 필요 없다. 배포 환경의 비밀 값으로 — 로그 · 저장소 파일에 적지 않는다 |
| `CAMP_REDIS_PREFIX` | `camp-game:` | 이 앱의 키 접두어 — 저장소를 다른 용도와 같이 써도 되게 모든 키가 이것으로 시작한다. 다른 접두어의 키는 읽지도 지우지도 않는다 (`:` 로 끝나게 붙임) |
| `BLOB_READ_WRITE_TOKEN` | Vercel 이 넣음 (Blob 저장소 연결) | Redis 저장소는 **이미지를 Blob 공개 저장소에만** 둔다 (R-67 · DEP-27, 11-7 — Vercel 밖 Redis 서버도) — 이 토큰이 없으면 이미지 저장이 503 (Redis 에 넣지 않음). 비밀 값 — 로그에 찍지 않는다 |
| `CAMP_SEED` | 없음 | `1` 이면 Redis 저장소가 비어 있을 때 코드 폴더의 `data/` · `assets/` 를 넣는다 — **처음 한 번만** 켜고 뺀다 (11-6) |
| `CAMP_STREAM_MAX_S` | 없음 (Vercel 함수는 270) | 실시간 연결(SSE)을 서버가 먼저 끊고 다시 붙게 할 시간(초) — 실행 시간 상한이 있는 곳용 (11-4) |

### 11-2. 잠금 (서버 모드)

- 공개 주소라 주소를 아는 사람은 누구나 닿는다 (참가자 포함) — 정답이 담긴 것은 모두 로그인 뒤로 둔다. PIN 이 유일한 잠금이다.
- 게임 화면 · 진행자 화면 · 관리 페이지 모두 **같은 PIN** 으로 들어온다. 로그인하면 `HttpOnly; Secure; SameSite=Strict` 쿠키를 준다.
  - 쿠키는 서명 키(처음 켤 때 저장소에 만드는 무작위 값 `.camp-secret`)와 PIN 으로 서명해 서버가 다시 떠도 유지된다 (7일). PIN 을 바꾸면 모두 다시 로그인한다. [나가기] 한 쿠키는 다시 쓸 수 없다 (Redis 면 쿠키 만료까지, 저장 폴더면 그 서버가 켜져 있는 동안). 서명 키는 정적 파일로 나가지 않고 백업에도 넣지 않는다.
  - 관리 페이지는 지금처럼 요청마다 PIN 헤더를 보내고, PIN 확인 때 같은 쿠키도 받아 이미지를 볼 수 있다.
- 로그인 없이 열리는 것: 화면 껍데기(`/` · `/host` · `/admin` · `/play` · `/app/**`), `/api/health`, `/api/session`(로그인 필요 여부), 이모티콘 템플릿, 진행자 설명서(`/docs/manual.md` — 앱 안 요약 설명서의 링크, R-51). **공개 모드(R-96)를 켜 두면** `GET /api/public`(숨기지 않은 문제 · 정답)과 그 문제들이 쓰는 `/assets/…` 이미지도 (11-8) — 꺼져 있으면 `/api/public` 은 제목만.
- 로그인이 필요한 것: `/data/**`, `/assets/**`(공개 모드의 위 이미지 말고), `/api/assets`, `/api/state*`, `/api/live*`, `/api/host/*` (없으면 401). 게임 화면은 401 이면 PIN 입력 화면을 띄운다. 공개 모드를 켜도 그대로다.
- PIN 실패 잠금(5회 → 60초)은 **접속한 곳(IP)별로** 센다. 입구(프록시 · 배포 환경) 뒤라 `X-Forwarded-For` 의 **마지막** 주소(입구가 붙인 것 — 앞쪽은 접속한 쪽이 꾸밀 수 있다)를 쓴다 — 누가 틀려도 다른 진행자는 막히지 않는다. 입구를 거치지 않는 경로로 마지막 주소까지 꾸미는 경우에 대비해 **서버 전체 상한**(10분에 100회 실패 → 5분 동안 모두 잠금)을 함께 둔다. (노트북 모드는 모두 `127.0.0.1` 이라 지금과 같다.)
- Host · Origin 검사는 공개 주소도 허용한다. `/api/health` 는 배포 환경의 상태 확인용이라 Host 검사 없이 답한다 (내용은 앱 이름 · 버전뿐).

### 11-3. 저장 — 저장 폴더 (Redis 없이 Node 서버 하나로 켤 때, R-37)

- 저장 폴더는 서버의 볼륨(`CAMP_DATA_DIR`)이다. Vercel 에는 계속 남는 디스크가 없어 Redis(11-6)를 쓴다.
- 볼륨은 디스크 하나다 — **관리 페이지 [백업 내려받기] 로 리허설 뒤 · 행사 전날 · 끝난 뒤 백업을 받아 둔다** (5-1, [16-deploy.md](16-deploy.md) 4장).
- 서버 1개. 실시간 상태(게임 화면 ↔ 진행자 화면)를 메모리에 두므로 서버를 늘리지 않는다 — 늘리려면 Redis 저장소(11-6).
- 처음 켤 때 저장 폴더에 `data/` · `assets/` · `state/` 가 없으면 만든다 — `data/` · `assets/` 는 코드 폴더의 초기 데이터를 복사, `state/` 는 빈 폴더 (폴더별로, 백업 · 숨김 파일은 빼고). 이후 새 버전을 올려도 **저장 폴더 내용은 그대로** — 고치는 곳은 관리 페이지 · 게임 화면, 통째로 바꿀 때는 [백업 올리기].
- 백업 폴더(`data/.backup` · `state/.backup`)도 저장 폴더에 쌓인다.
- **시작할 때 저장 폴더 점검** (코드 폴더와 저장 폴더가 다를 때): 점검용 파일을 만들고 → 이름 바꾸기로 덮어쓰고 → 읽고 → 지운다. 로그에 `저장 폴더 점검 ✔` 를 남기고, 안 되면 `저장 폴더에 쓸 수 없습니다 — <원인>` 을 남기고 시작하지 않는다 (마운트 · 권한 문제를 첫 저장 때가 아니라 배포 때 알 수 있게).

### 11-4. 실시간 연결

- 진행자 화면 · 게임 화면의 SSE 는 입구(프록시 · 로드밸런서)의 유휴 시간 제한에 걸리지 않도록 15초마다 신호를 보낸다. `X-Accel-Buffering: no` 도 그대로 보낸다 (nginx 계열 프록시 대비).
- 끊기면 브라우저가 2초 뒤 다시 붙는다 (`retry: 2000`).
- **실행 시간 상한 대응** (R-51 · DEP-17): Vercel 은 함수가 300초(무료)를 넘으면 끊는다. 그래서 `CAMP_STREAM_MAX_S`(Vercel 함수는 270초)가 지나면 서버가 먼저 `retry: 300` 과 `bye` 를 보내고 닫는다. 브라우저는 0.3초 뒤 다시 붙고, 화면은 끊김으로 보이지 않는다 — 게임 화면 "연결 끊김" · 진행자 화면 "○ 재연결 중" 이 뜨지 않는다.
- 서버가 먼저 끊은 연결은 **연결 표시를 지우지 않는다** — 진행자 화면에서 게임 화면이 끊긴 것으로 보이지 않고 명령도 그대로 받으며, 진행자 수가 0 이 되지 않는다 (0 이면 게임 화면에 점수판 채우기 창이 뜬다). 진행자 화면은 탭마다 같은 id 로 다시 붙어 한 명으로 센다. 다시 붙지 않으면 45초 뒤 지운다.
- **닫은 화면 바로 지우기** (R-51 · DEP-21): Vercel 은 브라우저가 닫은 연결을 함수에 알려 주지 않는다 — 함수는 15초 신호 쓰기가 성공한다고 보고 연결 표시를 계속 갱신해, 닫힌 화면이 서버가 먼저 끊을 때(270초)와 만료(45초)까지 최대 5분 남는다 (10/14 실제 환경에서 확인). 그래서 게임 화면 · 진행자 화면은 창을 닫거나 새로고침할 때(`pagehide`) `POST /api/live/leave` 를 보내고(`keepalive`), 서버는 연결 표시를 바로 지운다 — 게임 화면은 새로고침마다 창 id 가 바뀌므로, 이게 없으면 "다른 창 열기 막기" 를 켠 채 새로고침한 창이 최대 5분 막힌다. 브라우저가 알릴 틈 없이 끊기면(휴대폰 잠김 · 네트워크) 그대로 최대 5분 남는다. 뒤로 가기 캐시에서 돌아오면 다시 붙는다.
- **끊긴 사이의 알림**: 게임 화면에 보내는 알림에는 번호(SSE `id`)를 붙인다 (`hello` 에는 지금 번호). 다시 붙을 때 브라우저가 마지막 번호를 보내면(`Last-Event-ID`, 새로 연 연결은 `?last=`) 그 뒤의 명령 · 다시 읽기 · 닫기(다른 창이 넘겨받음)를 다시 보낸다. 15초가 지난 것은 버린다 (오래된 버튼이 늦게 실행되지 않게). 서버가 여럿이면 번호와 도착 순서가 조금 다를 수 있어 명령은 앞쪽 20개도 다시 보고, 게임 화면은 명령 id 로 한 번만 실행한다.
- 업로드 크기(백업 올리기 300MB)는 서버가 막는다. Vercel 은 요청 4.5MB 상한이 따로 있다 — DEP-18.
- **연결 끊김 비콘** (R-66): 게임 화면 "○ 저장 대기 n건 (서버 연결 끊김)" · 진행자 화면 "○ 재연결 중" · 관리 페이지 "○ 서버 연결 안 됨" 이 **뜨는 순간**(연결됨 → 끊김) 그 화면이 `GET /api/health` 를 한 번 보내 응답 시간을 잰다 — 전체 · DNS · 연결(TLS 포함) · 요청→첫 응답 (Resource Timing, 30초까지 기다림). 그 값과 뜬 시각 · 이유(실시간 연결 오류 · 상태 저장 실패 · 서버 확인 실패 · 요청 실패) · 창 id · 화면이 가려졌는지 · 기기 오프라인인지를 `POST /api/live/beacon`(로그인 필요 — 11-2, `keepalive`)으로 보내고, 서버는 로그 한 줄 "⚠ <서버 시각> 연결 끊김 — 게임 화면 g-xxxx · 실시간 연결 오류 · 화면 <뜬 시각> · 응답 2,904ms (DNS 0 · 연결 0 · 요청→첫 응답 2,902) · 도착 2.1초 뒤 · 화면 가려짐 <IP>". 네트워크 오류로 못 보내면 들고 있다가(5개까지) 다시 붙을 때 보낸다 — 뜬 시각은 그대로라 "도착 n초 뒤" 가 끊겨 있던 시간이다. 한 화면에서 10초에 한 번까지. 서버는 정해진 이름 · 숫자만 받는다(모르는 화면 · 이유는 400, 이상한 값은 버림). 화면 시각은 그 기기 시계라 몇 초 어긋날 수 있다. **읽는 법**: 응답이 길고 "요청→첫 응답" 이 대부분이면 이미 맺은 연결에서 네트워크가 멈춘 것, "연결" 이 길면 새 연결이 늦은 것, 응답이 짧은데 끊김이 떴으면 그 순간만 끊긴 것 (10/27 조사 — 15-qa 35장)

### 11-5. 배포 — Vercel (R-51 · DEP-15)

- 이전 운영 환경의 매니페스트 · 컨테이너 이미지 빌드는 R-51 로 뺐다.
- `api/index.js` 가 Vercel 함수 진입점이다. `vercel.json` 이 **모든 경로를 이 함수로** 보낸다. 앱은 첫 요청 때 한 번 만들고(저장소 점검 · 서명 키 — 11-6, 점검은 짧게 — R-55) 인스턴스가 살아 있는 동안 다시 쓴다. 서버 시작은 `createApp`(요청 처리기)과 `createAppServer`(포트 열기 — 노트북 · Node 서버)로 나뉘어 있어 두 방식이 같은 코드를 쓴다. 환경 변수 읽기도 공용(`server/config.mjs`).
- **공개 파일 막기**: Vercel 이 그대로 내주는 폴더는 `public/`(robots.txt 하나)뿐이다. 화면 코드 · 설명서 · 템플릿 · 초기 데이터(`CAMP_SEED`)는 `includeFiles` 로 함수 안에만 넣고, 서버가 4-2 규칙대로 내준다 — 정답이 든 `data/` 는 로그인 뒤 저장소(Redis)에서만, `docs/` 의 나머지 · `state/` · 코드는 404. `.vercelignore` 는 로컬 설정 · 현장 상태 · 백업 · 서명 키를 올리지 않는다.
- 설정이 없거나 틀리면(서버 모드가 아님 · Vercel 인데 Redis 주소 없음 · Upstash REST 주소만 있음 · 형식 오류) 요청에 503 "서버를 시작하지 못했습니다 — <빠진 설정>" 을 주고 로그에도 남긴다 — 응답에는 변수 이름만(값 없음). 저장소 접속 실패는 주소가 드러나지 않게 로그에만. 다음 요청 때 다시 시도한다.
- **공개 주소는 Vercel 이 알려 준다** (R-63): 운영 배포는 시스템 환경 변수(`VERCEL_PROJECT_PRODUCTION_URL` · `VERCEL_URL` · `VERCEL_BRANCH_URL` — 11-1)로 공개 주소를 만든다 — 도메인을 붙이거나 바꾸면 다시 배포만 하면 된다. 시작 로그 "✔ 캠프 게임 함수 시작 — 대표 주소 … · 다른 주소 …". **미리보기 배포는 켜지 않는다** — 503 "미리보기 배포(preview)는 쓰지 않습니다" (운영 Redis 를 지킴. 미리보기에 `CAMP_PUBLIC_ORIGIN` 을 넣으면 예전처럼 켜진다 — 넣지 않는다).
- **시각은 한국 시간**: Vercel 은 UTC 로 돌고 시간대(`TZ`)를 바꿀 수 없다 — 백업 파일 이름(`camp-game-<YYYYMMDD-HHmmss>.tar`, 게임 · 상태 백업) · 백업 목록의 시각 · 서버 로그의 시각은 프로세스 시간대와 상관없이 `Asia/Seoul` 로 만든다 (`server/files.mjs` `stamp` · `clock`). 데이터 안의 ISO 시각(`…Z`)은 그대로. 로그 시각은 `17시 32분 18초` 모양(자정 `0시`, 앞자리 0 없음)으로 직접 조립한다 — `toLocaleTimeString('ko-KR')` 은 Node(ICU) 판마다 모양이 달라 쓰지 않는다 (R-101).
- 리전 서울(`icn1`), 실행 시간 상한 300초, 빌드 단계에서 `npm test` (실패하면 배포 안 됨 — Redis 테스트는 `redis-server` 가 없어 건너뜀).
- 절차는 [16-deploy.md](16-deploy.md).

### 11-6. Redis 저장소 — 서버 여러 개 (R-50, `D-29` · `D-30`)

`CAMP_REDIS_URL` 이 있으면 저장 폴더 대신 Redis 에 둔다. 운영은 **외부 Redis — Upstash 무료 플랜** (`rediss://`, R-51 · `D-30`). 디스크에 쓰는(영속) Redis 를 쓴다 — 메모리에만 두는 Redis 는 서버가 모두 꺼지면 데이터가 사라진다 (`D-29`). 절차는 [16-deploy.md](16-deploy.md).

- **같이 보는 것**: 문제 · 이미지 · 현장 상태 · 백업(`.backup/` · 올리기 전 자동 백업) · 쿠키 서명 키뿐 아니라, 서버 메모리에 두던 것도 — 진행자용 현재 상태, 명령을 받을 게임 화면, 연결된 게임 화면 · 진행자 화면, 다른 창 열기 막기(R-46), PIN 실패 잠금 · [나가기] 한 쿠키. 그래서 서버(Vercel 함수 인스턴스)가 여러 개 떠도 같게 동작한다.
- **키**: 모두 `CAMP_REDIS_PREFIX`(기본 `camp-game:`)로 시작한다 — 저장소를 다른 용도와 같이 써도 다른 키를 건드리지 않는다.

| 키 (접두어 뒤) | 내용 |
| --- | --- |
| `f:<경로>` | 파일 — 첫 줄 머리말(크기 · 시각, 큰 파일이면 조각 묶음 · 조각 수) + 내용. 경로는 저장 폴더와 같다 (`data/games/photo-quiz.json` …). `assets/` 아래 이미지는 언제나 머리말만 `{ s, t, u: Blob 주소 }` — 이미지 본문은 Redis 에 두지도 읽지도 않는다 (R-67 · DEP-27, 11-7) |
| `u` · `u:ok` | 이미지 주소 표 HASH (경로 → Blob 주소, R-70) — 이미지를 올리면 HSET · 지우면 HDEL, `GET /api/assets` 가 HGETALL 한 번. `u:ok` 는 처음 한 번 이미지 머리말로 채웠다는 표시 (R-70 전에 올린 이미지) |
| `c:<묶음>:<번호>` | 400KB 가 넘는 파일의 조각 — 새 내용은 새 묶음에 쓰고 머리말을 바꾼 뒤 옛 묶음을 지운다 (읽는 쪽은 옛것 · 새것 중 하나를 온전히 본다) |
| `d:<폴더>` | 폴더 목록 HASH (이름 → 파일 · 폴더) — KEYS · SCAN 으로 훑지 않는다 (다른 키를 건드리지 않게) |
| `lock:<이름>` | 저장 줄 세우기 — `SET NX EX 15` 로 잡고, 내가 잡은 것인지 확인한 뒤 `DEL` 로 놓는다. 10초 못 잡으면 503 "다른 곳에서 저장하는 중" |
| `live:*` | 진행자용 현재 상태 · 명령 받을 창 · 막기 · 연결된 창(HASH — 게임 화면은 창 id, 진행자 화면은 탭 id, 45초 안에 신호가 없으면 끊긴 것) · 알림(`seq` + `ev:<번호>` — 보낸 시각 포함, 60초. 다시 붙은 게임 화면에 놓친 것을 다시 보낸다 — 11-4) · 알림 구독 채널(`ch`) |
| `auth:*` | PIN 실패 기록(접속한 곳별 · 전체 — 틀린 PIN 은 해시로만) · [나가기] 한 쿠키 (쿠키 만료까지) |
| `check:<무작위>` | Vercel 함수의 짧은 시작 점검 (R-55) — 60초 뒤 저절로 사라진다 |

- **기본 명령만**: `server/redis.mjs` 의 목록(문자열 · HASH · 카운터 · 알림 보내기 `PUBLISH`)만 쓴다 — 다른 명령을 쓰면 바로 오류라 로컬 Redis 테스트에서도 걸린다. **크기 · 시각만 볼 때는 머리말만** (`GETRANGE … 0 1023`, R-68): 이미지 `HEAD`(7-1) · [전체 검증] 의 이미지 확인 · 안 쓰는 이미지 목록 · 지우기는 파일 본문(작은 이미지는 400KB 까지)을 받지 않는다 — 전에는 `GET` 으로 본문까지 받아 [전체 검증] 한 번에 작은 이미지 전부를 내려받았다 (Upstash 전송량). 알림 받기(`SUBSCRIBE`)는 따로 연 연결에서만. 큰 값은 400KB 조각. 20초 넘게 쉰 연결은 새로 열고, 끊기면 다시 붙어 5번까지 재시도한다. 저장소가 돌려준 오류(사용량 한도 초과 · 인증 실패 등)는 재시도하지 않고 오류로 돌려준다.
- **실시간 중계** (R-51 · DEP-16): 알림에 번호를 붙여 저장하고(`ev:<번호>` 60초 — 다시 붙은 창 · 다시 붙은 구독이 채운다, 11-4) **구독(pub/sub)** 으로 바로 받는다 — 진행자 버튼 → 게임 화면 300ms 이내 (10장). SSE 연결이 있는 서버만 구독 연결을 따로 하나 연다 (구독한 연결은 다른 명령을 못 쓴다). 15초마다 `PING`(Upstash 사용량에 세지 않음)으로 살아 있는지 보고, 끊기면 다시 붙어 저장된 번호로 그 사이 알림을 채운다. 알림 하나에 명령 3개(`INCR` · `SET` · `PUBLISH`), 쉬는 동안은 0 — 0.2초 번호 확인(서버 하나당 시간당 18,000)이면 무료 한도(월 50만)를 넘는다. 구독을 못 하는 저장소면 로그 "구독(pub/sub)을 쓸 수 없어 0.2초마다 확인합니다" 를 남기고 번호 확인으로 돌아간다.
- **로그 (어느 서버에 붙었나)**: 서버마다 `📺 게임 화면 연결 · 끊김 <창 id 앞 8자>`, `🎤 진행자 화면 연결 · 끊김`, 진행자 명령 `▶ <명령>`(명령을 받은 서버), 다른 서버에서 받은 명령을 이 서버의 게임 화면에 넘기면 `◀ <명령> → 게임 화면 <창 id> (다른 서버에서 받은 명령)`. 서버 로그로 두 화면이 어느 서버에 붙었는지 · 명령이 서버를 건넜는지 본다.
- **비어 있을 때**: 저절로 초기 데이터를 넣지 않는다 — Redis 가 비워졌을 때 옛 초기 데이터로 조용히 돌아가면 유실을 알아챌 수 없다. 처음 한 번만 `CAMP_SEED=1` 로 켜서 넣거나(넣으면 `.seeded` 표시), 쓰던 서버의 백업을 넣는다. 비어 있으면 로그에 "저장소가 비어 있습니다" 를 남기고 그대로 켜진다 (관리 페이지로 복구할 수 있게).
- **시작할 때 점검**: 접속 · 인증 · 쓰기 · 덮어쓰기 · 읽기 · 지우기 → 로그 `저장소 점검 ✔ (Redis <주소> · 접두어 <접두어>)`, 안 되면 원인을 남기고 시작하지 않는다 (11-3 의 저장 폴더 점검과 같은 역할). 점검 파일은 시작마다 따로(`.camp-check/<무작위>.txt`) — Vercel 인스턴스 여럿이 한꺼번에 켜져도 서로의 점검 파일을 덮어쓰거나 지우지 않는다 (10/14 실제 환경에서 동시에 켜진 인스턴스가 503 을 낸 것을 고침). **Vercel 함수는 짧게** (R-55): 인스턴스가 자주 새로 켜지고 한꺼번에 수십 개 켜지기도 해서, 접속 · 쓰기 · 읽기만 `SET check:<무작위> … EX 60` · `GET` 두 명령으로 본다 (전부 하면 약 12 명령) → 로그 `저장소 점검 ✔ (… · 짧게)`. 시작할 때 명령은 이것과 `.seeded` · 서명 키 읽기까지 4개. Node 서버는 한 번만 켜지므로 전부 본다.
- **백업**: 리허설 뒤 · 행사 전날 · 끝난 뒤 [백업 내려받기] 는 그대로 받는다 (5-1, 잘못 저장 · 초기화를 되돌릴 바깥 사본).
- 노트북 모드 · 저장 폴더 서버 모드는 그대로 (메모리 · 파일).

### 11-7. 이미지 저장소 — Vercel Blob 공개 저장소 (R-67)

| 항목 | 설계 |
| --- | --- |
| 켜는 조건 | **Redis 저장소는 Blob 필수** (`server/config.mjs` — Vercel 운영 배포 · Vercel 밖 Redis 서버 모두, DEP-27) — 이미지를 Redis 에 넣지 않는 것이 목적이라 대신 Redis 에 넣는 길(폴백)은 없다. 토큰(`BLOB_READ_WRITE_TOKEN` — Blob 저장소를 프로젝트에 연결하면 Vercel 이 넣음)이 없거나 SDK 를 못 불러오면 함수 시작 로그 "✕ 이미지 저장소(Blob)를 쓸 수 없습니다 — <까닭>. 이미지 저장 · 옮기기는 실패합니다 (Redis 에 넣지 않음)" 를 남기고, **이미지 저장 · 백업 올리기의 이미지 · 옮기기는 503** "이미지 저장소(Blob)를 쓸 수 없어 저장하지 않았습니다". 앱은 켠다 — 진행 · 점수 · 이미 있는 이미지 보기는 그대로. 정상이면 시작 로그 "… · 이미지 Vercel Blob (공개)". 노트북 모드 · 저장 폴더 서버 모드 · Vercel 밖 Redis 서버(테스트 · R-50) 는 지금처럼 |
| 문제 데이터 | **그대로** — `image: "assets/photo-quiz/<카테고리>/<문제 id>.png"` (논리 경로). 게임 데이터 형식 · 검증 · 백업 tar · 노트북 모드가 바뀌지 않는다 |
| Redis 에 남는 것 | 이미지마다 `f:assets/…` 머리말만 `{ s 크기, t 시각, u Blob 주소 }` — 본문 · 조각 없음. 폴더 목록(`d:`)은 그대로라 목록 · [전체 검증] · 안 쓰는 이미지 정리(R-68)가 그대로 동작 |
| 쓰기 | 저장소의 `assets/` 아래 쓰기 = Blob `put(경로, 바이트, { access: 'public', addRandomSuffix: true })` → 머리말에 새 주소 → 옛 주소의 Blob · 옛 조각을 지운다. 올릴 때마다 새 주소라 CDN · 브라우저 캐시(기본 1달)가 옛 사진을 보여 주지 않는다 (같은 주소 덮어쓰기는 캐시에 반영되는 데 최대 60초 + 브라우저 캐시) |
| 읽기 (화면) | **이미지 주소 표(R-70)의 Blob 주소를 `<img>` 에 바로** — 화면이 시작할 때 · 게임 데이터가 바뀌었을 때 `GET /api/assets` 한 번(로그인 필요). 이미지마다 서버 함수를 타지 않는다 (처음 R-67 은 이미지마다 `/assets/…` → 함수 · Redis 2회 → 302 였다 — 장당 약 0.1초, 같은 이미지를 다시 그려도 매번). `/assets/…` 302 는 표에 없거나 표를 못 받았을 때의 대비로 남김. 없는 이미지 확인도 표로 (7-1) |
| 읽기 (서버) | 백업 내려받기처럼 바이트가 필요하면 주소에서 받아 온다 (Blob 데이터 전송에 셈 — 백업 한 번 ≈ 이미지 전체 크기) |
| 지우기 | Blob `del(주소)`(무료)를 먼저, 그다음 머리말 · 폴더 목록 항목 — 안 쓰는 이미지 정리(R-68)도 이 길로. Blob 이 꺼진 서버는 Blob 이미지를 지우지 않는다 (503). 교체 때 옛 Blob 을 못 지우면 저장은 된 채 옛 것이 남는다 (Vercel 대시보드 Storage 에서 지움) |
| 옛 이미지 옮기기 (끝남) | 10/27 관리 페이지 [☁ 이미지 Blob 으로 옮기기] 로 쓰는 이미지 146개를 옮겼다 (15-qa 39장 — Upstash 131MB → 988KB). 옮기기 화면 · API 와 Redis 에서 이미지 본문을 읽는 부분은 **걷어냈다** (DEP-27). 주소(`u`) 없는 이미지 키는 없는 것으로 본다 (`/assets` 404) |
| 공개 범위 | 공개 저장소라 **주소를 아는 사람은 로그인 없이 볼 수 있다** (정답 사진 포함). 주소는 로그인한 화면에만 302 로 알려 주고 무작위 접미사라 짐작할 수 없지만, Blob 은 검색 노출을 막는 설정(robots.txt)이 없다. Blob 자체에 Origin · Referer 허용 목록은 없어 **저장소 방화벽 규칙으로 Referer 가 우리 주소(`https://display-ad-camp.fun/`)로 시작하지 않는 요청을 막는다** (R-69, [16-deploy.md](16-deploy.md) 2-4 — 10/27 게시) — 우리 화면의 `<img>` 는 Referer `https://display-ad-camp.fun/` 로 통과, 주소를 새 탭에 붙이거나 다른 곳에 걸면 막힘. 서버가 Blob 에서 받을 때(`fetchBytes` — 백업 내려받기)도 Referer `<대표 주소>/` 를 붙인다. Referer 는 꾸밀 수 있어 진짜 접근 제어는 아니다 — 실제 보호는 짐작할 수 없는 주소를 로그인한 화면에만 알려 주는 것. 비공개 저장소 + 서명 URL 은 검토 후 하지 않기로 (`D-36`) |
| 리전 | `icn1`(서울) — 함수와 같은 곳 (Redis 는 도쿄 `ap-northeast-1`) |
| 사용량 대입 | 쓰는 이미지 약 94MB (안 쓰는 30MB 는 R-68 로 정리) → 저장 1GB 의 10% 아래. 옮기기 약 150 고급 작업. 같은 브라우저는 1달 캐시라 행사 · 리허설 수준이면 전송 10GB 안. 한도를 넘으면 30일 동안 사진이 안 뜨므로 사진을 줄여 올리기(`D-35`)와 사용량 확인(16-deploy)을 같이 한다 |

- **결정 (10/27)**: `D-34` A — `@vercel/blob` SDK 를 켤 때만 불러온다 (`server/blob.mjs`, 테스트는 같은 모양의 가짜 Blob). `D-35` B — 500KB 넘는 PNG · JPEG 는 올릴 때 JPEG 0.85 (7-3).
- **운영에서 켜기**: Blob 저장소 만들기 · 프로젝트 연결 · 옛 이미지 옮기기 순서는 [16-deploy.md](16-deploy.md) 2-3.
- **걷어냄 (DEP-27, 10/27)**: 옮기기를 마친 뒤 Redis 에서 이미지 본문 · 조각을 읽고 쓰는 부분과 옮기기 화면 · API(`/api/admin/images/blob*`)를 뺐다. 이제 Redis 저장소의 이미지는 Blob 에서만 읽고 쓴다 (조각은 백업 tar · 나눠 올리기 조각처럼 이미지가 아닌 큰 파일에만).

### 11-8. 공개 모드 `/play` (R-96 · R-97 · R-98 · R-99, `D-37`)

행사 뒤 누구나 PIN 없이 게임을 해 보는 페이지 ([01-app-flow.md](01-app-flow.md) 8장). 서버 모드의 잠금(11-2)은 그대로 두고, **켜져 있을 때 공개용 데이터 하나와 그 데이터가 쓰는 이미지만** 로그인 없이 연다.

| 항목 | 설계 |
| --- | --- |
| 스위치 | 저장소의 `state/public.json` `{ version: 1, on, updatedAt }` — 관리 API `GET` · `PUT /api/admin/public` (PIN 헤더, 4-3)만 쓴다. 없거나 깨졌으면 꺼짐. 서버가 여럿이어도 저장소(Redis)에서 읽으므로 같다. 현장 상태 API(`/api/state` — settings · route · scoreboard · sessions 만)와 백업(tar `classifyEntry` 가 "백업에 넣지 않는 파일")에 들어가지 않는다 — 백업을 옮겨도 공개가 따라 켜지지 않게. `state/` 라 git 에도 올라가지 않는다 |
| 공개용 데이터 | `GET /api/public` (`server/public-play.mjs`) — 요청마다 스위치를 읽고, 켜져 있으면 `data/app.json` · 게임 파일을 읽어 검증(`validateGame` — 기본값 채움)한 뒤 `publicGame`(`app/core/public-play.js`)으로 줄인다: **줄줄이 말해요(`roulette`)는 게임째 뺀다** (혼자 할 수 없음 — R-97). 숨긴 카테고리 · 문제를 빼고, 필드는 정해 둔 것만 (게임 id · type · 제목 · 아이콘 · 순서 · 문제 순서 `questionOrder`(R-102 — `defaults.questionOrder`, 없으면 `random`) / 카테고리 id · 이름 · 아이콘 · 설명 · 질문 문구 / 문제 정답 · 이모지 · 이미지 · 연출 · 정답 이미지 · 정답 글자 숨기기 · 정답 영상 · 질문 문구 · 힌트). **빼는 것**: 진행자 메모 `note` · 이미지 출처 `credit` · 숨김 · 추가일 · 진행 옵션 `defaults`(문제 순서만 위처럼 따로) · 게임 규칙 `rules`(행사용 — 팀 · 대표) · 게임 설명 `description`(행사용 — "가장 먼저 맞혀 보세요", R-99 — 화면이 혼자 하는 문구를 만든다). 낼 문제가 없는 카테고리 · 게임, 오류가 있는 게임은 뺀다 |
| 이미지 | 응답의 `images` — 이미지 주소 표(R-70)에서 **공개한 문제가 쓰는 경로만** 골라 준다 (Redis 저장소 → Blob 주소, `<img>` 에 바로). 파일 저장소면 `null` → 화면이 `/assets/…` 로 받고, 서버(`static.mjs`)는 로그인하지 않은 요청이라도 스위치가 켜져 있고 공개한 문제가 쓰는 경로면 내준다 (요청마다 게임 데이터를 다시 읽는다 — 파일 저장소에서만 타는 길). 그 밖의 이미지 · `/api/assets` · `/data/**` 는 그대로 401 |
| 화면 | `play.html` · `app/play/` — 공개용 데이터만 받는다. 현장 상태 · 실시간 연결 · 로그인을 쓰지 않는다 (`/api/state` · `/api/live*` 요청 없음, 서버에 쓰기 없음). 한 판은 고른 카테고리 하나 (R-98) — 문제 순서(`planRun(카테고리, questionOrder)` — 작성 순서면 데이터 순서, 무작위면 섞어서, R-102)와 위치는 브라우저 `localStorage` `camp-game:play:v2:<게임 id>:<카테고리 id>` `{ keys, index, order }` 에만, 다 풀면 `{ done: true }`. 다시 열 때 `restoreRun(카테고리, 저장값, questionOrder)` 으로 지금 데이터에 맞춘다 (숨긴 문제 빼고 위치 당김, 다 풂 · 깨진 값 · 순서 설정이 바뀐 판(`order` 가 없으면 `random`)이면 새 판). [↺ 이어하기 초기화] 는 `camp-game:play:v2:` 로 시작하는 키를 모두 지운다 (R-103). R-96 의 게임 단위 저장(`…:v1:<게임 id>`)은 읽지 않는다. [정답 보기] 하는 순간 다음 위치(마지막이면 `{ done: true }`)로 저장한다 (R-99). **화면 위치는 주소 해시** (R-99) — `#<게임 id>` · `#<게임 id>/<카테고리 id>`. 목록에서 고르면 `history.pushState({ up: <지금 해시> })`, 위로 갈 때는 `history.state.up` 이 갈 곳이면 `history.back()`(기록이 쌓이지 않게), 아니면 `replaceState`. `popstate` · 시작할 때 해시대로 그린다 (없는 id 면 `replaceState` 로 한 단계 위). 해시는 서버로 가지 않아 서버 · `vercel.json` 은 그대로. 사진 · 이모지 · 정답 영상은 게임 화면 모듈(`render-photo` · `render-emoji` · `clip`)을 그대로 쓴다 |
| 공개 범위 | 켜 두면 **숨기지 않은 모든 문제의 정답과 사진**이 인터넷에 열린다. 무엇을 공개할지는 숨김으로 정한다 — 관리 페이지 켜기 확인창이 "사람 사진처럼 밖에 공개하면 안 되는 문제는 먼저 숨기세요" 를 알린다. 게임 화면 `/` · 진행자 화면 · 관리 페이지 · 현장 상태는 켜도 PIN 그대로 |
| 비용 | 방문 한 번에 `/api/public` 1회 — Redis 명령 약 6개(스위치 · app.json · 게임 3개 · 이미지 표). 사진은 Blob 에서 바로 (Blob 데이터 전송 10GB / 월 — [16-deploy.md](16-deploy.md) 8장). 실시간 연결이 없어 켜 둔 화면이 명령을 쓰지 않는다 |
