# 캠핑 게임 진행 앱 — 스펙 문서

> **2026 디광 캠핑** (2026-10-29 목) 에서 모니터에 띄워 진행하는 **로컬 실행 게임 앱**
> 담당: 운영자 (준비위원회 3명)
> 저장소: 비공개 GitHub 저장소 (`D-13` · `D-30`)

## 한 줄 요약

제목 화면 → ☰ 메뉴에서 게임 선택 → 게임 홈에서 카테고리 확인 · 제외 → 게임 시작 → 매 판 **룰렛 준비(넣을 카테고리 고르기) → 룰렛 추첨**(같은 카테고리 반복 가능) → 진행 → 결과(정답 수).
종합 점수는 게임이 아니라 **종합 점수판**에서 팀별로 입력 · 합산하고, 게임별 1 · 2 · 3등 점수는 **배점표**에서 보여주고 입력한다.
진행자는 노트북에 띄운 **진행자 화면**(PIN)에서 현재 문제의 정답을 보고, 정답 공개 · 맞힌 팀 지정 · 다음 문제 · 종료를 버튼으로 진행한다 (판정은 말로, 모니터의 게임 화면에는 버튼 없음). 팀 이름은 앱 설정에서 입력하고, 카테고리 · 문제는 별도 **관리 페이지**(`/admin`, PIN)에서 누구나 추가한다.
노트북 안의 **로컬 서버**(`start.command`)로 실행하고, 데이터와 현장 상태(팀 설정 · 진행 기록 · 점수판)는 파일로 저장해 **git 으로 공유**한다.
행사 뒤에는 **공개 모드 `/play`** 를 관리 페이지에서 켜, 누구나 PIN 없이 이모티콘 퀴즈 · 사진 보고 맞추기를 카테고리별로 혼자 해 볼 수 있다 (팀 · 점수 없음 — R-96 · R-97 · R-98).

## 포함 게임

| 게임 | 앱이 하는 일 |
| --- | --- |
| 줄줄이 말해요 (1-2) | 진행자가 고른 주제를 고른 순간 공개 (원판 없음 — R-65) — 팀 차례 표시 없음 (진행자 화면에 예시). 주제에 문제가 있으면 문제 "노발○○" · 정답 후보는 진행자 화면에만 — 진행자가 읽어 준다 (R-44 · R-65) |
| 이모티콘 퀴즈 (2-1) | 사진 퀴즈와 같은 흐름 · 이모지 문제. 문제는 이모티콘 담당자가 준비 → 어드민 표 붙여넣기로 탑재 |
| 사진 보고 맞추기 (2-2) | 카테고리 룰렛 · 사진 문제 14개 카테고리(위키 예시 — 캐릭터 이름 · 확대 음식 · 포스터 제목 가림 · 명장면 명대사 · 과자 / 예능 조사 — 인물 · 브랜드 · 확대 사물 · 짤 출처 · 뮤직비디오 · 데뷔작 · 만화 · 그림 · 랜드마크) · 정답 기록 · 결과(정답 수) |
| (전체) | 배점표 — 게임별 1 · 2 · 3등 점수 보기 · 입력 / 종합 점수판 — 팀별 점수 입력 · 합산 · 시상식 발표 |

## 문서 관리 규칙

- **요구사항**: 사용자 요구는 [00-requirements.md](00-requirements.md) 에 `R-n` 으로 먼저 등록하고, 반영한 문서를 적는다. 요구가 바뀌면 행을 지우지 않고 "반영 (변경)" 으로 표시하고 경위를 남긴다.
- **미결 항목**: 본문에 `D-n` 으로 표시하고 [09-decisions.md](09-decisions.md) 에서 관리한다. 결정되면 "결정된 항목" 으로 옮기고 본문도 고친다.
- **새 게임 추가**: [games/README.md](games/README.md) 표에 행 추가 → `games/<게임>.md` 작성 → [02-data-schema.md](02-data-schema.md) 에 type 스키마 추가. 앱(어드민) 기능이 아니라 이 저장소에서 직접 하는 작업이다 (`D-10`, 지금은 범위 밖).
- **충돌 시 우선순위**: 07-state-model (전이 · 계산) > 02-data-schema (데이터) > 나머지 문서.
