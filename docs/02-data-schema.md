# 02. 데이터 스키마 (R-8, R-14)

## 1. 데이터 구성 개요

| 데이터 | 저장 위치 | 누가 바꾸나 | git 공유 | 내용 |
| --- | --- | --- | --- | --- |
| 앱 정보 | `data/app.json` | 개발자 | O | 행사 제목 · 부제, 등록된 게임 목록 |
| 점수판 기본값 | `data/scoreboard.json` | 개발자 | O | 라운드 목록 · 배점 기본값 (7장, [13-scoreboard.md](13-scoreboard.md)) |
| 게임 데이터 | `data/games/<게임 id>.json` | **관리 페이지** (`/admin`) → 서버 ([04-admin.md](04-admin.md)) | 초기 데이터만 (R-37 — 원본은 서버 저장 폴더) | 게임 정의 · 카테고리 · 문제 |
| 문제 이미지 | `assets/<게임 id>/<카테고리 id>/` | **관리 페이지** → 서버 | 초기 데이터만 (R-37) | 문제 이미지 · 정답 이미지 |
| 어드민 백업 | `data/.backup/` | 로컬 서버 (자동) | ✕ (`.gitignore`) | 저장 직전 파일 사본 |
| 설정 | `state/settings.json` | 앱 화면 (진행자) → 서버 | ✕ (R-37) | 팀, 카테고리 제외, 게임 옵션 → [03-settings.md](03-settings.md) |
| 진행 세션 | `state/sessions/<게임 id>.json` | 앱 (자동) → 서버 | ✕ (R-37) | 진행 위치 · 득점 이력 → [07-state-model.md](07-state-model.md) |
| 점수판 · 배점 변경분 | `state/scoreboard.json` | 배점표 · 종합 점수판 · 관리 페이지 점수 입력 → 서버 | ✕ (R-37) | → [13-scoreboard.md](13-scoreboard.md) 9-1 |
| 마지막 화면 위치 | `state/route.json` | 앱 (자동) → 서버 | ✕ (R-37) | 이어하기 문구 |
| 상태 백업 | `state/.backup/` | 로컬 서버 (자동) | ✕ (`.gitignore`) | 설정 · 점수판 저장 · 상태 초기화 직전 사본 |

- **DB 는 쓰지 않는다** (R-14). 공유 대상 데이터는 모두 프로젝트 폴더 안 파일이고, git 으로 주고받는다.
- **팀 이름 기본값은 코드 · 데이터 파일 어디에도 없다** (R-9). 진행자가 입력한 팀은 현장 상태 파일 `state/settings.json` 에만 저장된다 (R-28). 이 파일도 git 으로 공유하지만(`D-19`) 기본값이 아니라 진행자가 입력한 현장 값이다.
- 현장 상태 파일은 관리 페이지에서 초기화할 수 있다 ([04-admin.md](04-admin.md) 3-10, R-32).
- 현장 상태(설정 · 진행 기록 · 점수판)는 로컬 서버가 `state/` 파일로 저장하고, 브라우저 저장소는 임시 사본으로만 쓴다 ([08-tech.md](08-tech.md) 6장).
- 파일 읽기 · 쓰기는 **로컬 서버**가 맡는다 (R-18, [08-tech.md](08-tech.md) 4장). 게임 화면은 서버가 내주는 JSON 을 읽기만 하고, 쓰기는 어드민 → 서버 API 로만 한다.

## 2. 파일 형식

### 2-1. 게임 데이터 파일 (`data/games/<게임 id>.json`)

- **순수 JSON 파일**. 주석 · 머리말 없음.
- 로컬 서버가 정적 파일로 내주고(`GET /data/games/<id>.json`), 어드민 저장은 서버 API 가 같은 파일을 다시 쓴다.

### 2-2. git diff 를 위한 저장 규칙 (R-14)

여러 사람이 각자 어드민으로 문제를 추가하고 git 으로 합치므로, **같은 데이터는 항상 같은 글자로 저장**되어야 한다. 서버와 브라우저가 같은 직렬화 모듈(`app/core/serialize.js`)을 쓴다.

| 규칙 | 내용 |
| --- | --- |
| 들여쓰기 | 공백 2칸 (`JSON.stringify(data, null, 2)` 과 같음). 단 **숫자 · 문자열만 담은 배열**(그런 배열의 배열 포함 — `focus` · `masks` · `rules` · `examples` · `answers` 등)은 한 줄로 쓴다 (예: `"masks": [[30, 8, 40, 12], [5, 70, 30, 20]]`) |
| 줄바꿈 | LF, 파일 끝 줄바꿈 1개 |
| 인코딩 | UTF-8, BOM 없음. 한글 · 이모지는 그대로 저장 (`\u` 이스케이프 금지) |
| 키 순서 | 이 문서 표의 "순서" 열대로 고정. 직렬화 모듈이 정렬해 쓴다 |
| 생략 규칙 | 값이 기본값과 같은 선택 필드는 저장하지 않는다 (예: `effect: "none"`, `disabled: false` 생략) |
| 배열 순서 | 카테고리 · 문제 배열 순서 = 어드민 목록 순서. 어드민에서 순서를 바꾸지 않는 한 유지 |
| 문제 추가 위치 | 카테고리 `questions` 배열 **끝에** 추가 (git 병합 시 충돌 최소화) |
| 바뀐 게 없으면 | 파일을 다시 쓰지 않는다 (불필요한 git 변경 방지) |

- 데이터 담당은 따로 정하지 않는다 — **누구나 어드민으로 넣는다** (`D-14`). 그래서 문제 id 는 순번이 아니라 **무작위 4자리**다 (3-5) → 여러 사람이 각자 같은 카테고리에 추가해도 id · 이미지 파일 이름이 겹치지 않는다.
- 두 사람이 **같은 카테고리 끝에** 동시에 문제를 추가하면 git 이 충돌로 표시할 수 있다 → 두 사람의 문제 블록을 **모두 남기면** 된다 ([08-tech.md](08-tech.md) 5-5).

### 2-3. 앱 정보 파일 (`data/app.json`)

```json
{
  "schemaVersion": 1,
  "title": "2026 디광 캠핑",
  "subtitle": "10월 29일",
  "games": ["chain-talk", "emoji-quiz", "photo-quiz"]
}
```

| 필드 | 필수 | 타입 | 설명 |
| --- | --- | --- | --- |
| `schemaVersion` | O | 정수 | 현재 `1` |
| `title` | O | 문자열 | 제목 화면 큰 제목 (설정에서 덮어쓰기 가능) |
| `subtitle` | | 문자열 | 제목 화면 부제 |
| `games` | O | 게임 id 배열 | 앱이 불러올 게임 파일 목록 (`data/games/<id>.json`). 메뉴 순서는 각 게임의 `order` |

- 게임 목록을 파일 안에 두는 이유: 화면이 서버 API 없이 정적 파일만으로도 동작하게 하기 위함 (서버 비상 대안, [08-tech.md](08-tech.md) 4-7).

## 3. 공통 스키마

### 3-1. 게임 (Game)

| 순서 | 필드 | 필수 | 타입 | 기본값 | 설명 |
| --- | --- | --- | --- | --- | --- |
| 1 | `schemaVersion` | O | 정수 | — | 현재 `1` |
| 2 | `id` | O | 슬러그 | — | 파일명과 같아야 함 |
| 3 | `type` | O | `"photo"` \| `"emoji"` \| `"roulette"` | — | 게임 종류 (4장) |
| 4 | `title` | O | 문자열 (20자) | — | 메뉴 · 게임 홈 제목 |
| 5 | `icon` | | 이모지 1개 | `"🎮"` | 메뉴 · 게임 홈 아이콘 |
| 6 | `description` | | 문자열 (60자) | — | 게임 홈 설명 |
| 7 | `order` | | 정수 | `999` | 메뉴 정렬 (작을수록 위) |
| 8 | `rules` | | 문자열 배열 (각 40자, 최대 6개) | `[]` | 게임 홈 규칙 요약 |
| 9 | `defaults` | | Defaults | 3-3 | 진행 옵션 초기값 |
| 10 | `categories` | O | Category 배열 (1개 이상) | — | 3-4 |

- **득점형 type** = `photo`, `emoji` (문제 · 정답 기록 · 결과가 있음). **룰렛형 type** = `roulette`.

### 3-2. 판정 · 동점 · 점수 — 데이터 필드 없음

- 게임은 **정답 수만 센다** (R-22). 종합 점수(등수별 배점)는 게임 데이터에 두지 않고 점수판 데이터(7장)에 둔다.
- 판정은 선착순 고정 (`D-2`), 동점은 추가 문제 오픈 고정 (`D-3` — 이 게임에서 아직 안 나온 문제 중 무작위). 둘 다 설정할 것이 없어 게임 데이터에 `scoring` · 예비 문제 필드를 두지 않는다 ([games/README.md](games/README.md) 3 · 4장).
- 사진 보고 맞추기 릴레이(R-62)의 결과 순위 배점도 게임 데이터가 아니라 점수판(7장)의 사진 행에서 온다 — 게임 시작 때 진행 기록(`snapshot.points`)에 담는다 ([07-state-model.md](07-state-model.md) 3-2). 게임 데이터에는 팀당 대표 수(`defaults.relay`, 3-3)만 둔다.

### 3-3. 진행 옵션 기본값 (Defaults)

| 필드 | type | 범위 | 기본값 | 설명 |
| --- | --- | --- | --- | --- |
| `rounds` | 득점형 | 1 ~ 20 | `3` | 라운드 수 (= 룰렛 횟수). 같은 카테고리가 여러 번 나올 수 있어 카테고리 수와 무관 (R-16) |
| `questionsPerRound` | 득점형 | 1 ~ 20 | `5` | 라운드당 문제 수 |
| `questionOrder` | 득점형 | `"random"` \| `"fixed"` | `"random"` | 카테고리 안에서 문제 고르는 방식. `random` = 이 게임에서 아직 안 나온 문제 중 무작위 / `fixed` = 등록 순서대로 |
| `relay` (R-62) | 득점형 (화면 옵션은 `photo` 만) | 정수 0 ~ 6 | 없으면 게임 종류 기본값 — `photo` **2** · `emoji` 0 | 팀당 대표 수 (릴레이, [games/photo-quiz.md](games/photo-quiz.md) 4-1). `0` = 끔 (정답 수 방식). 그래서 서버 데이터를 고치지 않아도 사진 게임은 2명 릴레이가 된다. `0` 도 그대로 저장한다 (기본값과 다를 수 있으므로) |
| `perRep` (R-64) | 득점형 (관리 페이지 입력은 `photo` 만) | 정수 1 ~ 5 | `1` | 인당 문제 — 팀당 대표 방식에서 한 사람이 이만큼 맞히면 빠짐 (대표는 함께 나온다 — R-94), 팀은 `relay` × `perRep` 번 맞히면 끝 ([games/photo-quiz.md](games/photo-quiz.md) 4-1). 최소 문제 수에는 곱하지 않는다. 1 은 기본값이라 저장하지 않는다 |

- `perRep` 이 정수가 아니면 E04, 범위 밖이면 W01 로 1 ~ 5 에 맞춘다. 게임 홈 옵션은 없다 — 게임 시작 때 진행 기록 `snapshot.options.perRep` 으로 고정 (R-64).
- `relay` 가 정수가 아니면 E04, 범위 밖이면 W01 로 0 ~ 6 에 맞춘다. 게임 홈에서 바꾼 값은 설정 `games.<id>.relay` ([03-settings.md](03-settings.md) 4장)가 우선하고, 게임 시작 때 진행 기록 `snapshot.options.relay` 로 고정한다 ([07-state-model.md](07-state-model.md) 3-2).
- 룰렛형(`roulette`)은 `defaults.questionOrder` 만 쓴다 — 주제 안 문제를 [다음 문제] 로 낼 때 랜덤 / 작성 순서 (R-45). `rounds` · `questionsPerRound` 는 쓰지 않고 저장할 때 뺀다 (`D-7` — 추첨 횟수 · 팀 차례 표시 없음).
- `timerSeconds` (제한시간)는 타이머를 없애면서 뺐다 (R-33). `defaults` · 문제(3-5)에 남아 있으면 오류 · 경고 없이 무시하고, 관리 페이지에서 저장할 때 정리한다.

### 3-6. 공통 형식 규칙

| 항목 | 규칙 |
| --- | --- |
| 슬러그 | 영문 소문자 · 숫자 · 하이픈, 2~32자 (`^[a-z0-9]+(-[a-z0-9]+)*$`) |
| 경로 | 프로젝트 루트 기준 상대 경로, 구분자 `/`, 앞에 `/` · `./` · `..` 금지 |
| 이모지 1개 | 합성 이모지(👨‍👩‍👧, 🇰🇷 등) 포함 1개 글자 묶음 |
| 문자열 | 앞뒤 공백 제거 후 저장, 줄바꿈 금지 (`note` 제외) |
| 글자 수 | 사람이 보는 글자 단위 (이모지 · 한글 1자 = 1) |
| 백분율 좌표 | 0 ~ 100, 소수 1자리까지 |

## 4. 게임 종류별 스키마

### 4-1. `type: "photo"` — 사진 보고 맞추기 (R-17)

문제 필드 (공통 `id`, `answer` 다음):

| 순서 | 필드 | 필수 | 타입 | 기본값 | 설명 |
| --- | --- | --- | --- | --- | --- |
| 3 | `image` | O | 경로 | — | 문제 이미지. `assets/<게임 id>/<카테고리 id>/<문제 id>.<확장자>` |
| 4 | `effect` | | `"none"` \| `"zoom"` \| `"mask"` | `"none"` | 연출: 원본 / 확대 / 가림 ([games/photo-quiz.md](games/photo-quiz.md) 5장) |
| 5 | `zoom` | `effect: "zoom"` 이면 O | 숫자 1.5 ~ 10 (0.5 단위) | — | 시작 확대 배율 |
| 6 | `focus` | | `[x, y]` (%) | `[50, 50]` | 확대 중심 (`zoom` 일 때만) |
| 7 | `steps` | | 정수 1 ~ 6 | `3` | 축소 단계 수 (`zoom` 일 때만) |
| 8 | `masks` | `effect: "mask"` 이면 O | `[x, y, w, h]` 배열 (%, 1 ~ 8개) | — | 가림 상자. 배열 순서 = 진행자 [힌트 단계 ▶] 로 하나씩 제거되는 순서. `w`, `h` > 0, `x + w ≤ 100`, `y + h ≤ 100` |
| 9 | `answerImage` | | 경로 | — | 정답 공개 때 바꿔 보여줄 이미지. `assets/<게임 id>/<카테고리 id>/<문제 id>-answer.<확장자>` |
| 9-1 | `hideAnswerText` | | 불리언 | `false` | 정답 공개 때 정답 글자 띠를 숨긴다 (R-41). 정답 이미지가 있으면 그것만, 없으면 원래 사진(확대 · 가림 해제)만 — `answerImage` 와 상관없이 켤 수 있다 (R-47) |
| 9-2 | `answerClip` | | 유튜브 주소 | — | 정답 영상 (R-61) — 정답 공개 때 모니터에서 자동 재생, 끝나면 정답 띠 ([games/photo-quiz.md](games/photo-quiz.md) 5-5). 관리 페이지는 `https://youtu.be/<영상 id>` 로 저장한다. `youtube.com/watch?v=` · `youtu.be/` · `/shorts/` · `/embed/` · `/live/` 주소를 읽고, 클립 주소(`youtube.com/clip/…`)는 원본 영상을 알 수 없어 받지 않는다. 읽을 수 없으면 영상 없이 사용 (W13) |
| 9-3 | `clipStart` | | 초 (0 이상, 소수 1자리) | `0` | 재생 시작. 없으면 주소의 `t=` · `start=`, 그것도 없으면 처음부터 |
| 9-4 | `clipEnd` | | 초 (`clipStart` 보다 큼, 소수 1자리) | — | 재생 끝 — 이 시간에 멈추고 영상을 걷어낸다. 없으면 주소의 `end=`, 그것도 없으면 영상 끝까지. 시작보다 앞이면 무시 (W01) |
| 10 | `credit` | | 문자열 | — | 이미지 출처 메모 (표시 안 함) |

### 4-3. `type: "roulette"` — 줄줄이 말해요 (진행자가 고르는 주제 + 주제별 문제 — R-65 전에는 주제 룰렛)

- 카테고리 = 주제. 카테고리의 `rule`, `examples` 를 쓴다 (3-4).
- `defaults` 는 `questionOrder` 만 (3-3) — 주제 안 문제를 [다음 문제] 로 낼 때 랜덤(기본) / 작성 순서 (`D-24`, R-45). 라운드 · 추첨 횟수 · 팀 차례 옵션은 없다 (`D-7`).
- 주제마다 **문제(`questions`)를 둘 수 있다** (선택, R-44). 득점형 문제(3-5)와 달리 정답이 하나가 아니라 **정답 후보 목록**이다 — 팀원이 차례로 서로 다른 답을 말하므로.

```json
{
  "id": "idiom",
  "name": "사자성어 이어 말하기",
  "icon": "📜",
  "rule": "앞 사람이 사자성어 앞 두 글자를 말하면 뒤 두 글자를 이어 말하기",
  "examples": ["노발 → 대발", "대성 → 통곡", "동병 → 상련"],
  "questions": [
    {
      "id": "idiom-k7q2",
      "prompt": "노발○○",
      "answers": ["노발대발"],
      "addedAt": "2026-10-12"
    }
  ]
}
```

줄줄이 말해요 문제 (ChainQuestion) — 득점형 문제의 `answer` · `hint` · 이미지 필드는 쓰지 않는다:

| 순서 | 필드 | 필수 | 타입 | 기본값 | 설명 |
| --- | --- | --- | --- | --- | --- |
| 1 | `id` | O | 문자열 | — | 게임 안에서 유일. 3-5 와 같은 규칙 (`<주제 id>-<무작위 4자리>`, 어드민이 발급, 변경 불가) |
| 2 | `prompt` | O | 문자열 (20자 권장) | — | **진행자 화면에 띄울 문제 글자** — 진행자가 읽어 준다 (R-65 부터 게임 화면에는 나오지 않음). 빈칸은 `○` (예: "코스○○") |
| 3 | `answers` | O | 문자열 배열 (1개 이상, 50개 권장, 각 30자 권장) | — | **정답 후보** — 진행자 화면에 항상, 게임 화면에는 [정답 후보 표시] 때만 (가나다순으로 보여줌). 같은 후보 중복 금지(어드민이 입력 때 하나만 남김) |
| 4 | `note` | | 문자열 (100자) | — | 진행자 메모 (인정 기준 등). 진행자 화면 전용 |
| 5 | `disabled` | | 불리언 | `false` | 숨김 (출제 제외) |
| 6 | `addedAt` | | `YYYY-MM-DD` | — | 어드민이 기록 |

```json
{
  "id": "category-m3xk-9tdw",
  "prompt": "코스○○",
  "answers": ["코스모스", "코스요리", "코스피아", "코스트코"],
  "note": "'코스닥' 은 세 글자라 불인정"
}
```

- 카테고리 `prompt` · `defaultEffect` 초기값은 [games/photo-quiz.md](games/photo-quiz.md) 3장, [games/emoji-quiz.md](games/emoji-quiz.md) 2장.

### 4-5. 새 type 추가 규칙

- 이 장에 `4-n. type: "<값>"` 절 추가. 공통 필드는 그대로 쓰고 고유 필드만 정의.
- 공통 필드 이름을 다른 뜻으로 재사용하지 않는다.
- 검증 규칙(5장), 어드민 입력 화면([04-admin.md](04-admin.md)), 일괄 붙여넣기 열(6장)도 함께 정의.

## 5. 검증 규칙

브라우저(앱 시작 시 · 어드민 저장 전)와 로컬 서버(저장 요청 받을 때)가 **같은 검증 모듈**(`app/core/validate.js`)로 검사한다. 서버 검증을 통과하지 못하면 파일은 바뀌지 않는다.

### 5-1. 오류 (그 게임을 쓸 수 없음 / 저장 불가)

| 코드 | 조건 | 메시지 예 |
| --- | --- | --- |
| E01 | 게임 데이터 파일을 읽지 못함 / JSON 문법 오류 | `data/games/photo-quiz.json 을 읽을 수 없습니다 (문법 오류)` — git 충돌 표시(`<<<<<<<`)가 남아 있으면 "git 충돌이 해결되지 않았습니다" 로 안내 |
| E02 | `schemaVersion` 미지원 | `photo-quiz: schemaVersion 2 는 지원하지 않습니다` |
| E03 | 필수 필드 없음 | `photo-quiz.categories[0].questions[2].answer 가 없습니다` |
| E04 | 타입 · 범위 · 형식 위반 | `photo-quiz.categories[1].id 'Movie Scene' 은 슬러그 형식이 아닙니다` |
| E05 | id 중복 (카테고리 id / 문제 id — 게임 전체) | `photo-quiz: 문제 id 'snack-3hdv' 가 중복됩니다` |
| E06 | `id` 와 파일명 불일치 | `data/games/photo-quiz.json 의 id 가 'photo' 입니다` |

| E09 | type · 연출에 맞지 않는 구조 | `effect: "zoom"` 인데 `zoom` 없음 / `effect: "mask"` 인데 `masks` 없음 / `emoji` 문제에 `emojis` · `image` 둘 다 없음 |

- 오류가 있는 게임은 메뉴에 "⚠ 데이터 오류", 게임 홈에 오류 목록. 다른 게임은 정상 사용.

## 6. 일괄 붙여넣기 형식 (어드민 · R-15)

### 6-4. 붙여넣기 처리 규칙
- 붙여넣기 → **미리보기 표** (행별 ✔ / ⚠ / ✕ 와 사유) → [n개 등록] → 한 번의 저장 요청.
- ✕ 행(필수 누락 등)은 등록에서 제외하고 사유 표시. ⚠ 행(같은 정답 중복 등)은 체크박스로 포함 여부 선택.
- 등록 순서 = 붙여넣은 행 순서, 각 카테고리 끝에 추가 (2-2).

## 7. 점수판 기본값 (`data/scoreboard.json`, R-23 · R-24)

종합 점수판 · 배점표가 쓰는 **라운드(게임) 목록과 배점 기본값**. 현장에서 배점표 · 라운드 설정으로 바꾼 값은 현장 상태 파일 `state/scoreboard.json` 에 저장되고 (R-28) 이 파일은 바뀌지 않는다 ([13-scoreboard.md](13-scoreboard.md) 9-1). 순수 JSON, 저장 규칙은 2-2 와 같다.

```json
{
  "schemaVersion": 1,
  "rounds": [
    { "id": "team-forming", "name": "팀 정하기", "kind": "rank", "points": [50, 0, 0, 0] },
    { "id": "ten-seconds", "name": "10초 안에 성공하라", "kind": "rank", "points": [200, 100, 50, 0] },
    { "id": "chain-talk", "name": "줄줄이 말해요", "kind": "pass", "pass": 200, "fail": 0, "gameId": "chain-talk" },
    { "id": "emoji-quiz", "name": "이모티콘 퀴즈", "kind": "count", "per": 50, "gameId": "emoji-quiz" },
    { "id": "photo-quiz", "name": "사진 보고 맞추기", "kind": "rank", "points": [100, 50, 0, 0], "gameId": "photo-quiz" },
    { "id": "jegi", "name": "제기차기", "kind": "rank", "points": [300, 200, 100, 0] },
    { "id": "shoe-throw", "name": "신발 던지기", "kind": "rank", "points": [600, 400, 200, 0] }
  ]
}
```

### 라운드 필드

| 순서 | 필드 | 필수 | 타입 | 설명 |
| --- | --- | --- | --- | --- |
| 1 | `id` | O | 슬러그 | 라운드 id. 목록 안에서 유일. 점수판 입력값이 이 id 로 묶이므로 만든 뒤 바꾸지 않는다 |
| 2 | `name` | O | 문자열 (20자) | 배점표 · 점수판 행 이름 |
| 3 | `kind` | O | `"rank"` \| `"pass"` \| `"count"` \| `"manual"` | 등수 / 성공 · 실패 / 정답 수 (R-49) / 직접 입력 |
| 4 | `points` | `rank` 이면 O | 정수 4개 배열 | 1 · 2 · 3 · 4등 점수 (팀이 3개면 4등 값은 쓰지 않음). 음수 허용 |
| 5 | `pass` | `pass` 이면 O | 정수 | 성공 점수 |
| 6 | `fail` | `pass` 이면 O | 정수 | 실패 점수 |
| 7 | `per` | `count` 이면 O | 정수 | 정답 1개당 점수 (R-49). 점수 = 정답 수 × `per` |
| 8 | `gameId` | | 게임 id | 연결된 앱 게임. 그 게임 홈의 배점 구역에 표시 + 퀴즈 결과 자동 입력 대상 (한 게임에 여러 라운드 가능). `count` 라운드가 `categoryId` 없이 연결돼 있으면 그 게임 화면 · 진행자 화면이 정답 수 대신 점수(정답 수 × `per`)를 보여 준다 (여럿이면 첫 번째) |
| 9 | `categoryId` | | 카테고리 id | (`gameId` 가 있을 때) 자동 입력 때 그 카테고리 라운드들의 정답 수로 순위를 매김(`rank`) · 정답 수를 넣음(`count`). 없으면 게임 전체 정답 수 ([13-scoreboard.md](13-scoreboard.md) 10장) |
