# 01. 앱 흐름

## 1. 전체 흐름

```
[앱 실행]
   │
   ▼
[제목 화면] ──── ☰ ────▶ [햄버거 메뉴]
                          ├─ 게임 종류 목록 ──▶ [게임 홈: 카테고리 보기 · 제외 설정 · 옵션]
                          ├─ 배점표 ──────────▶ [게임별 1·2·3등 점수 보기 · 입력]
                          ├─ 종합 점수판 ────▶ [팀별 점수 입력 · 합산 · 발표]
                          ├─ 기록 · 통계 ────▶ [종합 점수 추이 · 팀별 통계 · 문제 기록] (R-58)
                          ├─ 팀 설정 ─────────▶ [팀 설정 화면]
                          ├─ 전체화면 · 도움말
                          ├─ 진행자 화면 ─────▶ (새 창 /host)
                          ├─ 관리 ────────────▶ (새 창 /admin — PIN)
                          └─ 제목 화면으로

[게임 홈] ── 게임 시작 ──▶ [룰렛 준비: 이번 판에 넣을 카테고리 고르기] ── Enter ──▶ [룰렛 회전 · 추첨]
                              ▲                                                      │ 확정
                              │                                                      ▼
                              │                    [라운드 소개] → [문제] → [정답] → … (라운드 문제 수만큼)
                              │                                                      │ (진행자: 한 문제 더 / 라운드 종료)
                              │                                                      ▼
                              │                                   [라운드 종료: 팀별 라운드 점수] (R-56)
                              │                                                      │
                              └──────────── 남은 라운드 있음 ◀───────────────────────┘
                                                   │ 없음
                                                   ▼
                                     [최종 결과: 정답 수 순서] ──▶ (종합 점수판 / 게임 홈 / 제목 화면)
```

- 위 흐름은 득점형 게임(`photo` 사진 보고 맞추기, `emoji` 이모티콘 퀴즈) 기준이다. 이모티콘 퀴즈는 룰렛 · 라운드 소개 · 라운드 종료가 없다 (R-90) — 게임 홈 → [문제 고르기(모니터 카테고리 목록, 진행자 화면에서 문제 [내기]) → 문제 → 정답] 반복 → [종료] → 결과 ([games/emoji-quiz.md](games/emoji-quiz.md) 3장). 룰렛 전용 게임(`roulette`, 줄줄이 말해요)은 원판이 없다 (R-65) — 게임 홈 → [주제 고르기(진행자 화면) → 고른 순간 모니터에 주제 카드 (→ 문제가 있는 주제는 진행자가 [첫 문제 ▶] — 문제 "노발○○" · 정답 후보는 진행자 화면에만, R-44 · R-65)] 를 필요한 만큼 반복 → [끝내기] 로 게임 홈. 팀 차례 · 추첨 횟수 · 추첨 완료 화면은 없다 (`D-7`, [games/chain-talk.md](games/chain-talk.md)).
- 퀴즈 게임은 **맞힌 개수만 센다** (R-22). 종합 점수는 별도 메뉴 "종합 점수판"에서 입력 · 합산하고, 게임별 1 · 2 · 3등 점수는 "배점표"에서 보여주고 입력한다 ([13-scoreboard.md](13-scoreboard.md)).
- 사진 보고 맞추기는 **릴레이** (R-62, 팀당 대표 기본 2명 — [games/photo-quiz.md](games/photo-quiz.md) 4-1): 라운드 문제 수 대신 **한 팀만 남을 때까지** 문제를 내고, 라운드 종료 화면은 이번 라운드 순위, 최종 결과는 라운드 등수의 배점 합(게임 점수) 순서.
- 햄버거 메뉴는 **어느 화면에서든** 열 수 있다 (게임 진행 중 포함).
- 게임 진행 중 메뉴에서 다른 게임을 고르면 확인 후 이동한다 (4-4).

## 2. 제목 화면 (R-3)

- 앱을 열면 **항상** 제목 화면이 먼저 나온다. 진행 중이던 게임이 저장돼 있어도 바로 그 게임으로 가지 않는다.
- 표시 내용
  - 행사 제목 / 부제 (앱 설정값, [03-settings.md](03-settings.md) 3장)
  - 좌상단 ☰ 버튼
  - 가운데 하단 안내: "☰ 메뉴에서 게임을 골라 주세요"
  - 팀 설정 상태
    - 설정됨: 팀 이름 배지 나열 (팀 색)
    - 미설정: "⚠ 팀 설정이 필요합니다 — ☰ → 팀 설정" (강조색)
  - 이어하기 카드 (저장된 진행 중 게임이 있을 때만)
    - "진행 중인 게임: 사진 보고 맞추기 · 라운드 2 · 3번 문제" + [이어하기] 버튼
    - 이어하기 → 저장된 위치로 바로 복귀
- ~~제목 화면에서 `→` / `Enter` / `Space` 를 누르면 햄버거 메뉴가 열린다~~ (R-73 에서 없앰 — ☰ 버튼으로) (진행자가 메뉴 버튼을 못 찾는 상황 대비).

## 3. 햄버거 메뉴 (R-4)

- 열기: 좌상단 ☰ 버튼 클릭. 닫기: ☰ 다시 클릭, `Esc`, 메뉴 바깥 클릭. `M` 키는 없다 (R-73).
- 형태: 화면 왼쪽에서 밀려 나오는 패널 (너비 화면의 28%, 최소 360px). 뒤 화면은 어둡게.
- 메뉴 항목 (위에서부터)

| 구역 | 항목 | 동작 |
| --- | --- | --- |
| 게임 | 게임 종류 목록 (데이터에 등록된 게임 전부, `order` 순) | 해당 게임 홈으로 이동 |
| | 각 항목 표시 | 아이콘 · 게임 이름 · 카테고리 수 · 문제 수. 진행 중이면 "진행 중" 배지 |
| 점수 | 배점표 | 게임별 1 · 2 · 3등 점수 보기 · 입력 ([13-scoreboard.md](13-scoreboard.md) 4장) |
| | 종합 점수판 | 팀별 점수 입력 · 합산 · 발표 ([13-scoreboard.md](13-scoreboard.md) 6장) |
| 설정 | 팀 설정 | 팀 설정 화면 |
| 보기 | 전체화면 | 전체화면 토글 |
| | 도움말 | 단축키 도움말 오버레이 |
| | 진행자 화면 | 새 창으로 진행자 화면(`/host`) 열기 — 현재 문제 정답 확인 + **진행 조작 패널** (정답 공개 · 맞힌 팀 지정 · 다음 문제 · 종료), PIN 필요 ([12-host-view.md](12-host-view.md)) |
| | 다른 창 열기 막기 / 허용 | 🔒 [다른 창 열기 막기] ↔ 🔓 [다른 창 열기 허용] — 켜 두면 다른 기기 · 탭에서 게임 화면을 열 수 없다 (진입이 안 되는 화면, PIN 입력도 없음). 꺼져 있으면 새로 연 게임 화면이 이 창을 닫을지 묻는다 ([12-host-view.md](12-host-view.md) 6-3, R-46) |
| 이동 | 제목 화면으로 | 제목 화면 (진행 중 게임은 저장된 채 유지) |
| 관리 | 관리 (메뉴 맨 아래, 작은 글씨) | 새 창으로 **관리 페이지(`/admin`)** 열기 — 카테고리 · 문제 추가, 점수 입력, 상태 초기화. 첫 화면은 PIN (`D-9`, R-31, [04-admin.md](04-admin.md) 2장) |

- 메뉴 안에서는 방향키 `↑` `↓` 로 항목 이동, `Enter` 로 선택 가능 (키보드만으로 조작).
- 현재 보고 있는 게임은 메뉴에서 강조 표시.

## 4. 게임 홈 (R-5, R-6)

게임 종류를 고르면 나오는 화면. **카테고리를 보여주기만** 하고, 고르지 않는다.

### 4-1. 표시 내용

| 요소 | 내용 |
| --- | --- |
| 게임 제목 · 설명 | 데이터의 `title`, `description` |
| 규칙 요약 | 데이터의 `rules` (3~5줄 목록) |
| 배점 | 이 게임과 연결된 종합 점수판 라운드의 1 · 2 · 3등 점수 (예: "🥇 100 · 🥈 50 · 🥉 0") + [배점 수정] + [배점표 전체 보기] (R-24, [13-scoreboard.md](13-scoreboard.md) 5장). 퀴즈 게임은 "정답 수로 순위를 정하고, 종합 점수는 점수판에서 입력" 안내 — 릴레이(R-62)는 "라운드마다 대표를 모두 내보낸 순서로 등수를 매겨 배점을 더합니다. 게임 결과 순위도 그 합입니다." |
| 카테고리 목록 | 카테고리 카드 그리드 (4-2) |
| 진행 옵션 | 라운드 수, 팀당 대표 (사진 — R-62), 라운드당 문제 수 (릴레이가 아닐 때), 문제 순서 (4-3) |
| 팀 | 현재 팀 설정 요약 + [팀 설정] 바로가기 |
| 게임 시작 버튼 | 시작 조건(4-4) 충족 시 활성 |

### 4-2. 카테고리 카드

| 요소 | 내용 |
| --- | --- |
| 아이콘 · 이름 | 카테고리 `icon`, `name` |
| 설명 | 카테고리 `description` (한 줄) |
| 문제 수 | "문제 7개" (사용 가능한 문제 = `disabled` 아닌 문제 수) |
| 미리보기 | **없음** — 문제 이미지 · 정답은 게임 홈에서 절대 보여주지 않는다 (스포일러 방지) |
| 제외 토글 | 카드 우상단 스위치 "포함 / 제외". 제외 시 카드 반투명 + "제외됨" 표시 |

- 카드를 클릭해도 "선택"되지 않는다. 클릭 동작은 제외 토글뿐이다.
- 문제가 0개인 카테고리는 자동으로 "문제 없음" 표시, 토글 비활성(항상 제외 취급).
- 릴레이(R-62)에서는 문제가 **(팀 수 − 1) × 대표 수**보다 적은 카테고리도 쓸 수 없다 — "문제 3개 · 4개 필요" 로 꺼지고 토글 비활성, 포함 후보가 아니다 (`D-33`). 팀 수 · 팀당 대표를 바꾸면 바로 다시 계산.
- 제외 설정은 게임별로 저장되어 다음 실행에도 유지된다 ([03-settings.md](03-settings.md) 4장).
- 키보드 단축키 없음 — 제외 토글 · 시작 · 이어하기 · 새로 시작은 클릭으로 (R-76. 예전 `Tab` · 방향키 이동, `Space` 토글, `Enter` 시작, `N` 새로 시작).

### 4-3. 진행 옵션

> **R-92**: 아래 옵션은 **게임 홈에 없다** — 관리 페이지 게임 편집 "진행 기본값" 에서만 정하고, 예전에 게임 홈에서 저장한 값은 무시한다. 게임 홈 아래 요약 줄도 없앴다. 표는 옵션의 뜻 · 범위 · 기본값으로 남긴다.

아래는 득점형(`photo`, `emoji`) 게임 옵션이다. `roulette` 게임은 "문제 순서"(랜덤 / 작성 순서) 하나만 있다 — 주제에 문제가 있을 때만 보인다 (`D-7`, R-45, [games/chain-talk.md](games/chain-talk.md) 3-1).

| 옵션 | 범위 | 기본값 | 설명 |
| --- | --- | --- | --- |
| 라운드 수 | 1 ~ 20 | 데이터 `defaults.rounds` (없으면 3) | 룰렛을 몇 번 돌릴지 **계획** — 참고값이라 진행 중 [한 라운드 더 ▶] 로 넘길 수 있고 [종료] 로 일찍 끝낼 수 있다 (R-40). 같은 카테고리가 여러 번 나올 수 있으므로 포함 카테고리 수와 무관 (R-16) |
| 팀당 대표 (R-62) — 사진 보고 맞추기만 | 0 ~ 6 (0 = "끔") | 데이터 `defaults.relay` (없으면 게임 종류 기본값 — 사진 **2**, 이모티콘 0) | 라운드마다 팀당 대표 n명 릴레이 — 맞히면 빠지고, 대표가 모두 맞힌 순서로 1 · 2 · 3등 ([games/photo-quiz.md](games/photo-quiz.md) 4-1). 0 이면 예전 정답 수 방식 |
| 라운드당 문제 수 | 1 ~ 20 | 데이터 `defaults.questionsPerRound` (없으면 5) | 라운드를 시작할 때 뽑는 문제 수 — **계획**이라 라운드 끝에서 [한 문제 더 ▶] 로 같은 카테고리 문제를 더 낼 수 있다 (R-43). 카테고리에 남은 문제가 더 적으면 남은 만큼만 (5-5). **릴레이에서는 쓰지 않아 숨긴다** — 순위가 정해질 때까지 낸다 (5-4) |
| 문제 순서 | 랜덤 / 작성 순서 | 데이터 `defaults.questionOrder` (없으면 **랜덤**) | 카테고리 안에서 어떤 문제를 어떤 순서로 낼지 (5-4) |

- 화면 하단 요약: "포함 카테고리 3개 · 3라운드 · 라운드당 5문제 · 예상 15문제 (약 15분)". 릴레이면 "포함 카테고리 12개 · 3라운드 · 팀당 대표 2명 — 한 팀만 남을 때까지, 라운드마다 4문제 이상 · 문제가 4개보다 적은 카테고리 2개는 빠짐"
- (R-92 전) 옵션 값은 게임별로 저장했다 — 지금은 데이터 `defaults` 만 ([03-settings.md](03-settings.md) 4장).
- 타이머는 두지 않는다 (R-33, `D-20`). 문제를 얼마나 끌지는 연출 단계(진행자 [힌트 단계 ▶])와 진행자의 [정답 공개]로 정한다.

### 4-4. 게임 시작 조건

| 조건 | 미충족 시 |
| --- | --- |
| 팀 설정 완료 (2~4팀, 이름 모두 입력) — 득점형만. `roulette` 은 팀을 쓰지 않아 필요 없음 (`D-7`) | 버튼 비활성 + "팀 설정이 필요합니다" + [팀 설정] 링크 |
| 후보 카테고리(제외 안 됨 + 문제 1개 이상 — 릴레이는 (팀 수 − 1) × 대표 수 이상, R-62) ≥ 1 | 버튼 비활성 + "포함된 카테고리가 없습니다". 릴레이에서 문제가 모자라 후보가 없으면 "팀당 대표 2명이면 카테고리마다 문제가 4개 이상 필요합니다" |
| 데이터 검증 통과 | 오류 화면 ([08-tech.md](08-tech.md) 8장) |

- 이 게임의 진행 중 세션이 있으면 [게임 시작] 대신 [이어하기] + [새로 시작] 두 버튼.
  - 새로 시작 → 확인창 "진행 중인 게임 기록이 지워집니다" → 확인 시 세션 삭제 후 시작.
- 다른 게임이 진행 중이면 시작 시 확인창: "진행 중인 '○○' 게임은 그대로 저장됩니다. 새 게임을 시작할까요?" (게임별 세션 독립 저장, [07-state-model.md](07-state-model.md))

### 4-5. 게임 시작 시 확정되는 것 (세션 스냅샷)

시작 버튼을 누르는 순간 아래 값을 세션에 고정한다. 이후 게임 홈 설정을 바꿔도 진행 중 세션에는 영향 없음.

- 팀 수 (팀 이름 · 색은 표시용이라 설정 변경 시 즉시 반영)
- 첫 룰렛 준비의 카테고리 선택 (게임 홈 제외 반영) — 이후 매 판 룰렛 준비에서 진행자가 바꾼다 (5-2)
- 라운드 수, 라운드당 문제 수, 문제 순서, 팀당 대표 (R-62 — 이 값이 없는 예전 세션은 정답 수 방식 그대로)
- (릴레이) 결과 순위에 쓰는 라운드 배점 — 배점표의 이 게임 행. 단 배점은 고정이 아니라 배점표에서 바꾸면 진행 중 세션도 따라간다 ([07-state-model.md](07-state-model.md) 3-2, `D-33`)

## 5. 룰렛 (R-5)

룰렛은 모든 게임 type 이 같은 화면 · 같은 동작을 쓴다. 달라지는 것은 "언제 돌리는가" 와 "확정 후 어디로 가는가" 뿐이다.

### 5-1. 언제

| type | 룰렛을 돌리는 시점 | 확정 후 |
| --- | --- | --- |
| 득점형 (`photo`, `emoji`) | 게임 시작 직후 + 라운드가 끝나고 남은 라운드가 있을 때 | 라운드 소개 화면 |
| `roulette` | 게임 시작 직후 + 주제 카드 · 문제에서 [다시 추첨] (지금은 진행자 [다음 주제 ▶], 횟수 제한 없음 — 게임 화면 `→` 는 R-85 에서 없앰) | 주제 카드 화면 (문제가 있으면 [첫 문제 ▶] 로 문제 — R-44) |

### 5-2. 룰렛 준비 — 이번 판에 넣을 카테고리 고르기 (R-21, R-16)

룰렛을 돌릴 때마다 **항상** 먼저 "룰렛 준비" 상태가 된다. 진행자가 **진행자 화면**의 카테고리 목록에서 빼거나 다시 넣은 뒤 돌린다 (`D-16` 확정). 게임 화면은 넣은 카테고리의 원판만 보여 준다 — 목록은 진행자 화면에만 (R-72).

| 항목 | 규칙 |
| --- | --- |
| 언제 | 득점형은 매 라운드 추첨 전, 룰렛형은 매 추첨 전, 그리고 정지 후 **다시 돌리기**를 할 때도 준비 상태로 돌아온다 |
| 목록 | 이 게임의 카테고리 전부 (숨김 카테고리 제외). 게임 홈에서 제외했던 카테고리도 "빠짐" 상태로 보여 다시 넣을 수 있다 |
| 항목 표시 | 아이콘 · 이름 · 넣음 / 빠짐 토글 · (득점형) 남은 문제 수 "남은 문제 4" · 이번 게임에서 당첨된 횟수 "×2" |
| 원판 | 목록에서 넣은 카테고리만 같은 크기 조각으로, 토글할 때마다 **즉시** 다시 그려 미리 보여준다 |
| 처음 선택 | 첫 판 = 게임 홈 제외 설정 반영. 그다음 판부터 = **직전 판의 선택을 그대로 이어받음** (매번 처음부터 고를 필요 없음) |
| 앱이 바꾸는 것 | 없음. 이미 나온 카테고리도 넣은 상태 그대로 남는다 (R-16). 단 남은 문제가 0개가 된 카테고리는 "모두 출제함" 으로 표시하고 넣을 수 없다 (걸려도 진행할 문제가 없으므로). 릴레이(R-62)는 남은 문제가 (팀 수 − 1) × 대표 수보다 적은 카테고리도 "⊘ 부족 · 남은 3 / 4" (진행자 화면 "부족 · 남은 3/4") 로 넣을 수 없다 — 넣기 · 빼기 · 모두 넣기 무시 (`D-33`) |
| 넣은 카테고리 0개 | 돌릴 수 없음 — "카테고리를 1개 이상 넣으세요" |
| 넣은 카테고리 1개 | `Enter` → 회전 없이 그 카테고리 카드 (`Enter` 로 확정) |
| 적용 범위 | **이번 게임에만**. 게임 홈의 제외 설정(다음 게임의 첫 선택값)은 바꾸지 않는다 |
| 저장 | 선택은 진행 기록에 저장 → 새로고침해도 유지 |

- 같은 카테고리가 여러 번 나와도 되고, 매 회전은 원판에 넣은 카테고리 사이의 독립 추첨이다 (모든 조각 확률 같음). 단 진행자 화면에서 결과를 지정하면 그 회전은 지정한 조각에 멈춘다 (5-3, R-48).
- 원판 아래(또는 목록 위)에 지난 라운드 기록을 칩으로 보여준다 (예: "지난 라운드: 🔍 확대 음식 · 🔍 확대 음식").

### 5-3. 동작
1. 룰렛 화면 진입 → **룰렛 준비** (5-2): 게임 화면은 원판 미리보기만 (목록은 진행자 화면 — R-72). 대표 호출("팀마다 두 분씩 나와 주세요" — 사진 릴레이, R-62)은 화면에 띄우지 않고 진행자가 말로 한다 — 대표 호출과 카테고리 고르기 중 무엇을 먼저 할지는 현장에서 정함 (`D-4`).
2. 진행자가 **진행자 화면**의 목록에서 [넣기/빼기] 한다 — 게임 화면 원판이 바로 바뀐다. 게임 창 키로는 넣고 빼지 않는다 (R-72).
3. 진행자 화면 [룰렛 돌리기] (비상용 `Enter` — 언제나 무작위) → 원판이 커지며 회전 시작.
4. 결과 카테고리는 **회전 시작 순간 먼저 결정**한다 — 무작위, 진행자 화면에서 결과를 지정했으면 그 카테고리 (R-48, [12-host-view.md](12-host-view.md) 4-8). 원판은 그 조각에 멈추도록 회전 각도를 계산한다 (조각 안 멈춤 위치도 무작위 — 경계에 걸쳐 보이지 않게 조각 폭의 15~85% 지점). 조각 수와 상관없이 같은 계산이라 몇 칸이든 정한 조각에 멈추고, 결과를 지정해도 바퀴 수 · 회전 시간 · 멈춤 위치는 무작위라 모니터만 봐서는 구분되지 않는다.
5. 회전: 4~6초 (무작위), 최소 4바퀴, 감속 곡선(ease-out cubic). 회전 중 상단 포인터가 조각 경계를 지날 때마다 살짝 튕기는 효과.
6. 정지 후: 당첨 조각 강조(밝게 + 테두리) → 0.5초 뒤 화면 가운데 큰 카드 "ROUND 2 · 🎬 영화 · 드라마 제목" 팝업.
7. 진행자 선택
   - [확정] (비상용 `Enter`, R-79): 라운드 소개 화면 (룰렛형은 주제 카드)
   - [다시 돌리기] (비상용 `Backspace`, R-84 — 예전 `Space` 는 R-79 에서 없앰): **룰렛 준비로 돌아감** (선택 유지, 방금 결과는 버림) → 필요하면 빼고 다시 [룰렛 돌리기]. 횟수 제한 없음
8. 확정 시 그 카테고리에서 라운드 문제를 뽑아 세션에 고정한다 (5-4, 득점형만).

- 룰렛 화면 헤더: 득점형 = "ROUND 2 카테고리 추첨", `roulette` = "주제 추첨" (팀 · 차례 · 횟수 없음 — `D-7`).
- 회전 중에는 `Esc` 외 키 무시 (메뉴는 ☰ 로). 회전 중 메뉴를 열면 회전은 계속되고, 닫으면 결과가 보인다.
- 새로고침 시: 확정 전이면 룰렛 준비 상태로 복귀 (선택 유지). 확정 후면 라운드 소개로 복귀.

### 5-4. 라운드 문제 뽑기
- 대상: 해당 카테고리에서 `disabled` 가 아니고 **이 게임에서 아직 출제하지 않은** 문제. 같은 카테고리가 다시 나와도 같은 문제는 한 게임에서 두 번 나오지 않는다.
- 문제 순서 = **랜덤 (기본)**: 대상 문제 중 무작위로 `라운드당 문제 수` 개를 뽑아, 뽑힌 순서대로 출제한다. 등록한 순서와 상관없다.
- 문제 순서 = 작성 순서: 대상 문제를 데이터(어드민 목록) 순서대로 앞에서 `라운드당 문제 수` 개. 같은 카테고리가 다시 나오면 지난번 다음 문제부터 이어진다.
- 릴레이(R-62)도 `라운드당 문제 수`만큼 뽑는다 (R-95 — 전에는 라운드당 문제 수를 쓰지 않고 최소 수만 뽑았다). 다만 순위가 정해지는 최소 수 **(팀 수 − 1) × 대표 수** (3팀 × 2명 = 4)보다 적게는 뽑지 않고, 카테고리에 남은 만큼만. 순위가 정해지면 다 내지 않아도 라운드 종료. 다 내도 순위가 안 정해졌으면 [다음 문제 ▶] 때 같은 카테고리에서 하나씩 더 뽑아 목록 끝에 붙인다 (같은 랜덤 / 작성 순서 규칙). 라운드를 끝낼 때 뽑아 두고 안 낸 문제는 목록에서 빼 다음 라운드 · 후보로 돌려놓는다.
- 뽑은 문제 id 목록을 세션에 저장 → 새로고침 · 이전 이동에도 같은 문제 · 같은 순서.
- 무작위는 매 게임 새로 뽑는다 (고정 시드 없음). 같은 설정으로 새로 시작해도 출제 문제 · 순서가 달라진다.

### 5-5. 문제가 모자랄 때

같은 카테고리가 여러 번 나올 수 있으므로, 한 카테고리의 남은 문제가 라운드 분량보다 적어질 수 있다.

| 상황 | 처리 |
| --- | --- |
| 남은(미출제) 문제 수 < 라운드당 문제 수 | 남은 문제만으로 라운드 진행. 라운드 소개에 실제 문제 수 표시 ("총 2문제") |
| 어떤 카테고리의 남은 문제 0개 | 룰렛 준비 목록에 "모두 출제함" 표시, 원판에 넣을 수 없음 (5-2) |
| 모든 카테고리의 남은 문제 0개 | 룰렛 준비 대신 "더 출제할 문제가 없습니다" 안내 → 진행자 [결과 보기 ▶] (비상용 `Enter`, R-79) 로 결과 화면 |
| (릴레이, R-62) 남은 문제 < (팀 수 − 1) × 대표 수 | 그 카테고리는 쓸 수 없다 — 게임 홈 "문제 3개 · 4개 필요", 룰렛 준비 "⊘ 부족" (5-2). 앞 라운드에서 써서 모자라진 것도 같다 (`D-33`) |
| (릴레이) 모든 카테고리가 부족 | "더 출제할 문제가 없습니다" → 결과. [한 라운드 더 ▶] 도 막힘 |
| (릴레이) 라운드 도중 그 카테고리 문제가 떨어짐 (정답자 없음이 많을 때) | 거기서 라운드 종료 — 대표를 다 내보내지 못한 팀은 맞힌 대표 수로 등수 (같으면 공동). 진행자 화면이 "이 카테고리에 낼 문제가 없습니다" 안내 (6장) |

- 예방: 카테고리당 문제를 `라운드당 문제 수 × 2` 개 이상 등록하는 것을 권장한다 (같은 카테고리가 두 번 나와도 부족하지 않게). 릴레이(3팀 × 2명)는 최소 4개, 정답자 없음 대비 6개 이상, 두 번 뽑혀도 되려면 8 ~ 12개 ([games/photo-quiz.md](games/photo-quiz.md) 8장). 관리 화면 문제 목록 상단에 "현재 문제 7개 · 라운드 1.4회 분량" 처럼 안내한다 ([04-admin.md](04-admin.md)).

## 6. 라운드 진행

- 라운드 소개 → 문제 → 정답 → 다음 문제 … 의 진행은 게임 종류별 문서를 따른다 (사진 보고 맞추기: [games/photo-quiz.md](games/photo-quiz.md), 이모티콘 퀴즈: [games/emoji-quiz.md](games/emoji-quiz.md)).
- 라운드 마지막 문제의 정답을 공개하면 진행자 화면에 먼저 **"라운드가 종료되었습니다"** 안내 — 문제를 더 낼지 여기서 끝낼지 묻는다 (R-56, [12-host-view.md](12-host-view.md) 4-9).
  - **[한 문제 더 ▶]** (게임 화면 키 없음 — `N` 은 R-85 에서 없앰) — 같은 카테고리에서 안 낸 문제를 하나 더 내고 이 라운드를 이어 간다 (몇 번이든, 남은 문제가 있는 동안 — R-43). 그 문제의 정답을 공개하면 다시 묻는다.
  - **[라운드 종료 ▶]** (비상용 `Enter`, R-85) — 게임 화면에 **라운드 종료 화면**: "라운드가 종료되었습니다" + 팀별 이번 라운드 점수 · 누적 ([05-screens.md](05-screens.md) 4-11).
- **릴레이 (사진 보고 맞추기, R-62)** 는 라운드 끝이 "마지막 문제" 가 아니라 **한 팀만 남았을 때**다 — 그 정답 화면에서 진행자 화면에 "🏁 순위가 정해졌습니다 — 1등 팀A · 2등 팀B · 3등 팀C" + [라운드 종료 ▶]. 그 전에는 [다음 문제 ▶] — 뽑아 둔 문제를 다 냈으면 같은 카테고리에서 하나 더 뽑는다 (5-4). 카테고리 문제가 떨어졌으면 "🏁 이 카테고리에 낼 문제가 없습니다 — 대표를 다 내보내지 못한 팀은 맞힌 대표 수로 등수" + [라운드 종료 ▶]. [한 문제 더 ▶] 는 없다. 라운드 종료 화면은 "이번 라운드 순위" (팀별 등수 · 맞힌 대표 n/n).
- 라운드 종료 화면에서 (비상용 `Enter`, R-85)
  - 남은 라운드 있음 → 진행자 화면 [다음 라운드 ▶] → 룰렛 준비 (현재 정답 수 요약을 룰렛 화면 하단에 표시 — 릴레이는 팀별 게임 점수)
  - 남은 라운드 없음 → 진행자 화면 [결과 보기 ▶] → 최종 결과. 그 옆 **[한 라운드 더 ▶]** (게임 화면 키 없음 — `Shift+N` 은 R-85 에서 없앰) — 누르면 룰렛 준비로 가서 한 라운드를 더 한다. 몇 번이든 되고, 남은 문제가 없으면 버튼이 없다 (R-40)
  - 진행자 화면 [◀ 라운드로 돌아가기] (게임 화면 키 없음 — R-74) — 그 라운드 마지막 문제의 정답 화면으로 (맞힌 팀 고치기 · 한 문제 더)
- 문제 진행은 진행자 화면 버튼으로 한다 (R-26, R-29): (진행자가 말로 판정) → [정답 공개] (맞힌 팀이 있든 이 문제를 끝내기로 했든) → 맞힌 팀 선택 · [없음] → [다음 문제 ▶]. 게임 화면에는 버튼이 없다.
- 진행자가 언제든 **[종료]** (게임 화면 키 없음 — R-77 · R-80) → 확인 "게임을 종료하고 결과를 볼까요?" → 결과 화면 (팀별 맞힌 개수 · 1 · 2 · 3등).

## 7. 최종 결과 (R-22)

- 퀴즈 게임 결과는 **팀별 정답 수와 정답 수 순서**만 보여준다. 종합 점수(100 / 50 / 0 등)는 계산하지 않는다 ([games/README.md](games/README.md) 3장, [05-screens.md](05-screens.md) 4-8).
- 예외 — 사진 보고 맞추기 릴레이 (R-62): 순위 = 라운드마다 등수의 배점(배점표 사진 행)을 더한 **게임 점수**. 라운드별 표는 정답 수 대신 등수 ("1등"). 게임 점수가 같으면 아래 추가 문제.
- 정답 수가 같은 팀이 있으면 모두 공개 후 "동점! 추가 문제로 순위를 정합니다" (R-85 — 예전 "동점! S 키로 추가 문제") — 진행자가 진행자 화면에서 이 게임에서 아직 안 나온 문제를 카테고리 → 문제로 골라 열고 (R-54 — 게임 창 `S` 는 R-85 에서 없앰) 동점 팀끼리 선착순으로 가린다 (`D-3`, [games/README.md](games/README.md) 3장).
- 모두 공개 후 **라운드(카테고리)별 정답 수 표**를 함께 보여준다 — 진행자가 종합 점수판에 라운드별 등수를 입력할 때 쓴다 ([13-scoreboard.md](13-scoreboard.md) 10장).
- 결과 화면에서 할 수 있는 것
  - 진행자 [다음 순위 공개] (비상용 `Enter`, R-85): 하위 순서부터 차례로 공개
  - 모두 공개 직후 "종합 점수판에 채울까요?" — [확인] 자동 입력 / [점수 고치기] 고쳐서 입력 / [취소] 나중에 메뉴로 수동 입력 (`D-18`, [13-scoreboard.md](13-scoreboard.md) 10장)
  - 게임 화면(모니터)에는 버튼이 없다 (R-26). 점수판 채우기는 진행자 화면 창에서, 다른 화면으로는 ☰ 메뉴로 이동한다 ([05-screens.md](05-screens.md) 4-8)
- 결과까지 본 세션은 "완료" 상태로 저장 → 게임 홈에서 [새로 시작] 만 표시 (이어하기 없음), 완료 결과는 "지난 결과 보기" 로 열람 가능.

## 8. 공개 모드 `/play` (R-96 · R-97 · R-98 · R-99, `D-37`)

행사(10/29)가 끝난 뒤 **누구나 PIN 없이 게임을 혼자 해 보는** 별도 페이지. 관리 페이지에서 켜고 끈다 ([04-admin.md](04-admin.md) 3-16). 행사용 게임 화면 `/` · 진행자 화면 `/host` · 관리 페이지 `/admin` 은 켜도 PIN 그대로다. 공개하는 게임은 **이모티콘 퀴즈 · 사진 보고 맞추기** — 줄줄이 말해요는 팀원이 차례로 이어 말하는 게임이라 혼자 할 수 없어 뺀다 (R-97).

```
/play ── 꺼져 있음 ─▶ "지금은 공개하지 않습니다"
  │
  ▼ 켜져 있음
[게임 목록]  게임 카드 (아이콘 · 이름 · 설명 · 카테고리 n개 · 문제 n개 · ✔ 다 푼 카테고리 n / N)
  │ 카드 클릭 · 방향키 + Enter                                     ▲ Esc
  ▼                                                               │
[카테고리 목록]  게임 머리 · 혼자 하는 방법 · 카테고리 카드 (문제 n개 · 이어하기 n / N · ✔ 다 풂)  ◀──┐
  │ 카드 클릭 · 방향키 + Enter                                                              │ Esc
  ▼                                                                                       │
[문제] ─ [💡 힌트 (n)] H ─▶ 한 단계 힌트 (다 쓰면 힌트 글)                                       │
  │ [정답 보기] Enter                                                                     │
  ▼                                                                                       │
[정답] (정답 영상이 있으면 영상 → [⏭ 영상 넘기기]) ── [다음 문제 ▶] Enter ─▶ 다음 [문제] … ──────┤
  ▼ 마지막 문제 [끝 ▶]                                                                       │
[모두 풀었습니다 — <게임> · <카테고리>]  [다시 풀기] · [카테고리 목록] Enter ──────────────────────┘
```

- **카테고리 고르기 (R-98)**: 게임을 고르면 카테고리 목록이 나온다 (게임 소개를 겸함). 카테고리를 고르면 **그 카테고리의 숨기지 않은 문제 전부**를 관리 페이지의 문제 순서대로 낸다 (작성 순서면 데이터 순서, 무작위면 섞어서 — R-102) — 룰렛 · 라운드가 없고 다른 카테고리 문제는 섞이지 않는다. 다 풀면 카테고리 목록으로 돌아와 다른 카테고리를 고른다. 숨긴 카테고리 · 문제는 나오지 않고, 낼 문제가 없는 카테고리 · 게임은 빠진다.
- **팀 · 점수가 없다**: 맞힌 팀 · 맞힌 사람 · 점수 띠 · 결과 · 점수판 채우기 · 진행자 화면 연결이 없다. 서버의 현장 상태(팀 설정 · 진행 기록 · 종합 점수판)는 읽지도 쓰지도 않는다 — 행사 기록은 그대로 남는다.
- **이어하기 · 다 풂**: 카테고리마다 문제 순서와 위치를 **그 브라우저에만** 저장한다 (`localStorage` `camp-game:play:v2:<게임 id>:<카테고리 id>`). **정답을 본 문제는 푼 것으로** — [정답 보기] 하는 순간 다음 문제로 저장해, 거기서 나가거나 새로고침하면 다음 문제부터 (R-99). 풀던 카테고리를 다시 고르면 그 위치부터 — 그 사이 관리 페이지에서 숨긴 문제는 빼고, 새로 넣은 문제는 다시 풀 때 들어간다. 마지막 정답을 보면 "다 풂" 으로 바뀌고, 다 푼 카테고리를 다시 고르면 새 판. 풀던 중에 처음부터 하려면 문제 화면 [↺ 처음부터] (R-99). 문제 순서 설정이 바뀐 뒤 풀던 카테고리를 열면 바뀐 순서로 1번부터 (R-102). 이 브라우저의 진행을 모두 지우려면 게임 목록 [↺ 이어하기 초기화] (R-103 — 확인창을 거친다).
- **주소 · 뒤로 가기 (R-99)**: 화면 위치를 주소에 남긴다 — `/play` 게임 목록, `/play#<게임 id>` 카테고리 목록, `/play#<게임 id>/<카테고리 id>` 문제 (문제 → 다음 문제는 주소 그대로). 브라우저 뒤로 가기는 `Esc` 처럼 한 단계 위로, `Esc` · [☰ …목록] 으로 올라가도 기록이 쌓이지 않는다. 새로고침하거나 주소로 바로 들어와도 그 화면 (풀던 카테고리는 이어서, 다 푼 카테고리는 "모두 풀었습니다"). 없는 게임 · 카테고리 주소(숨김 · 오타)면 한 단계 위로.
