# 12. 진행자 화면 — 정답지 · 진행 조작 패널 (R-19, R-20, R-26, R-29, R-30, R-36)

## 1. 목적

- 모니터에 나오는 게임 화면은 참가자용이라 정답 공개 전에는 정답이 없다. 진행자는 판정을 위해 **지금 나오고 있는 문제의 정답을 미리** 알아야 한다 (`D-12`).
- 그래서 게임 화면과 별도로 **진행자 화면**(`/host`)을 연다. 게임 화면이 바뀌면 진행자 화면도 실시간으로 따라 바뀐다.
- **진행 조작은 모두 진행자 화면 버튼으로 한다** (R-26, R-29): [정답 공개], 정답 공개 후 **맞힌 팀 지정**(어느 팀에 1개를 셀지), [다음 문제], [종료], 룰렛 조작, 결과 공개, 점수판 채우기. 정답 · 오답 판정 버튼은 두지 않는다.
- **게임 화면(모니터)에는 진행용 버튼을 두지 않는다.** 참가자에게 보이는 화면은 보여주기 전용이다. 게임 화면 키보드 단축키([06-controls.md](06-controls.md))는 진행자 화면을 못 쓸 때를 위한 **비상용**으로만 남긴다.
- 인쇄용 정답지(이전 스펙의 `P` 키)는 이 화면으로 대체하고 만들지 않는다.

## 2. 화면 배치

### 2-1. 권장: 디스플레이 "확장" 모드 (노트북 1대)

```
┌────────────── 외부 모니터 (참가자) ──────────────┐   ┌──── 노트북 화면 (진행자) ────┐
│                                                  │   │ 진행자 화면 (/host)           │
│   게임 화면 (전체화면, 버튼 없음)                  │   │  Q3 · 정답: 초계국수           │
│                                                  │   │  [정답 공개] → 맞힌 팀 [A][B][C]│
│                                                  │   │  [다음 문제]   [종료]          │
│                                                  │   │ ───────────────────────────── │
│                                                  │   │ 터미널 (서버 · PIN)            │
└──────────────────────────────────────────────────┘   └───────────────────────────────┘
```

- macOS 디스플레이 설정에서 **미러링을 끄고 확장 모드**로 둔다. 게임 창은 외부 모니터로 옮겨 전체화면(`F`), 진행자 화면 창은 노트북 화면에 둔다.
- ⚠ **미러링 모드로는 쓸 수 없다** — 진행자 화면(정답)이 모니터에도 그대로 나온다. 반드시 확장 모드.
- 서버는 노트북 안(`127.0.0.1`)에서만 열린다. 네트워크(와이파이 · 핫스팟)가 전혀 필요 없다.

### 2-2. 진행자 여러 명이 휴대폰으로 — 서버 모드 (R-36)

- 앱을 서버(Vercel — R-51)에 올려 두면([08-tech.md](08-tech.md) 11장) 진행자 여러 명이 **각자 휴대폰으로** 진행자 화면을 연다.
- 휴대폰은 캠핑장 와이파이가 아니라 **모바일망(LTE · 5G)** 으로 공개 주소에 붙는다. 노트북과 휴대폰이 같은 네트워크에 있을 필요가 없다 (R-30 에서 휴대폰 접속을 뺀 이유였던 문제가 없다).
- 게임 화면(모니터에 연결한 노트북)도 같은 서버 주소를 브라우저로 연다. 노트북도 인터넷에 붙어 있어야 한다. 화면 배치는 2-1 과 같다 — 노트북 화면에도 진행자 화면을 띄워 둘 수 있다.

```
 휴대폰 (진행자 1) ─┐
 휴대폰 (진행자 2) ─┼─ LTE · 5G ─▶ 서버 (공개 주소 + PIN) ◀─ 인터넷 ─ 노트북 ─▶ 모니터
 노트북 창 (선택)  ─┘                                             (게임 화면)
```

- 휴대폰 화면 폭(360px~)에서도 정답 · 버튼이 한 열로 보이게 한다. 버튼 크기는 4-1 그대로(높이 56px 이상).
- 진행자 화면 여러 개가 동시에 열려 있어도 된다 (7장) — 누가 눌러도 같은 명령이고, 겹친 명령은 `basedOn` 검사로 하나만 적용된다.
- 행사 전에 진행자마다 휴대폰으로 한 번 입장해 홈 화면에 추가해 둔다 ([manual.md](manual.md) 2장).

### 2-3. 노트북 모드에서 다른 기기에 띄우고 싶을 때 (선택 — 앱 기능 아님)

- 노트북 모드(`start.command`, 서버가 `127.0.0.1` 에만 열림)는 휴대폰 접속 기능이 없다. 서버를 쓸 수 없을 때의 비상용이다.
- 진행 노트북이 맥북이므로, 필요하면 **macOS 기능**으로 해결한다. 진행자 화면은 맥의 브라우저 창이라 디스플레이만 늘리면 그 창을 옮기면 된다.
  - **iPad 가 있으면 Sidecar**: iPad 를 맥의 디스플레이로 붙이고 진행자 화면 창을 iPad 로 옮긴다. 같은 Apple ID 필요, USB 케이블로도 연결 가능 — 공유기 · 인터넷 불필요.
  - **iPhone 은 맥 화면을 받는 기본 기능이 없다** (macOS "iPhone 미러링" 은 반대로 iPhone 화면을 맥에 띄우는 기능).

## 3. 여는 방법

| 방법 | 동작 |
| --- | --- |
| 게임 화면 ☰ → "진행자 화면" | 새 창으로 `/host` 열기 → 창을 노트북 화면으로 옮김 |
| 주소 직접 입력 | 노트북 모드: `http://127.0.0.1:1029/host` (노트북에서만) |
| 휴대폰 (서버 모드) | 서버 주소 + `/host`. 홈 화면에 추가해 두면 편하다 |

- 처음 열면 PIN 입력 화면 → 6자리 PIN 입력 → 진행자 화면 (5장). PIN 은 노트북 모드면 터미널에 표시된 값, 서버 모드면 운영자가 정해 둔 고정 PIN.

## 4. 화면 구성

### 4-1. 레이아웃

문제 진행 중:

```
┌────────────────────────────────────────────────────────────────┐
│ 📸 사진 보고 맞추기 · ROUND 2 · 🔍 확대 음식      ● 실시간 [가리기] │
├────────────────────────────────────────────────────────────────┤
│ Q 3 / 5                              문제 진행 중 · 확대 1/3 단계 │
│ ┌──────────┐  이 음식은 무엇일까요?                              │
│ │ (썸네일) │  정답   초계국수                                     │
│ └──────────┘  메모   '닭국수' 는 불인정    힌트  여름 · 차가운 면  │
├────────────────────────────────────────────────────────────────┤
│ 화면        [🔍 힌트 단계 ▶]  [💡 힌트]                        │
│ 진행        [ 정답 공개 ]   [ 다음 문제 ▶ ]   [종료]               │
├────────────────────────────────────────────────────────────────┤
│ 이번 라운드  1 ✔ 떡볶이 (팀A)  2 ✔ 짜장면 (-)  ▶3 초계국수  4 …   │
│ 정답 수  팀A 3 · 팀B 2 · 팀C 1                                 │
└────────────────────────────────────────────────────────────────┘
```

정답 공개 후 — **맞힌 팀 지정** 구역이 열린다 (4-3):

```
├────────────────────────────────────────────────────────────────┤
│ 맞힌 팀     [ ● 팀A ]  [ ● 팀B ]  [ ● 팀C ]   [ 없음 ]            │
│             (지금: 팀B ✔ — 다른 팀을 누르면 바뀜)                  │
│ 진행        [ 다음 문제 ▶ ]   [종료]                                │
├────────────────────────────────────────────────────────────────┤
```

| 구역 | 내용 |
| --- | --- |
| 머리줄 | 게임 아이콘 · 이름 · 라운드 · 카테고리, 연결 상태(● 실시간 / ○ 재연결 중), [📝 정답 기록] (득점형 진행 중, 4-10 — R-60), [가리기] |
| 현재 문제 카드 | 번호 · 진행 상태(문제 진행 중 / 정답 공개됨) · 연출 상태(확대 n/m 단계, 가림 n/m 제거, 이모지 n/m 공개) · 썸네일 · 질문 문구 · **정답(가장 크게)** · 메모(`note`) · 힌트. 번호 배지는 "Q 3 / 5" — 릴레이(R-62)는 문제 수 대신 "Q 3 · 팀당 대표 2명" (인당 문제가 2 이상이면 "Q 3 · 대표 2명 × 2문제", R-64) |
| 화면 | [힌트 단계 ▶] (게임 화면 키 없음, R-78 — 확대 축소 · 가림 제거(마지막 상자는 정답 공개 때, 상자 1개면 버튼 없음 — R-42) · 이모지 하나 더), [◀], [💡 힌트] 표시 · 숨김 (게임 화면 `Z` · `Shift+Z` · `H` 는 R-78 에서 없앰). 타이머는 없다 (R-33) |
| 맞힌 팀 | **정답 공개 후에만** 나타난다. 팀 버튼 + [없음] (4-3). 릴레이는 대표를 모두 내보낸 팀 버튼이 꺼지고, 아래에 진행 줄 (4-3). 사진 팀당 대표 방식은 "맞힌 사람" — 팀마다 [대표1] [대표2] (R-94, 4-3) |
| 정답 영상 (R-61) | 정답 영상이 있는 사진 문제만 — 맞힌 팀 아래(공개 전에는 현재 문제 카드 아래) "🎬 정답 영상 — 1:23 – 1:35 (12초)" 카드. 현재 문제 카드에도 "🎬 정답 영상" 배지. **정답 공개 전**: "정답 공개 때 모니터에서 자동으로 재생되고, 영상이 끝나면 정답 글자가 나옵니다" + 경고 — 게임 화면을 연 뒤 아직 한 번도 클릭 · 키 입력이 없으면 "⚠ … 브라우저가 영상 소리를 막을 수 있습니다 — 게임 화면(모니터)을 한 번 클릭하세요", 유튜브가 이미 못 튼다고 알려 왔으면 그 이유 + "정답 공개 때 영상 없이 정답 글자를 바로 보입니다". **정답 공개 후**: 모니터 재생 상태(⏳ 불러오는 중 · ▶ 재생 중 · ⏸ 일시정지 · ✔ 영상 끝 · ⚠ 못 틀었을 때 이유) + 버튼 — 재생 중 [⏸ 일시정지] · [⏭ 영상 끝내기 (정답 글자 보이기)], 일시정지 [▶ 계속] · [⏭ 영상 끝내기], 끝난 뒤 · 못 튼 뒤 [↺ 영상 다시 재생], 정답 화면으로 바로 들어와 아직 안 틀었으면 [▶ 영상 재생]. 소리가 막혀 소리 없이 도는 중이면 "🔇 … 게임 화면(모니터)을 한 번 클릭하면 소리가 켜집니다" ([games/photo-quiz.md](games/photo-quiz.md) 5-5) |
| 진행 | [정답 공개] (공개 전) · [다음 문제 ▶] · [종료] (4-4). [↶ 되돌리기] 는 없다 — 지난 문제는 [📝 정답 기록] 에서 고친다 (R-60) |
| 이번 라운드 목록 · 정답 수 | 번호 · 정답 · 맞힌 팀. 지난 문제는 흐리게, 현재 문제 ▶. 팀별 정답 수. 아직 안 낸 문제마다 **[다음으로]** — 누르면 그 문제가 바로 다음 차례로 옮겨진다 (나머지는 한 칸씩 밀림, R-35). 다음 차례인 문제에는 "다음" 표시. 목록 아래 **후보** — 이번 라운드 카테고리에서 라운드에 안 뽑힌 · 이 게임에 아직 안 낸 문제를 정답과 함께 모두 (데이터 순서). 후보마다 **[다음으로]** — 누르면 바로 다음 차례로 들어가고 이번 라운드의 마지막 문제가 후보로 돌아간다 (문제 수 그대로, 지금 문제가 라운드 마지막이면 한 문제 더 — R-52, `D-31`). 후보 제목줄에 무엇이 바뀌는지 안내. 남은 문제가 없으면 후보 칸 없음. 아래 팀별 점수 줄은 정답 수 — 릴레이(R-62)는 라운드 중에는 팀별 "맞힌 대표 1/2" (다 내보냈으면 "2/2 🥇1등" — 인당 문제가 2 이상이면 맞힌 문제 수 "3/4", R-64 — R-94 부터 대표마다 ●○ 묶음 "3/4 · ●● ●○"), 룰렛 · 라운드 종료 · 결과에서는 게임 점수 "150점" |
| 크기 | 버튼 높이 56px 이상 (트랙패드로 빠르게 누를 수 있게, 휴대폰 · Sidecar 터치도 고려). 정답 글자 48px 이상. 휴대폰 폭(760px 미만)에서는 표 · 버튼을 한 열로 쌓는다 (2-2) |
| 색 | 게임 화면과 같은 어두운 테마. 정답 · 주요 버튼만 `--accent`, 팀 버튼은 팀 색, [종료] 는 `--danger` 테두리 |

### 4-2. 게임 화면 상태별 표시 · 버튼

| 게임 화면 상태 | 진행자 화면 표시 | 버튼 |
| --- | --- | --- |
| 제목 · 메뉴 · 게임 홈 · 배점표 · 종합 점수판 | "진행 중인 문제가 없습니다" + 마지막 게임 이름 | 없음 (게임 시작은 게임 창 ☰ 메뉴 · 게임 홈에서) |
| 룰렛 준비 (득점형) | "ROUND 2 카테고리 고르기" — 카테고리 목록(넣음/빠짐 · 남은 문제 수 · 당첨 횟수) · **결과 지정** 줄 (4-8). 릴레이(R-62)는 한 라운드에 모자란 카테고리가 "부족 · 남은 3/4" 로 꺼져 있고 (넣기 · 결과 지정 불가) 아래 "팀당 대표 2명 — 남은 문제가 4개보다 적은 카테고리는 이 게임에서 쓰지 않습니다". 넣을 수 있는 카테고리가 하나도 없으면 "더 출제할 문제가 없습니다" + "한 라운드(4문제)를 낼 만큼 문제가 남은 카테고리가 없습니다" + [결과 보기 ▶] (`D-33`) | 항목마다 [넣기/빼기], [모두 넣기], 결과 지정 [무작위] · 넣은 카테고리마다 (R-48), **[룰렛 돌리기]** |
| 문제 고르기 (이모티콘 퀴즈 — R-90, 원판 없음) | "문제 고르기 — 모니터: 카테고리 목록 · 낸 문제 n개" + 카테고리 버튼(남은 n) → 고른 카테고리의 남은 문제 목록(이모지 · 정답 — 가리기 `B` 대상) — 4-11. 다 냈으면 "더 출제할 문제가 없습니다" | 문제 [내기] (`question.pick {questionId}`), [종료] · (다 냈으면) [결과 보기 ▶] |
| 주제 고르기 (룰렛형 — R-65, 원판 없음) | "주제 고르기 — 누르면 바로 모니터에 공개됩니다" + 안내(누르면 모니터에 그 주제 카드 · 문제가 있는 주제는 규칙을 설명한 뒤 [첫 문제 ▶] — 문제는 진행자 화면에만 · 고르기 전까지 모니터에 후보가 안 보임). 주제 버튼 목록 (가리기 `B` 대상): 아이콘 · 이름 · "문제 n" / "문제 모두 냄" · ×고른 횟수. 무작위 후보(문제를 다 내지 않은 주제)는 밝게, 나머지는 흐리게 — 흐린 것도 누를 수 있다. ### 4-11. 이모티콘 퀴즈 문제 고르기 (R-90)

룰렛 · 라운드 없이 진행자가 문제를 하나씩 골라 낸다 ([games/emoji-quiz.md](games/emoji-quiz.md) 3장).

| 화면 | 진행자 화면 |
| --- | --- |
| 문제 고르기 (모니터 카테고리 목록) | 카드 "문제 고르기 — 모니터: 카테고리 목록 · 낸 문제 n개" — 카테고리 버튼(아이콘 · 이름 · "남은 n") 을 누르면 그 카테고리의 남은 문제가 데이터 순서로 (번호 · 이모지(이미지 문제는 🖼) · 정답 · [내기]). 다시 누르면 접힘. [종료] |
| 문제 | 문제 카드(배지 "n번째 문제" — 문제 수 대신) · [힌트 단계 ▶] · [💡 힌트] · [정답 공개] · [종료]. 문제 목록은 없다 (공개 전에는 다음 문제를 고를 수 없음) |
| 정답 | 맞힌 팀 · [없음] · [카테고리 목록 ▶] (`question.next` — 모니터를 문제 고르기로) · [종료] + 아래 "다음 문제 고르기" 카드 (위와 같은 목록 — [내기] 하면 바로 다음 문제). 맞힌 팀도 [없음] 도 정하지 않고 [내기] 하면 "맞힌 팀 확인" 창 → [넘어가기] 면 같은 명령을 `noCredit` · `key` 를 붙여 다시 보낸다 (R-87 과 같음) |

- 고른 카테고리는 그 진행자 화면 창에만 기억한다 — 그 카테고리 문제를 다 내면 처음(카테고리 버튼만)으로.
- 머리줄은 "😀 이모티콘 퀴즈 · 🎬 영화" (ROUND 없음). 라운드 목록 · [다음으로] · 라운드 종료 안내 · [한 문제 더] · [한 라운드 더] · [팀 점수에 반영] 은 없다.

### 4-3. 맞힌 팀 지정 — 정답 공개 후 카운팅 (R-29)

정답 · 오답을 문제 도중에 판정하지 않는다. 진행자는 말로 판정하고, **정답을 공개한 뒤 이 문제를 맞힌 팀을 골라** 1개를 센다.

| 버튼 | 동작 |
| --- | --- |
| [팀A] [팀B] [팀C] (팀 색) | 그 팀 **정답 수 +1**. 문제당 맞힌 팀은 1팀 (선착순, `D-2`) — 이미 다른 팀이 지정돼 있으면 그 팀 −1, 새 팀 +1 (정정). 게임 화면 정답 아래 "✔ 팀A +1" 표시 |
| 같은 팀 다시 | 변화 없음 |
| [없음] | 아무도 못 맞힘 — 지정돼 있던 팀이 있으면 그 팀 −1, 정답 아래 "정답자 없음" |
| 정답 공개 전 | 맞힌 팀 구역이 보이지 않는다 (카운팅 불가) |
| 지난 문제 고치기 | 머리줄 [📝 정답 기록] (4-10, R-60) — 이 게임에서 낸 문제마다 팀 버튼 · [없음] 으로 바로 고친다. 게임 화면은 지금 화면 그대로. (비상용: 게임 화면을 이전 문제의 정답 화면으로 돌리기 `←` · 마지막 점수 변경 되돌리기 `Backspace`) |

- 추가 문제(동점 처리)에서는 동점 팀 버튼만 나온다 (`D-3`).
- **릴레이 (R-62, 사진)**: 이 문제 전에 대표를 모두 내보낸 팀 버튼은 "팀A 🥇1등 · 빠짐" 으로 꺼져 있다 (명령이 와도 무시). 버튼 아래 진행 줄 "팀당 대표 2명 — 팀A 2/2 🥇1등 · 팀B 1/2 · 팀C 0/2". 이 문제로 대표를 모두 내보낸 팀은 아직 버튼이 살아 있어 다른 팀으로 바꿀 수 있다 (다음 문제부터 꺼짐). 추가 문제에는 이 제한이 없다.
- ~~인당 문제 (R-64) 교체 안내 "🔄 팀A 대표1 — … 다음 문제부터 대표2 차례"~~ — R-94 로 없앰 (대표는 함께 나오고 차례가 없다).
- **맞힌 사람 (R-94, 사진 팀당 대표 방식)**: 구역 제목 "맞힌 사람 — 정답 공개 후 팀 · 대표를 누름". 팀 버튼 대신 **팀마다 한 줄** — 팀 이름(팀 색 왼쪽 띠) + [대표1 ●○] [대표2 ○○] (● = 그 사람이 이번 라운드에 맞힌 수, ○ = 남은 수 — 인당 문제만큼). 누르면 그 팀 · 대표가 맞힌 것으로 (`answer.credit {team, rep}`), 고른 버튼은 "✔ 대표2 ●○". 같은 팀 다른 대표를 누르면 바뀐다. 이 문제 전에 인당 문제를 채운 대표는 "대표1 ●● 빠짐" 으로 꺼지고, 대표를 모두 내보낸 팀은 버튼 없이 "팀A 🥇1등 · 빠짐". [없음] 은 아래 줄. 상태 줄 "지금: 팀A 대표2 ✔ — 다른 사람을 누르면 바뀜", 진행 줄 "대표 2명 × 2문제 — 팀A 3/4 · ●● ●○ · 팀B 4/4 🥇1등 · …" (대표마다 ●○ 묶음). 고른 사람이 이 문제로 인당 문제를 채웠고 팀에 대표가 남았으면 그 아래 **빠짐 안내** "🚪 팀A 대표1 — 2문제를 다 맞혀 빠집니다" (인당 1 이면 "맞혀서 빠집니다") — 진행자가 말로 알린다. 게임 화면(모니터) 점수 띠의 대표 묶음 클릭도 같다 (05-screens 4-10).

### 4-5. 결과 화면 — 순위 공개 · 점수판 채우기

- [다음 순위 공개 ▶] 로 하위 순위부터 공개 (게임 화면 연출은 [05-screens.md](05-screens.md) 4-8).
- 모두 공개한 뒤 동점 그룹이 있으면 **추가 문제 고르기** 카드 (`D-3`, R-54) — 제목 "추가 문제 — 팀A · 팀B 동점" (먼저 가릴 그룹). ① 카테고리 버튼: 이 게임에 포함된 카테고리 중 남은 문제가 있는 것 (아이콘 · 이름 · 남은 n) → ② 그 카테고리의 남은 문제 목록 (정답, 데이터 순서), 문제마다 **[내기]** · [◀ 카테고리]. [내기] 를 누르면 그 문제가 게임 화면에 추가 문제로 열린다. 이 게임에서 이미 낸 문제(라운드 · 앞선 추가 문제)는 없다. 무작위 버튼은 없다 — 게임 창 `S` 가 비상용 무작위. 목록 · 정답은 [가리기] 대상. 후보가 없으면 "추가 문제가 없어 공동 순위로 정합니다".
- 모든 순위를 공개하면 **진행자 화면에** "종합 점수판에 채울까요?" 창이 뜬다 — [확인] / [점수 고치기] / [취소] (`D-18`, [13-scoreboard.md](13-scoreboard.md) 10장). 점수 고치기 창도 진행자 화면에서 연다. 참가자가 보는 모니터에는 띄우지 않는다.
- 진행자 화면이 연결돼 있지 않으면 이 창은 게임 화면에 뜬다 (비상용).
- 점수를 주는 게임 (R-49 — 점수판 "정답 수" 라운드가 게임 전체에 연결된 게임, 기본값 이모티콘 퀴즈): 결과 표에 **점수** 열(정답 수 × 1개당 점수), 아래 팀별 점수 띠도 "팀A 150점". 동점이어도 점수가 같으니 추가 문제 고르기를 내지 않는다. 채우기 창의 정답 수 행은 "3개 (150)", [점수 고치기] 는 칸마다 정답 수 입력 ("[3] 개 × 50"). 문제 진행 중의 팀별 띠도 점수로 보인다.
- 릴레이 (R-62, 사진): 결과 표의 "정답 수" 열 대신 **"게임 점수 (라운드 배점 합)"** ("150점" — 순위 기준), 아래 표는 **라운드별 순위** (값 "1등", 등수 없는 라운드 "-"). 게임 점수가 같으면 추가 문제 고르기를 그대로 낸다 (대표 규칙 없이 동점 팀 선착순).

### 4-6. 가리기
- [가리기] 버튼 또는 `B` 키 → 정답 · 메모 · 힌트 · 목록 · 룰렛 결과 지정(4-8)을 흐리게 가림 (다시 누르면 해제). 노트북 화면을 다른 사람이 볼 때 사용. 버튼은 그대로 누를 수 있다.
- 가리기 상태는 그 진행자 화면 창에만 적용 (다른 진행자 화면 창에는 영향 없음).

### 4-7. 설명서 (R-38)

- 머리줄 [❓ 설명서] → 진행자 화면 위에 **한 화면 분량의 요약 설명서**를 겹쳐 연다. 휴대폰 폭에서는 화면 전체, 넓은 화면에서는 가운데 창 (2열). [✕ 닫기] · `Esc` · 바깥 누르기로 닫는다. 열려 있어도 실시간 연결 · 게임 진행은 그대로.
- PIN 입력 화면에서도 [❓ 설명서] 를 열 수 있다 (입장 전에 미리 읽기).
- 내용 (관리 페이지와 같은 모듈 — [04-admin.md](04-admin.md) 3-12):

| 구역 | 내용 |
| --- | --- |
| 진행 순서 — 이모티콘 · 사진 | 룰렛 [넣기/빼기] → [룰렛 돌리기] → [확정] → [첫 문제 ▶] → 말로 판정 → [정답 공개] → 맞힌 팀 · [없음] → [다음 문제 ▶] … 라운드 끝 "라운드가 종료되었습니다" → [한 문제 더 ▶] 또는 [라운드 종료 ▶] → (모니터에 라운드 점수) [팀 점수에 반영] → [다음 라운드 ▶] … [결과 보기 ▶] → [다음 순위 공개 ▶] → (동점) 추가 문제 고르기 — 카테고리 → [내기] → 점수판 [확인]. 사진은 팀당 대표 2명 릴레이 — 맞힌 사람은 빠지고, 한 팀만 남으면 "순위가 정해졌습니다" → [라운드 종료 ▶], 모니터엔 순위 (R-62) |
| 줄줄이 말해요 | 주제 버튼 · [🎲 무작위] (원판 없음 — R-65) → 모니터에 주제 카드 (예시는 진행자 화면) → (문제가 있는 주제) 규칙 설명 뒤 [첫 문제 ▶] 또는 목록 [내기] → 진행자 화면에만 "노발○○" + 정답 후보 — 읽어 준다 → [다음 문제 ▶] … → 다음 팀 [다음 주제 ▶] (문제를 다 낸 주제는 무작위에서 빠짐) → [끝내기] |
| 규칙 | 먼저 외친 팀부터 · 말로 판정 · 문제당 1팀 · 감점 없음 · 타이머 없음. 사진은 대표가 모두 맞힌 순서가 라운드 등수 — 다 맞힌 팀 버튼은 꺼지고, 문제가 모자란 카테고리는 룰렛에 안 들어감, 결과는 라운드 배점 합 (R-62) |
| 버튼 | [힌트 단계 ▶] · [💡 힌트] · 정답 영상 [⏭ 영상 끝내기] · [⏸ 일시정지] · [↺ 영상 다시 재생] (R-61) · [📝 정답 기록] · [다음으로] · [종료] · [한 문제 더 ▶] · [라운드 종료 ▶] · [팀 점수에 반영] (4-9) · [한 라운드 더 ▶] · 룰렛 결과 지정 (4-8) · [가리기] · [나가기] (서버 모드: 모니터 노트북에서 누르지 않기) |
| 게임 화면 노트북에서 | ☰ → 게임 고르기 · [게임 시작] · 팀 설정 · 배점표 · 종합 점수판(발표 `P`) |
| 이럴 땐 | ○ 재연결 중 · "게임 화면과 연결되지 않았습니다" · "화면이 바뀌어 적용하지 않았습니다" · 맞힌 팀 실수 · 휴대폰이 안 될 때. 서버 모드는 인터넷 연결, 노트북 모드는 터미널(서버) 기준으로 안내 |
| 맨 아래 | 전체 설명서 링크 (저장소 [manual.md](manual.md), 새 탭) |

### 4-8. 룰렛 결과 지정 (R-48)

룰렛 결과는 회전을 시작하는 순간 먼저 정하고, 원판은 그 조각에 멈추도록 돈다 ([01-app-flow.md](01-app-flow.md) 5-3). 진행자가 그 결과를 미리 고를 수 있다. 득점형 카테고리 추첨 · 줄줄이 말해요 주제 추첨 모두, 원판 조각 수와 상관없이.

| 항목 | 규칙 |
| --- | --- |
| 자리 | 룰렛 준비 카드, 카테고리 목록 아래 **결과 지정** 줄 — [🎲 무작위] (기본) + 지금 원판 후보(넣은 카테고리, 득점형은 남은 문제가 있는 것)마다 버튼, 원판 순서대로 |
| 고르기 | 누르면 그 버튼이 켜지고 "지정: 🍪 과자 이름 — 이번 한 번만, 모니터엔 안 보임". 같은 버튼을 다시 누르거나 [무작위] 를 누르면 풀림 |
| 돌리기 | [룰렛 돌리기] 가 지정한 카테고리를 함께 보낸다 (`roulette.spin {categoryId}`, 6-2). 게임 화면은 그 조각에 멈추게 돈다 |
| 모니터 | 아무 표시 없음. 바퀴 수(4~6) · 회전 시간(4~6초) · 조각 안 멈춤 위치(15~85%)는 지정해도 무작위라 지정하지 않은 회전과 구분되지 않는다 |
| 한 번만 (`D-27`) | 회전이 시작되면(게임 화면이 회전 중 · 정지로 바뀌면) 지정은 [무작위] 로 돌아간다. [다시 돌리기] · 다음 라운드에서 또 지정하려면 다시 고른다 |
| 원판에서 빠지면 | 지정해 둔 카테고리를 [빼기] 하거나, 다른 진행자가 빼거나, 관리 페이지 저장으로 원판 후보에서 사라지면 지정도 풀린다 |
| 거절 | 명령이 도착했을 때 그 카테고리가 원판 후보가 아니거나 룰렛 준비가 아니면 돌리지 않는다 — 진행자 화면에만 "지정한 카테고리가 원판에 없습니다 — 다시 고르세요" (룰렛형은 "주제"). 무작위로 바꿔 돌리지 않는다. 그 사이 화면이 바뀌었으면 6-2 의 `basedOn` 검사로 "화면이 바뀌어 적용하지 않았습니다" |
| 원판 1개 | 지금처럼 회전 없이 그 카테고리 (지정해도 같음) |
| 비상용 키 | 게임 화면 `Enter`(돌리기)는 언제나 무작위 — 지정은 진행자 화면에만 |
| 남기지 않음 | 지정은 그 진행자 화면 창의 메모리에만 있다. 다른 진행자 화면에는 보이지 않고(그 화면에서 [룰렛 돌리기] 하면 무작위), 진행 기록 · 점수판 · 서버 터미널(명령 이름만 출력, 5-1)에도 남지 않는다. 새로고침하면 [무작위] |
| 가리기 | 결과 지정 줄은 [가리기] 대상 (4-6) — 버튼은 그대로 누를 수 있다 |

### 4-9. 라운드 종료 안내 · 라운드 점수 (R-56)

라운드 마지막 문제의 정답을 공개하면 진행자 화면에 **먼저** 라운드가 끝났다고 알리고, 문제를 더 낼지 여기서 끝낼지 묻는다. 끝내면 게임 화면(모니터)에 팀별 라운드 점수를 보여준다 ([05-screens.md](05-screens.md) 4-11).

```
├────────────────────────────────────────────────────────────────┤
│ 맞힌 팀     [ ● 팀A ]  [ ● 팀B ]  [ ● 팀C ]   [ 없음 ]            │
├──────────────────────── (--accent 테두리) ──────────────────────┤
│ 🏁 라운드가 종료되었습니다                                         │
│ ROUND 2 · 🍪 과자 이름 — 5문제를 모두 냈습니다                      │
│ 문제를 더 낼까요, 여기서 종료할까요?                                │
│ [ 한 문제 더 ▶ ]   [ 라운드 종료 ▶ ]                               │
├────────────────────────────────────────────────────────────────┤
│ 진행        [종료]                                                │
```

| 항목 | 규칙 |
| --- | --- |
| 언제 | 득점형, 지금 라운드의 마지막 문제(라운드 목록의 끝 — [한 문제 더 ▶] 로 늘렸으면 늘린 마지막)의 **정답 공개 화면**. 추가 문제(동점)에는 없다 |
| 자리 | 맞힌 팀 구역 바로 아래 카드 (`--accent` 테두리). 창(모달)으로 띄우지 않는다 — 맞힌 팀을 먼저 골라야 하고, 창이 맞힌 팀 버튼을 가리면 안 되므로 |
| 문구 | 제목 "🏁 라운드가 종료되었습니다", "ROUND 2 · 🍪 과자 이름 — n문제를 모두 냈습니다" (n = 이번 라운드에 낸 문제 수), "문제를 더 낼까요, 여기서 종료할까요?". 맞힌 팀을 아직 고르지 않았으면 "↑ 맞힌 팀(또는 [없음])을 먼저 고르세요" (고르지 않아도 버튼은 눌린다) |
| [한 문제 더 ▶] | 같은 카테고리에서 안 낸 문제를 하나 더 (`question.more`, R-43) → 그 문제의 정답을 공개하면 이 안내가 다시 뜬다. 남은 문제가 없으면 버튼 대신 "이 카테고리에 남은 문제가 없습니다" |
| [라운드 종료 ▶] | `question.next` → 게임 화면이 **라운드 종료 화면**으로. 진행 줄의 [다음 문제 ▶] 자리는 비운다 ([종료] 는 그대로) |
| 라운드 종료 화면 — 진행자 화면 | 카드 "ROUND 2 종료 — 게임 화면에 라운드 점수 표시 중" + 표 (팀 · 이번 라운드 · 누적 — 점수를 주는 게임은 "150점 (3개)"). 아래 "계획 3라운드 중 2번째" · "계획한 3라운드를 모두 했습니다" |
| 라운드 종료 화면 — 버튼 | **[다음 라운드 ▶]** (계획한 라운드가 남았을 때 → 룰렛 준비, 남은 문제가 하나도 없으면 룰렛 준비 대신 "더 출제할 문제가 없습니다") / 계획한 라운드가 끝났으면 **[결과 보기 ▶]** + **[한 라운드 더 ▶]** (남은 문제가 있을 때, `round.more` — R-40 의 버튼이 정답 화면에서 여기로 옮겨옴). **[◀ 라운드로 돌아가기]** (`round.back` — 마지막 문제 정답 화면으로: 맞힌 팀 고치기 · 한 문제 더), [종료] (결과). 지난 문제는 머리줄 [📝 정답 기록] 으로 고치면 라운드 점수 · 누적을 다시 계산한다 (R-60) |
| 종합 점수판에 반영 (R-57) | 라운드 종료 카드 아래 카드 "종합 점수판에 반영 — 이번 라운드": 이 게임에 연결된 점수판 행 × 팀 표로 이번 라운드가 더하는 점수("1등 +100" · "3개 +150")와 반영 뒤 종합 합계 · 순위 + **[팀 점수에 반영]** (반영 전에는 이 버튼이 가장 크고, 반영 뒤에는 [다음 라운드 ▶] · [결과 보기 ▶] 가 가장 큼). 반영 뒤 "✔ 반영했습니다", 계산이 달라지면 "점수가 바뀌었습니다" + [다시 반영]. 처음 반영하는 행에 다른 값이 있으면 "이미 입력된 값을 덮어씁니다". 연결된 행이 없으면 안내만 ([13-scoreboard.md](13-scoreboard.md) 10-6) |
| [종료] | 라운드 도중에 누르면 지금처럼 바로 결과 — 라운드 종료 화면을 거치지 않는다 |
| 릴레이 — 언제 (R-62) | "라운드 마지막 문제" 가 아니라 정답 화면에서 **한 팀만 남았을 때**(순위가 정해짐) 또는 **그 카테고리에 낼 문제가 없을 때**. 그 전에는 마지막으로 뽑아 둔 문제여도 안내 없이 [다음 문제 ▶] — 같은 카테고리에서 하나 더 뽑는다 |
| 릴레이 — 문구 | 순위가 정해짐: "🏁 순위가 정해졌습니다" · "ROUND 2 · 🍪 과자 이름 — 🥇1등 팀A · 🥈2등 팀B · 🥉3등 팀C". 문제가 떨어짐: "🏁 이 카테고리에 낼 문제가 없습니다" · 등수 줄(못 끝낸 팀은 "(1/2)") · "대표를 다 내보내지 못한 팀은 맞힌 대표 수로 등수를 정합니다" (인당 문제가 2 이상이면 "(3/4)" · "맞힌 문제 수로", R-64). 맞힌 팀을 아직 안 골랐으면 같은 안내. 버튼은 **[라운드 종료 ▶]** 하나 — [한 문제 더 ▶] 는 없다 |
| 릴레이 — 라운드 종료 화면 | 카드 "ROUND 2 종료 — 게임 화면에 라운드 순위 표시 중" + 표 (팀 · 이번 라운드 "🥇1등" (정답 없으면 "등수 없음") · 맞힌 대표 "2/2" · 게임 점수 "150점"). 반영 카드 · 버튼은 위와 같다 — 반영 미리보기의 등수가 릴레이 등수 |
| 비상용 키 | 게임 화면: 라운드 마지막 정답에서 `Enter` = [라운드 종료 ▶], 라운드 종료 화면에서 `Enter` = [다음 라운드 ▶] · [결과 보기 ▶] (R-85). [한 문제 더 ▶] · [한 라운드 더 ▶] · [팀 점수에 반영] 은 키 없음 (예전 `N` · `Shift+N` · `B` 는 R-85), [◀ 라운드로 돌아가기] 도 키 없음 (R-74) ([06-controls.md](06-controls.md) 3-5) |

### 4-10. 정답 기록 고치기 (R-60)

지난 문제의 맞힌 팀을 고친다. 예전 [↶ 되돌리기] (게임 전체 기록의 마지막 한 건 지우기)를 대신한다.

```
┌ 📝 정답 기록 — 이 게임에서 낸 문제 ─────────────────────── [✕ 닫기] ┐
│ ROUND 1 · 🔍 확대 음식                          팀A 1 · 팀B 1 · 팀C 0 │
│  Q1 샘플 국수     [✔ 팀A] [팀B] [팀C] [없음]                          │
│  Q2 확대 음식 2   [팀A] [✔ 팀B] [팀C] [없음]                          │
│ ROUND 2 · 🍪 과자 이름                                               │
│  Q1 과자 이름 1   진행 중 — 정답 공개 뒤 맞힌 팀 버튼으로                │
└───────────────────────────────────────────────────────────────────┘
```

| 항목 | 규칙 |
| --- | --- |
| 여는 곳 | 머리줄 **[📝 정답 기록]** (득점형 게임 진행 중 어느 화면에서나 — 룰렛 준비 · 라운드 소개 · 문제 · 정답 · 라운드 종료 · 결과 · 추가 문제). 누르면 머리줄 바로 아래 카드가 열리고, 다시 누르거나 [✕ 닫기] 로 닫는다. 그 진행자 화면 창에만 (다른 진행자 화면 · 모니터에는 안 보임) |
| 목록 | 이 게임에서 낸 문제를 라운드 순서로 — 라운드 머리 "ROUND 1 · 🔍 확대 음식" + 그 라운드 팀별 정답 수, 문제마다 "Q1 정답" + 팀 버튼(팀 색, 지금 맞힌 팀은 ✔) · [없음](정답자 없음으로 표시했으면 켜짐). 한 문제 더(R-43) · 후보(R-52)로 낸 문제도 그 라운드에. 추가 문제(동점)는 "추가 문제" 칸 — 그 동점 팀 버튼만 |
| 감추기 | 아직 내지 않은 문제(라운드에 뽑아 둔 남은 문제 포함)는 없다. 정답 공개 전인 지금 문제는 "진행 중 — 정답 공개 뒤 맞힌 팀 버튼으로" (버튼 없음). 정답은 [가리기] 대상 |
| 고치기 | 버튼을 누르면 바로 바뀐다 (`history.credit` — 확인 창 없음). 규칙은 정답 화면의 맞힌 팀 버튼과 같다: 문제당 1팀, 다른 팀이면 교체, 같은 팀 다시 누르면 변화 없음, [없음] 은 맞힌 팀을 지운다. 사진 팀당 대표 방식의 라운드 문제는 팀마다 "팀A [대표1] [대표2]" (R-94 — `history.credit {questionId, team, rep}`), 그 문제 전에 인당 문제를 채운 대표는 거절 "팀A 대표1 — 2문제를 다 맞혀 빠졌습니다" |
| 릴레이 (R-62) | 같은 규칙 — 그 문제 전에 대표를 모두 내보낸 팀은 고를 수 없다 (거절 "그 문제 전에 대표가 모두 맞힌 팀입니다 (릴레이)", 진행자 화면에만). 앞 문제를 고치면 다 내보낸 순서 · 라운드 등수 · 게임 점수를 다시 계산한다 — 다 내보낸 뒤에 남은 기록은 세지 않는다 |
| 게임 화면(모니터) | 화면은 지금 그대로, 토스트 없음. 스코어보드 점수 · 라운드 종료 화면의 라운드 점수만 다시 계산 |
| 결과 화면에서 고치면 | 순위가 바뀔 수 있어 순위 공개를 처음부터 (모니터 시상대가 다시 가려짐) · 점수판 채우기를 다시 묻는다 |
| 라운드 종료 화면에서 고치면 | 반영 카드가 "점수가 바뀌었습니다 — [다시 반영]" (R-57). 종합 점수판에 반영한 지난 라운드를 고쳐도 같다 — 다음 라운드 종료 · 결과에서 다시 반영 |
| 관리 페이지 | 고치지 않는다 — 진행 기록은 게임 화면이 들고 있어, 관리 페이지에서 고치면 진행 중인 게임 화면과 저장이 부딪친다 |
| 비상용 | 없다 — 게임 화면 `Backspace` (마지막 점수 변경 되돌리기)는 R-83, 맞힌 팀 키 `1`~`4` · `0` 은 R-81 에서 없앴다. 점수는 진행자 화면에서만 넣고 고친다. 지난 문제로 돌아가는 키(`←`)는 없다 (R-74) |

## 5. 보안 정책 (R-20)

목표: **참가자가 정답을 미리 보거나 게임을 조작하지 못하게** 하는 간단한 정책. 본격적인 보안 시스템이 아니라 행사 현장에서 실수와 장난을 막는 수준이다.

### 5-1. 정책

| 항목 | 정책 |
| --- | --- |
| 접속 범위 | 노트북 모드: `127.0.0.1` 에만 열림 — **노트북 안에서만 접속** (2-3). 서버 모드: 공개 주소 — 누구나 닿으므로 게임 화면까지 PIN (2-2, 5-4) |
| 입장 PIN | 서버를 켤 때마다 무작위 6자리 PIN 을 새로 만든다 (`crypto.randomInt`). **서버 터미널에만** 표시. 게임 화면 · 관리 페이지 · 파일 · git 어디에도 표시하거나 남기지 않음. **관리 페이지(`/admin`)도 같은 PIN 을 쓴다** — 관리는 쿠키 대신 탭에 둔 PIN 을 요청마다 헤더로 보낸다 (`D-9`, R-31, [04-admin.md](04-admin.md) 2-1) |
| PIN 고정 (선택) | 리허설 등에서 고정하려면 `--pin <6자리>` 로 실행. 저장소 파일에는 적지 않는다. 서버 모드는 항상 고정 PIN (배포 환경의 비밀 값, 5-4) |
| 입장 후 | 서버가 무작위 토큰(32바이트)을 발급해 쿠키로 준다 (`HttpOnly`, `SameSite=Strict`, `Path=/`). 토큰은 서버 메모리에만 있어 **서버를 다시 켜면 모두 무효** → 새 PIN 으로 다시 입장. 쿠키를 쓰는 이유: 실시간 갱신(SSE, `EventSource`)은 요청 헤더를 붙일 수 없다 |
| 조작 요청 | 진행자 화면의 버튼 요청(`POST /api/host/command`)은 **유효한 토큰 + `X-Camp-App` 헤더 + 같은 출처(Origin)** 일 때만 받는다. 정해진 명령 목록(6-2) 밖의 요청은 거부 |
| 실패 제한 | PIN 5회 연속 실패 → 60초 잠금 (진행자 화면 · 관리 화면 실패를 합쳐서 센다). 잠금 중에는 "잠시 후 다시 시도하세요" |
| 데이터 최소화 | 진행자 API 는 **현재 문제 + 이번 라운드 목록 + 이번 라운드 카테고리의 후보**만 준다 (후보 = 그 카테고리에서 아직 안 낸 문제의 정답, R-52. 줄줄이 말해요: 지금 문제의 정답 후보 + 지금 주제의 문제 글자 목록 — 정답 후보는 지금 문제 것만). 결과 화면에서 모두 공개한 뒤 동점이면 추가 문제 후보(이 게임에 포함된 카테고리의 남은 문제)의 정답도 준다 — 게임 진행이 끝난 뒤라서 (R-54). 정답 기록(4-10, R-60)은 이 게임에서 **이미 낸** 문제의 정답만 준다 (안 낸 문제 · 공개 전 지금 문제는 없음). 진행 중에 게임 전체 정답을 한 번에 주는 API 는 없다 — 다른 카테고리 정답은 그 카테고리가 라운드로 뽑혀야 보인다. **예외 — 이모티콘 퀴즈 (R-90)**: 진행자가 문제를 골라 내므로 문제 고르기 · 문제 · 정답 화면에서 이 게임에서 **아직 안 낸 문제 전부**의 이모지 · 정답을 준다 (진행자 화면은 PIN 입장 · 가리기 `B` 대상, 결과 화면에서는 주지 않음) |
| 캐시 · 검색 | 진행자 화면 · API 응답은 `Cache-Control: no-store`, 페이지에 `noindex` |
| 나가기 | 진행자 화면 [나가기] → 토큰 폐기 (다시 PIN 필요) |
| 기록 | 서버 터미널에 입장 성공 · 실패 · 잠금, 조작 명령(시각 · 명령 이름 · 접속 주소)을 출력 (PIN 값은 출력하지 않음) |
| 게임 화면 | 정답 공개 전에는 화면에 정답을 그리지 않는다. 진행자 화면 주소 · PIN 을 게임 화면에 표시하지 않는다 (☰ 메뉴의 "진행자 화면" 은 창만 열고 PIN 은 보여주지 않음) |

### 5-2. 서버 시작 시 터미널 출력 예

```
✔ 캠프 게임 서버 실행 중 (Ctrl+C 로 종료)
  게임 화면    http://127.0.0.1:1029/
  진행자 화면  http://127.0.0.1:1029/host
  PIN          ●●●●●●   (진행자 화면 · 관리 화면 공용 — 실행할 때마다 새 6자리) ← 참가자에게 보이지 않게 주의
```

### 5-3. 범위 밖

- 계정 · 비밀번호 관리 — 하지 않는다. 노트북 모드는 노트북 안에서만, 서버 모드는 공용 PIN + 게임 화면까지 잠금으로 충분하다.
- 노트북 모드의 휴대폰 접속 (예전 스펙의 `--lan` 옵션) — 캠핑장 와이파이 전제가 불확실해 만들지 않는다. 휴대폰은 서버 모드로 (2-2).
- (참고) 관리 페이지(`/admin`)도 같은 PIN 으로 잠근다 (`D-9`, R-31). 관리는 쿠키를 쓰지 않고 그 탭에 둔 PIN 을 요청마다 헤더로 보내므로, 진행자 화면에 로그인해 있어도 관리 페이지는 PIN 을 따로 묻는다 ([04-admin.md](04-admin.md) 2-1).

### 5-4. 서버 모드에서 달라지는 것 (R-36)

공개 주소라 참가자도 닿을 수 있다. 주소를 아는 사람이 정답을 미리 보거나 게임을 조작하지 못하게 5-1 에 더해 아래를 적용한다. 자세한 것은 [08-tech.md](08-tech.md) 11-2.

| 항목 | 서버 모드 |
| --- | --- |
| PIN | 고정 6자리 (비밀 값 `CAMP_PIN`). 서버 로그에 찍지 않는다. 바꾸면 모두 다시 로그인 |
| 게임 화면 | **게임 화면도 PIN 으로 잠근다.** 처음 열면 PIN 입력 → 들어가면 지금처럼 |
| 데이터 · 이미지 · 상태 | 정답이 든 `/data/**`, 이미지 `/assets/**`, 상태 · 실시간 API 는 로그인한 사람에게만 (없으면 401) |
| 쿠키 | `HttpOnly; Secure; SameSite=Strict`, 7일. 서버 저장소의 서명 키 + PIN 으로 서명해 서버가 다시 떠도 유지 — 행사 도중 서버가 재시작돼도 다시 로그인하지 않는다 |
| 실패 제한 | 5회 실패 → 60초 잠금을 **접속한 곳(IP)별로** 센다 — 한 사람이 틀려도 다른 진행자는 막히지 않는다 |
| 나가기 | 게임 화면 · 관리 페이지와 쿠키를 함께 쓰므로 **그 브라우저 전체가 잠긴다**. 그래서 [나가기] 를 누르면 확인 "이 브라우저에서 연 게임 화면 · 관리 페이지도 함께 잠깁니다" 를 먼저 띄운다. 모니터 게임 화면을 띄운 노트북에서는 누르지 않는다. 잠긴 게임 화면은 다음 상태 보고(30초 안)에 PIN 화면으로 바뀌고, 다시 입장하면 이어서 진행 (저장 대기분은 브라우저 사본에 남아 있다가 올라간다) |
| HTTPS | 배포 환경(Vercel)이 HTTPS 를 붙인다 |

## 6. 동작 원리 (실시간 동기화 · 조작 전달)

```
                  상태 (POST /api/live)                       상태 (SSE /api/host/stream)
게임 화면 ───────────────────────────────▶ 로컬 서버 ───────────────────────────────▶ 진행자 화면
          ◀───────────────────────────────           ◀───────────────────────────────
                  명령 (SSE /api/live/commands)              버튼 (POST /api/host/command)
```

### 6-1. 상태 (게임 화면 → 진행자 화면)

| 단계 | 내용 |
| --- | --- |
| 1. 게임 화면 → 서버 | 화면 · 문제 · 연출 단계 · 정답 공개 · 맞힌 팀 · 정답 영상 재생 상태(R-61)가 바뀔 때마다 현재 상태를 보낸다 (100ms 묶음). 보내는 것은 **id 와 상태값뿐** — 정답 텍스트는 보내지 않는다 (정답 영상 구간은 서버가 데이터에서 붙인다). 30초마다 같은 상태를 다시 보낸다 (서버 재시작 대비). 정답 영상 재생 상태는 상태 번호(`basedOn` 비교, 6-2)를 올리지 않는다 — 영상이 끝나는 순간 누른 맞힌 팀 버튼이 "화면이 바뀌어" 로 거절되지 않게 |
| 2. 서버 | 받은 상태를 메모리에 1개만 보관 (파일 저장 안 함). 데이터 파일에서 문제 id 로 정답 · 메모 · 힌트를 찾아 붙여 진행자용 상태를 만든다 |
| 3. 서버 → 진행자 화면 | Server-Sent Events 로 변경 즉시 전송. 15초마다 연결 확인 신호 |
| 4. 진행자 화면 | 처음 열 때 `GET /api/host/state` 로 현재 상태를 받고 이후 SSE 로 갱신. 연결이 끊기면 자동 재연결 (1 · 2 · 5초 간격). 서버가 실행 시간 상한 전에 먼저 끊은 것(`bye` — Vercel, [08-tech.md](08-tech.md) 11-4)이면 ○ 재연결 중 없이 바로 다시 붙는다. ○ 재연결 중 이 뜨는 순간 그때 응답 시간을 재어 서버 로그에 비콘 한 줄 (R-66 — 08-tech 11-4) |

### 6-2. 명령 (진행자 화면 버튼 → 게임 화면)

| 단계 | 내용 |
| --- | --- |
| 1. 진행자 화면 → 서버 | 버튼을 누르면 `POST /api/host/command` `{ id, cmd, args, basedOn }` — `basedOn` 은 진행자 화면이 보고 있던 상태 번호 |
| 2. 서버 | 토큰 · 명령 이름 검사 후 게임 화면 명령 채널(SSE `/api/live/commands` — 노트북 모드는 노트북 안에서만, 서버 모드는 로그인한 게임 화면만)로 전달. 게임 화면이 연결돼 있지 않으면 409 "게임 화면과 연결되지 않았습니다". 게임 화면이 잠깐 끊긴 사이의 명령은 다시 붙을 때 전달한다 (15초 안 — [08-tech.md](08-tech.md) 11-4) |

### 6-3. 게임 화면은 하나만 (R-46)

게임 화면이 2개 이상 열려 있으면, 제목 화면에 머문 다른 창(휴대폰 · 다른 탭 · 예전 창)의 상태 보고가 진행 중인 창을 덮어써 진행자 화면이 "진행 중인 문제가 없습니다" 로 끊기고 진행자 명령도 그 창으로 갔다. 그래서 게임 화면을 열 때 하나만 남긴다.

| 단계 | 동작 |
| --- | --- |
| 1. 확인 | 게임 화면은 입장(서버 모드 PIN) 직후, 데이터를 읽기 전에 `GET /api/live/peers?clientId=` 로 다른 게임 화면이 연결돼 있는지 · 다른 창 열기가 막혀 있는지 묻는다. 확인할 수 없으면(비상용 python 서버 등) 그냥 연다 |
| 2. 없음 | 바로 연다 |
| 3. 있음 · 막기 꺼짐 | 가운데 창 "다른 게임 화면이 열려 있습니다 — 게임 화면은 하나만 써야 진행자 화면이 끊기지 않습니다" + **[이전 창 닫고 여기서 진행]** · **[이 창 쓰지 않기]**. 묻는 동안 2초마다 다시 확인해 이전 창이 사라지면(새로고침 · 닫기) 묻지 않고 연다 |
| 3-1. 이전 창 닫기 | `POST /api/live/takeover` → 서버가 다른 게임 화면에 `event: kick` 을 보내고 연결을 끊는다. 이전 창은 진행을 멈추고(상태 보고 · 명령 · 키 입력 모두) **PIN 입력 화면** "다른 창에서 게임 화면을 열어 이 창은 멈췄습니다". 거기서 PIN 을 넣으면 새로고침 — 다시 1 부터 (이번엔 그 창이 "다른 창" 을 닫을지 묻는다). 진행 기록은 서버에 있으므로 새 창에서 [이어하기] 로 그대로 이어진다 |
| 3-2. 이 창 쓰지 않기 | "이 창은 사용하지 않습니다 — 탭을 닫아 주세요" + [다시 확인]. 상태를 보내지도 명령을 받지도 않는다 |
| 4. 있음 · 막기 켜짐 | 묻지 않고 **진입이 안 되는 화면** "🔒 다른 게임 화면에서 진행 중이라 열 수 없습니다 — 진행 중인 창의 ☰ 메뉴에서 [다른 창 열기 허용] 을 누르거나 그 창을 닫으세요". PIN 입력 없음. 3초마다 다시 확인해 열 수 있게 되면 연다 |

- **다른 창 열기 막기**: 게임 화면 ☰ 메뉴 [🔒 다른 창 열기 막기] ↔ [🔓 다른 창 열기 허용] (`POST /api/live/lock` `{ on }`). 서버가 모든 게임 화면에 `event: lock` `{ on }` 으로 알린다. 막기는 **다른 게임 화면이 연결돼 있을 때만** 효과가 있다 — 막아 둔 창이 닫히거나 새로고침되면(연결이 끊기면) 새 창은 바로 열린다. 서버 메모리에만 두며 서버를 다시 켜면 꺼진다.
- 막기가 켜져 있는데 다른 게임 화면이 명령 채널에 붙으려 하면 서버는 `event: blocked` 를 보내고 끊는다 — 그 창은 4 의 화면을 보인다. 이전 창 닫기(`takeover`)도 거절(423)한다.
- 서버는 명령 채널에 연결된 게임 화면이 아닌 곳의 `POST /api/live` 는 받지 않는다 (204, 반영 안 함) — 닫힌 창 · 막힌 창이 덮어쓰지 못하게. 연결된 게임 화면이 하나도 없을 때(명령 채널이 붙기 전, 비상용 서버)는 받는다.
- 진행자 화면은 이전 창이 닫히면 새 창이 상태를 보낼 때까지 "진행 중인 문제가 없습니다".

## 7. 범위 밖

- 진행자 화면에서 게임 고르기 · 게임 시작 · 팀 설정 — 게임 창(☰ 메뉴)에서 한다. 문제 수정 · 점수 입력 · 상태 초기화는 관리 페이지(`/admin`)에서 한다.
- 진행자 화면 여러 대 동시 접속은 허용 (모두 같은 내용, 누구나 조작 가능 — 먼저 도착한 명령이 적용되고 나머지는 6-2 의 `basedOn` 검사로 무시).
