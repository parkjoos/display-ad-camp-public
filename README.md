# display-ad-camp-game

**2026 디광 캠핑** (2026-10-29) 진행용 로컬 게임 앱 — 줄줄이 말해요 · 이모티콘 퀴즈 · 사진 보고 맞추기.

서버(Vercel — 옮기는 중, R-51)에 올려 두고 노트북으로 모니터에 게임 화면을, 진행자들은 휴대폰(LTE · 5G)으로 진행자 화면을 연다 (PIN). 문제 · 현장 상태의 원본은 서버 저장소(Redis)다 (4장). 서버를 쓸 수 없을 때는 노트북 하나로 도는 노트북 모드(1장)로 진행한다.

> **진행자라면 → [진행자 설명서](docs/manual.md)** — 접속 · 진행자 화면 사용법 · 당일 순서 · 문제가 생기면

- 스펙 문서 목차: [docs/README.md](docs/README.md) · 작업 목록: [docs/14-tasks.md](docs/14-tasks.md) · 결정 사항: [docs/09-decisions.md](docs/09-decisions.md)

## 1. 실행

필요한 것: macOS, **Node.js 22 이상** (`node -v` 로 확인, 없으면 https://nodejs.org). `npm install` 은 필요 없다.

1. Finder 에서 **`start.command` 더블클릭** — 처음 한 번 "확인되지 않은 개발자" 경고가 뜨면 우클릭 → 열기.
2. 터미널이 열리고 서버가 켜지면 브라우저가 게임 화면을 연다. 터미널에 주소와 **PIN** 이 나온다.

```
✔ 캠프 게임 서버 실행 중 (Ctrl+C 로 종료)
  게임 화면    http://127.0.0.1:1029/
  진행자 화면  http://127.0.0.1:1029/host
  관리 페이지  http://127.0.0.1:1029/admin
  PIN          ******   (진행자 화면 · 관리 페이지 공용) ← 참가자에게 보이지 않게 주의
```

- 터미널에서 직접: `npm start` 또는 `node server.mjs` (옵션 `--pin 123456` 으로 PIN 고정, `--open` 으로 브라우저 열기).
- 끄기: 터미널에서 `Ctrl+C`. **게임 진행 중에는 터미널 창을 닫지 않는다.**
- 이미 켜져 있을 때 `start.command` 를 다시 누르면 브라우저만 연다.
- PIN 은 서버를 켤 때마다 새로 정해지고 터미널에만 나온다. 저장소 파일에는 적지 않는다.

### 서버에 올려 쓸 때 — 서버 모드

진행자 여러 명이 휴대폰(LTE · 5G)으로 진행자 화면을 열 때는 서버에 올린 앱을 쓴다 — Vercel + 외부 Redis(Upstash)로 옮기는 중이다 (R-51). 주소는 운영자가 알려 주고, PIN 은 운영자가 정해 둔 고정 값이며 공개 주소라 **게임 화면도 PIN 으로 연다**. 노트북 모드(위)는 서버를 못 쓸 때의 비상용으로 그대로 남는다.

- 진행자 사용법: [docs/manual.md](docs/manual.md)

- 동작 · 잠금 규칙: [docs/08-tech.md](docs/08-tech.md) 11장
- 처음 준비 · 배포 · 업데이트 · 백업: [docs/16-deploy.md](docs/16-deploy.md)
- 저장은 **Redis** — 서버가 여러 개여도 같이 본다 (R-50). 키는 모두 `camp-game:` 로 시작. [docs/08-tech.md](docs/08-tech.md) 11-6

## 2. 화면 세 개

| 화면 | 주소 | 쓰는 곳 | 내용 |
| --- | --- | --- | --- |
| 게임 화면 | `/` | 외부 모니터 (`F` 전체화면) | 제목 · 룰렛 · 문제 · 정답 · 결과 · 종합 점수판 |
| 진행자 화면 | `/host` (PIN) | 노트북 화면 | 지금 문제의 정답 · 메모 · 힌트, 진행 버튼 (룰렛 · 정답 공개 · 맞힌 팀 · 다음 · 종료 · 점수판 채우기) |
| 관리 페이지 | `/admin` (PIN) | 노트북 | 문제 · 카테고리 추가, 점수 입력, 백업 내려받기 · 올리기 · 복원, 상태 초기화 |

- 게임 화면은 좌상단 ☰ 메뉴(도움말도 메뉴에서), `F` 전체화면. 진행자 화면 · 관리 페이지도 메뉴(☰)에서 새 창으로 연다.
- 진행자 요약 설명서: 진행자 화면 맨 위 [❓ 설명서], 관리 페이지 맨 위 [📖 설명서] (긴 설명서는 [docs/manual.md](docs/manual.md)).
- 키 전체: [docs/06-controls.md](docs/06-controls.md), 진행자 화면: [docs/12-host-view.md](docs/12-host-view.md).

## 3. 문제 넣기 — 관리 페이지

서버 주소 + `/admin` (노트북 모드는 ☰ → 관리 또는 `http://127.0.0.1:1029/admin`) → PIN 입력 (서버 모드는 운영자가 정한 PIN, 노트북 모드는 터미널의 PIN). PIN 은 그 탭에만 기억하고, [잠그기] 를 누르거나 탭을 닫으면 다시 묻는다.

| 하려는 것 | 방법 |
| --- | --- |
| 사진 문제 1개 | 게임 → 카테고리 [문제 관리] → [+ 문제 추가] → 이미지 끌어다 놓기 또는 `⌘V` 붙여넣기 (화면 캡처 · "이미지 복사") → 정답 → 연출 → 저장 |
| 확대 문제 | 연출 "확대" → 이미지에서 **확대할 곳 클릭** → 배율 · 단계 (점선 = 처음 보이는 범위) |
| 가림 문제 (제목 · 로고 가리기) | 연출 "가림" → 이미지 위를 **드래그해 상자 그리기** (번호 순서대로 진행자 [힌트 단계 ▶] 로 벗겨짐) |
| 정답 영상 (뮤직비디오 · 명대사) | 사진 문제 편집 → "🎬 정답 영상 — 유튜브" → 영상 주소 + 시작 · 끝 시간 (`83` · `1:23` — 유튜브 [공유] → 시작 시간 체크로 복사하면 시작이 채워짐) → [▶ 구간 미리보기] 로 재생되는지 확인. 정답 공개 때 모니터에서 자동 재생, 끝나면 정답 글자 |
| 사진 여러 장 | [여러 장 한 번에 추가] → 정답(파일 이름에서 자동) · 연출 → [모두 저장]. 확대 · 가림은 각 문제에서 지정할 때까지 숨김 ("⚠ 설정 필요") |
| 이모티콘 문제 (담당자 시트) | 이모티콘 퀴즈 → [표 붙여넣기] → 구글 시트에서 복사한 표 붙여넣기 → 미리보기 확인 → [n개 등록]. 템플릿: [docs/templates/emoji-quiz-template.tsv](docs/templates/emoji-quiz-template.tsv) 또는 [템플릿 복사] |
| 이모티콘 문제 정답 이미지 (포스터 · 앨범 표지) | 이모티콘 문제 편집 → "정답 이미지 (선택)" → 파일 선택 · 끌어다 놓기 · 그 칸을 누른 뒤 `⌘V`. 정답 공개 때 이모지 대신 보인다 (표 붙여넣기로는 못 넣음 — 등록 뒤 문제 편집에서) |
| 줄줄이 말해요 주제 | 줄줄이 말해요 → [+ 카테고리 추가] 또는 [표 붙여넣기] |
| 줄줄이 말해요 문제 ("코스○○" + 정답 후보) | 줄줄이 말해요 → 주제 [문제 관리] → [+ 문제 추가] → 문제 글자(`○` 는 [○ 넣기]) · 정답 후보(Enter, 또는 쉼표 · 줄바꿈으로 여러 개 붙여넣기) → 저장. 모니터엔 문제, 진행자 화면엔 정답 후보 |
| 카테고리 추가 · 숨기기 | 게임 화면 → 카테고리 표의 버튼 (숨기면 게임 홈 · 룰렛에 안 나옴) |
| 잘못 저장했을 때 | [백업 목록] → 그 시점으로 복원 (게임별 최근 20개) |
| 이미지 · 데이터 점검 | [전체 검증] — 없는 이미지 · 안 쓰는 이미지 · 데이터 경고 |

- 아이폰 사진(HEIC)은 안 된다 → Mac 미리보기 → 내보내기 → JPEG.
- 큰 사진은 브라우저가 긴 변 2400px JPEG 로 줄여서 저장한다.
- 저장하면 열려 있는 게임 화면에 바로 반영된다 (새로고침 필요 없음). 서버에 저장되므로 커밋 · 푸시는 필요 없다 (4장).

## 4. 데이터 원본 · 백업

운영에서 문제 · 이미지 · 현장 상태(팀 설정 · 진행 기록 · 종합 점수판)의 **원본은 서버 저장소**(Redis)다 (R-37 · R-50). 잘못 저장 · 초기화에 대비해 아래 때마다 백업을 받아 둔다. 서버 주소의 관리 페이지에서 저장하면 바로 모두에게 보인다 — **커밋 · 푸시가 필요 없다**.

| 어디에 | 무엇 |
| --- | --- |
| 서버 저장소 (Redis — R-50) | 원본 — `data/` · `assets/` · `state/` |
| 백업 파일 (`camp-game-<시각>.tar`) | 관리 페이지 [⬇ 백업 내려받기] 로 받은 그 시점 전체. 팀 드라이브 등에 보관 |
| git 저장소 | 코드 · 문서 · 초기 데이터(`data/` · `assets/` — 서버 첫 시작 · 노트북 모드 시작 값). `state/` 는 올리지 않는다 |

| 때 | 할 일 |
| --- | --- |
| 리허설 뒤 (10/27) | 서버 관리 페이지 [백업 내려받기] → [상태 초기화] → [리허설 기록 지우기] |
| 행사 전날 (10/28) | [백업 내려받기] — 서버를 못 쓰게 되면 노트북 모드에서 [⬆ 백업 올리기] 로 이어서 진행 |
| 행사가 끝나면 (10/29) | [백업 내려받기] — 최종 점수판 · 진행 기록 보관 |
| 노트북에서 넣은 문제를 서버로 | 노트북 관리 페이지 [백업 내려받기] → 서버 관리 페이지 [백업 올리기] (현장 상태는 끄고) |

- 받은 `.tar` 는 Mac 에서 더블클릭하면 `data` · `assets` · `state` 폴더로 풀린다.
- 초기 데이터(git)까지 맞추고 싶으면 백업을 풀어 `data/` · `assets/` 만 커밋한다 (선택 — [docs/08-tech.md](docs/08-tech.md) 5-4).
- 자세히: [docs/08-tech.md](docs/08-tech.md) 5장, [docs/04-admin.md](docs/04-admin.md) 3-11.

## 5. 문제가 생기면

| 증상 | 대응 |
| --- | --- |
| "Node.js 22 이상이 필요합니다" | https://nodejs.org 에서 설치 후 다시 실행 |
| 1029 포트를 다른 프로그램이 쓴다 | 그 프로그램을 끄고 다시 실행 |
| 게임 도중 서버가 꺼졌다 | 게임 화면은 계속 진행된다. `start.command` 로 다시 켜면 그동안의 기록을 파일로 올린다 |
| PIN 을 잊었다 · 서버를 다시 켰다 | 터미널의 새 PIN 으로 진행자 화면 · 관리 페이지에 다시 들어간다 |
| PIN 을 5번 틀렸다 | 60초 뒤 다시 |
| 화면이 이상하다 | 브라우저 새로고침 (`Cmd+R`) — 진행 기록은 파일에 있어 그대로 이어진다 |

## 6. 개발

- 구조: `server.mjs` · `server/` (Node 내장 모듈만), `index.html` · `host.html` · `admin.html` + `app/` (빌드 없는 ES 모듈). 파일 구조: [docs/08-tech.md](docs/08-tech.md) 3장.
- 테스트: `npm test` (`node --test` — 공용 모듈 · 서버 API · 서버 모드 · 붙여넣기 해석 · Redis 저장소와 서버 두 개 — `redis-server` 가 있을 때만, 없으면 건너뜀 · Vercel 함수 진입점 · 실시간 연결 다시 붙기 · 백업 나눠 올리기 · 알림 구독 — `redis-cli` 도 있을 때).
- 배포: Vercel + 외부 Redis — 함수 진입점 `api/index.js`, 설정 `vercel.json` ([docs/16-deploy.md](docs/16-deploy.md), 작성 중 — R-51).
